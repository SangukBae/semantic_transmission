# LGVSC 할루시네이션 검출·완화 실험안

설계일: 2026-09-21. **제안 상태이며 구현·실행·효과 입증 완료 기록이 아니다.**

상위 기준: [ETRI 후속 프로토콜](../../../ETRI_FOLLOWUP_PROTOCOL.md). 선행 근거와 적용 한계: [심층 조사](ETRI_HALLUCINATION_LITERATURE_REVIEW_2026-09-21.md). 기존 결과·설정은 보존하고 새 실험 ID·평가기 버전을 부여한다.

## 1. 실험의 중심 가설

**희소한 의미 패킷의 유효기간과 갱신을 관리하고, 생성기가 최신 수신 근거를 따르도록 제한하면 장시간 복원의 잘못된 상태 지속을 줄일 수 있다.** 추가 전송량·계산량·정상 동작 손실까지 함께 평가한다.

원인과 대응을 다음처럼 분리한다.

| 원인 가설 | 확인 방법 | 대응 실험 |
|---|---|---|
| 송신단에서 사건을 놓침 | 송신 원본의 사건과 추출·전송 이벤트 대조 | 시간별 caption·동작·방향·등장/퇴장 보강 |
| 오래된 조건이 남음 | 경계·packet 생성/수신/적용·참조 초기화 로그 대조 | scene ID, TTL, 갱신 상한, 장면 경계 초기화 |
| 조건은 맞지만 생성기가 무시함 | 원본·TX·RX에서 확인한 사건과 복원 대조 | 수신 anchor 제약, 조건 강도 조절, 제한적 재생성 |
| NTSCC 또는 VAE가 anchor를 이미 왜곡함 | 원본 키프레임→수신 키프레임→VAE 왕복→생성 분리 | 수신 anchor의 불확실성을 고려; 원본 키프레임 조건은 oracle 진단 |
| 평가기의 관측 실패 | 독립 정답과 자동 추출 상태 대조 | UNKNOWN/가려짐/퇴장 구분, 추출기 교정 |

## 2. 공통 실험 계약

### 2.1 데이터·길이·분할

다음은 **메일에서 지정한 표본 수가 아니라 시작 규모 제안**이다.

- 개발·실행 가능성 확인: 독립 원본 3편, 낮음/일반/높음 장면전환 각 1편, 실제 연속 60–90초.
- 별도 교정: 독립 원본 6편, 각 유형 2편. 문턱·키프레임 간격·조건 강도 선택에만 사용.
- 최초 미사용 평가: 독립 원본 12편, 각 유형 4편. 이는 예비 평가이며 충분한 일반화·검정력을 보장하지 않는다. 본 평가 규모는 예비 분산·오류 빈도·계산 비용으로 결정한다.
- 같은 원본의 인접 구간을 서로 다른 분할에 넣지 않는다. 기존 ETRI/WebVid 중 결과를 이미 본 원본은 개발 자료다.
- 유형은 결과를 보기 전에 경계 수/분, hard cut/dissolve, 객체 출현·퇴장, 배경 변화 근거로 고정한다. 빈도 기준은 확보 원본의 분포를 보고 교정 단계 전에 등록한다.
- 반복·감속·프레임 복제·무관한 클립 이어붙이기로 길이를 늘리지 않는다. 원본 시각과 처리 FPS 대응표를 보관한다.

처리 해상도는 우선 기존 576×320, 24 FPS를 유지한다. 60초는 1,440장의 시간축이다. 기존 `max_frames=384` 제한을 제거하는 것만으로 지원 완료로 판정하지 않고, 출력 길이·시간 대응·중간 상태·메모리를 직접 검사한다.

### 2.2 채널·난수·전송 비용

- 1차는 AWGN **10 dB**. 효과가 확인된 소수 arm만 **5/15 dB**에 추가 평가한다. 세 값은 이번 제안이며 ETRI 지정값이 아니다.
- 예비 대응 난수 목록: `(channel_seed, generation_seed) = (1024,42), (2048,43), (4096,44)`. 서로 다른 변동 요인을 분해할 때에는 작은 표본에서 3×3 교차 실험을 추가한다.
- 수신단만 바꾸는 arm은 **같은 수신 파일 바이트**를 재사용한다. 시드가 같다는 사실만으로 같다고 간주하지 않는다.
- 키프레임·패킷을 추가하는 arm은 공통 심벌의 잡음을 안정된 `(video, frame, packet, symbol)` ID로 대응시킨다. 단순 순차 RNG는 패킷 추가 후 잡음 대응이 깨질 수 있다. 추가 심벌은 별도 고정 규칙으로 생성한다.
- 비용은 시각 심벌, 의미 패킷, 구간/scene 정보, 부호화·패딩, 사용한 재전송·피드백까지 합산한다. 심벌 수와 파일 저장 바이트는 다른 단위로 보고한다.
- 동일 예산 비교는 총 채널 사용량을 맞추거나, 일치하지 않으면 비용–오류 곡선으로 보고한다. 패킷을 늘린 arm의 개선을 수신단 알고리즘만의 효과로 주장하지 않는다.

### 2.3 기준선과 입력 누출 방지

| ID | 조건 | 해석 |
|---|---|---|
| B0 | 현재 `etri_official.json` 경로 | 공개 코드의 로컬 이식 기준선. 원 논문 완전 재현으로 표시하지 않음 |
| B1 | B0 + 고정한 endpoint-exact 정렬 정책 | 프레임 연결/conditioning 변경 효과. 후속 완화는 B1과 대응 비교 |
| B2 | B1 + 고정 간격 키프레임 | 단순 정보 추가 기준선. 적응형 정책과 동일 비용 또는 곡선 비교 |
| O1 | 원본 키프레임 또는 정답 사건 정보를 수신단에 직접 제공 | 원인 분리용 oracle. 실용 통신 성능 표에서 분리 |
| O2 | 원본 전체 LR 영상을 VSR 모델에 직접 제공 | 추가 전송을 모델링하지 않으면 외부 정보 상한 실험 |

B1의 두 정책(출력 연결과 생성 conditioning)을 각각 명시한다. `clean_keys`, 원본 caption, 원본 광류를 수신단에서 읽는 경로는 O1로 분류한다. 평가기는 원본을 사용할 수 있지만 **완화 의사결정은 실제 RX와 사전 설치 모델만** 이용한다.

## 3. E0 — 장시간 실행·오류 원인 지도

**목적:** 60초 지원과 baseline의 실제 실패가 어디서 발생하는지 확인한다.

1. 기존 짧은 점검 구간→20초→60초로 단계 확장한다. 60초 입력을 받았지만 16초만 처리한 경우를 실패로 검출한다.
2. 낮은/일반/높은 장면전환 각 1편에서 B0·B1을 우선 1개 난수 쌍으로 실행한다. 이전 짧은 검증과 중복되는 정렬 확인은 재사용한다.
3. 원본·송신 선택·수신 키프레임·VAE 왕복·최종 복원을 같은 시간축으로 대조한다.
4. chunk를 써도 연속 시간축과 이전 구간 참조를 유지한다. 정상 구간에서 무조건 초기화한 결과는 별도 arm이다. 경계 중복·누락을 로그로 남긴다.
5. 장면·객체 오류를 주석하고 원인 단계를 `TX_OMISSION / RX_CORRUPTION / STALE_CONDITION / DECODER_VIOLATION / UNRESOLVED`로 기록한다. 원인 불명은 강제로 분류하지 않는다.

**산출물:** 실제 입력/출력 길이·FPS·프레임 수·PTS 대응, 총 실행 시간·최대 GPU/호스트 메모리·실패/재개 위치, 오류 사례 지도. 60초 미달이면 최대 검증 길이와 병목을 보고하고 길이 미충족으로 남긴다.

## 4. E1 — 검출기 비교와 보류 교정

**근거:** HalluGen의 full-reference 평가와 measurement–prediction 검출기를 분리하는 설계, sFRC의 국소 오류 평가, VidHalLoc의 판정기 검증 필요성. [HalluGen](https://arxiv.org/html/2512.03345v1) · [sFRC](https://arxiv.org/html/2603.04673v2) · [VidHalLoc](https://arxiv.org/html/2609.09895v1)

| 평가군 | 후보 | 사용할 수 있는 입력 |
|---|---|---|
| 외부 원본 참조 평가 | PSNR/SSIM/LPIPS/DISTS, SHAFE의 RGB 전이판, sFRC 전이판 | 원본·복원 |
| 기존 의미 진단 | 선택한 FSO 성분·UEP·EOI | 각 지표의 명시된 입력; 유효성 확정 전 보조 결과 |
| 수신단 위험 판정 | keyframe anchor 불일치, packet 만료·scene 불일치, 사건 조건 모순, 여러 생성 후보의 불일치 | 복원·실제 RX·모델, 원본 없음 |
| 간단한 비교군 | 경과 시간만 사용, anchor 차이만 사용, 단순 주기 경고 | 같은 RX 입력 |

SHAFE는 현재 1채널 입력 처리와 low-pass cutoff를 바꿔야 한다. 원본판과 수정판 이름·특징 추출기·해상도·문턱을 명시한다. 원본 참조 평가 점수와 RX 전용 위험 점수를 한 ROC 순위표에 섞어 같은 정보 조건이라고 주장하지 않는다.

개발 자료에는 Added/Missing/Distorted 통제 편집 외에도 정상 가려짐, 화면 밖 퇴장, 조명 변화, 카메라 이동, 정상 씬 체인지, 압축/잡음, 속도 변화, 일부 packet 미관측을 포함한다. **통제 편집 검출 성공과 실제 생성 오류 검출 성공을 별도로 보고**한다.

수신단 상태는 `SUPPORTED / CONTRADICTED / UNKNOWN`으로 둔다. 낮은 detector confidence와 정상 가려짐을 `Missing`으로 자동 변경하지 않는다. 다중 생성 일치도도 모두 같은 환각을 만들면 낮은 위험을 보이므로 확정 정답으로 쓰지 않는다.

**평가:** 유형별 PR-AUC, event recall과 false alarms/min, 시간 구간 IoU, 검출 지연, 가능한 영역의 IoU/PR, UNKNOWN 비율 및 risk–coverage. 위치 정답이 없는 사례는 위치 성능의 분모에서 구분하되 전체 사례 수·제외 사유를 공개한다. threshold는 교정 세트에서 고정하고 평가 세트에서 재조정하지 않는다.

## 5. E2 — 씬 체인지·조건 유효기간·누락 대안

**우선 실행할 완화 실험.** SKEM의 의미 기반 keyframe 선택과 전용 shot detector를 구별한다. 비교 가능한 공개 기준선으로 [TransNet V2](https://github.com/soCzech/TransNetV2)를 사용하되 최신 복원 논문으로 분류하지 않는다. 경계 정답은 독립 원본 판독 또는 검증된 주석에서 얻는다.

첫 비교는 2×2로 구성한다.

| arm | 경계에서 packet/참조 초기화 | 최대 키프레임 간격·주기적 의미 갱신 |
|---|---|---|
| C00 | 없음 | 없음 |
| C10 | 있음 | 없음 |
| C01 | 없음 | 있음 |
| C11 | 있음 | 있음 |

- TX packet에 `scene_id`, `segment_id`, `valid_from`, `valid_until`, `event_time`, `update_reason`, 버전을 부여한다. 실제 수신·적용 시각도 별도 기록한다.
- shot 경계에서는 이전 장면의 caption·동작·참조 상태를 만료시킨다. 의미 packet만 바꾸고 이전 생성 참조가 남는 경우와 둘 다 초기화하는 경우를 추가 비교한다.
- 최대 키프레임 간격 후보는 **1/2/4초**. 기존 1초 개선 실험을 포함하는 교정 후보이며 최종 수치는 데이터·전송 예산으로 고정한다. 임의로 최선의 test 결과를 선택하지 않는다.
- 자연 발생한 miss/false alarm/지연을 먼저 기록한다. 별도 통제 시험에서는 장면 경계 신호를 0/10/30% 누락시키고 0/0.5/1초 지연시킨다. 통제 누락과 원래 검출기의 성능을 섞지 않는다.
- 미래 키프레임을 기다려 양방향 조건으로 생성하면 lookahead 지연을 기록한다. offline 결과를 인과적 실시간 복원으로 표시하지 않는다.
- 수신단이 추가 송신을 요청하는 정책은 기본 실험에 숨겨 넣지 않는다. 사용할 경우 feedback·재전송 비용과 왕복 지연을 가진 별도 arm으로 정의한다.

**주 결과:** 경계 이후 이전 객체·배경·caption의 잔존 시간, 경계 검출 precision/recall 및 적용 지연, 오류 초/분, 정상 연속 구간의 깜빡임, packet·keyframe 비용. 주기 갱신은 검출 실패의 영향을 제한할 수 있지만 정상 사건 누락까지 해결한다고 가정하지 않는다.

## 6. E3 — 동적 의미 패킷과 decoder 반영의 2×2 비교

**목적:** 정보가 없어서 틀리는지, 정보를 보내도 생성기가 따르지 않는지 분리한다.

현재 PLLaVA 4프레임 구간 caption+flow 스칼라를 기준으로, 송신 원본에서 `entity_id / action / start / end / direction / relative_speed / confidence`를 추출한다. 속도는 처음에는 화면 좌표에서 프레임 크기로 정규화한 상대 속도이며, 카메라 보정 없이 세계 좌표 속도나 m/s로 해석하지 않는다. 불확실한 이벤트는 확정 사실로 packet에 넣지 않는다.

| arm | 패킷 | decoder 조건 반영 |
|---|---|---|
| D00 | 현재 caption+flow | 현재 경로 |
| D10 | 시간표시 동적 이벤트 추가 | 기존 방식의 구간 텍스트 |
| D01 | 현재 packet | 시간 범위에 맞춘 조건 분할·만료 |
| D11 | 시간표시 동적 이벤트 추가 | 사건 경계에 맞춘 조건 적용·만료 |

D01은 없는 사건을 만들어 넣지 않는다. 현재 packet이 가진 구간 유효범위만 사용한다. 초기에는 학습 없이 사건 경계별 prompt/조건 관리로 시작하고, 객체별 공간 조건 주입은 별도 후속 변경으로 둔다.

**비용 대조:** 이벤트 텍스트를 늘리는 조건과 그 비용에 상응하는 키프레임·구간 caption 추가 조건을 비교한다. 단어 수가 아니라 UTF-8·packet 직렬화·부호화 후 실제 채널 사용량을 기록한다.

**주 결과:** 걷기/달리기/정지 전환, 등장/퇴장 시점, 방향 변화, 사건 순서의 누락·지연·잘못된 지속. 중간 caption을 더 많이 보내도 시점이 틀리는 실패와 잘못 추출한 이벤트가 영상으로 전파되는 새 오류를 포함한다.

## 7. E4 — 수신 anchor·신뢰도에 따른 제한적 제어

**근거의 차용 범위:** DynamicDPS는 관측 제약, SparkVSR는 참조 강도 조절, RAR는 평가 후 정지 구조를 제공한다. 세 방법을 그대로 결합한 재현으로 부르지 않는다. [DynamicDPS](https://arxiv.org/html/2503.01075v2) · [SparkVSR](https://arxiv.org/html/2603.16864v1) · [RAR](https://arxiv.org/html/2603.26385v1)

1. **anchor 일치 기준선:** 같은 수신 키프레임과 생성된 해당 시점의 복원 사이 특징/저주파 차이를 측정한다. 강제로 모든 중간 프레임을 anchor에 붙이지 않는다.
2. **일괄 CFG 비교:** 현행 text CFG 7과 낮춘 후보 1/3을 같은 RX·잡음으로 교정 비교한다. 이는 SparkVSR RFG와 다른 제어다. 텍스트 조건 약화로 필수 사건이 사라질 수 있다.
3. **조건부 제어:** E1에서 고정한 위험 판정이 발동한 구간만 한 번 보수적 조건으로 재생성한다. 정상 구간까지 같은 처리를 하는 arm과 비교해 gate의 가치를 분리한다.
4. **보류/대체 출력:** packet 만료 또는 근거 부족이면 기존 출력 유지, 마지막 수신 프레임 유지, 신뢰 상태 표시 중 하나의 정책을 사전 고정한다. 프레임 유지의 움직임 손실·staleness·화면 정지는 별도 오류다.

원본 참조 점수로 후보를 고르는 arm은 oracle이다. RX 점수로 선택한 후보는 다른 평가기와 독립 주석으로 검증한다. 재생성 최대 횟수 1, 총 소요 시간, 거절된 후보를 포함한 실패 수를 기록한다. 여러 후보 중 가장 좋은 예시만 골라 제출하지 않는다.

**후속 연구용 관측 모델:** 시각 수신 심벌을 $y_v=E_r(x_K)+n$으로 볼 수 있다면, 고정된 rate·power·side information 아래 $E_r(\hat{x}_K)$와 $y_v$의 차이를 제약 후보로 쓸 수 있다. 이는 실제 NTSCC 연산·잡음 정규화·미분 가능성 확인이 필요한 설계다. 수신 RGB keyframe의 픽셀 잔차는 이 심벌 likelihood와 같지 않다. 중간 사건은 키프레임 심벌 일치만으로 보장할 수 없다.

## 8. E5 — 대체 복원 모델과 영상 미세조정의 진행 조건

P1/P2로 설명되지 않는 decoder 조건 무시나 장기 움직임 오류가 남을 때만 진행한다.

| 선택지 | 공정한 입력 | 필요한 작업·제약 |
|---|---|---|
| SeedVR2/FlashVSR 후처리 | LGVSC가 실제 만든 복원 영상 | 모든 arm에 같은 해상도 평가, 생성 세부 증가로 새 오류가 생기는지 확인 |
| SparkVSR 구조 차용 | 실제 RX 키프레임+LGVSC 복원으로 만든 보조 영상 | 원래 전체 LR 관측을 가진 설정과 다름. adapter/학습 분포 검증 |
| STCDiT 구조 차용 | 수신 구간·키프레임 기반 참조 | Open-Sora와 Wan 구조 차이, VAE segment·anchor mapping 재설계 |
| STAR식 영상 loss | 송신 원본으로 학습하되 추론 조건은 RX와 동일 | 동적·경계·키프레임 오류를 포함한 비디오 학습 자료와 별도 자원 |

현재 RTX 4080 16GB에서는 기존 모델의 짧은 구간 추론·수신 정보 변경·오프라인 평가부터 한다. STCDiT-tiny의 저자 24GB 조건이나 SeedVR2의 H100 조건을 이 PC의 실행 가능성으로 대신하지 않는다. offload·양자화가 필요하면 같은 모델의 별도 변형으로 기록하고 결과를 확인한다.

학습 ablation은 **image-only 추가 학습 / video 추가 학습 / video+장면·이벤트 조건**으로 비교하되 기초 pretrained 모델과 총 학습량을 명시한다. 이름만 image/video로 바꾸고 샘플 수·업데이트·계산량 차이를 숨기지 않는다. 단순히 사전학습 영상 모델을 사용했다는 사실을 프로젝트의 영상 미세조정 실행 증거로 쓰지 않는다.

## 9. 평가 지표·정답·통계

### 9.1 원본 기준 정답

오류 주석은 `video_id, object_id, t_start, t_end, type, region, evidence, confidence, visibility`로 저장한다. Added/Missing/Distorted는 복수 표시 가능하며 drift/flicker/action/speed/order/stale_scene 태그를 별도로 둔다. 정상 퇴장·가려짐·실제 cut을 음성 사례로 포함한다.

실제 생성 복원에서는 원본과 복원의 사건 대응을 독립적으로 판독한다. 가능하면 두 명의 독립 주석과 불일치 조정을 사용한다. 사람 검수가 없는 조건에서는 통제 편집의 확정 정답과 실제 복원의 별도 AI 검토·미확정을 구분하며, 같은 검출기의 출력을 재사용하지 않는다. 정답이 부족한 범위는 진단으로 남긴다.

Missing의 박스는 원본 객체 위치·시각에 근거한다. 복원에 없는 객체의 자동 검출 박스를 꾸며 넣지 않는다. 좌표계·시간 대응과 미확정 영역을 기록한다.

### 9.2 주 평가량

**오류 초/분:**

$$
H_c=\frac{60}{T_{\mathrm{eval}}}\int_{\Omega_{\mathrm{eval}}} \mathbf{1}\{c\text{ 유형의 확정 오류가 하나 이상 존재}\}\,dt
$$

유형별 시간 합집합을 사용해 동일 유형의 여러 객체를 중복 계산하지 않는다. 다수 객체 피해는 별도의 객체·초 합계로 보고한다. 이 값은 투명한 집계량이며 그 자체를 새 학술 지표로 주장하지 않는다. $\Omega_{\mathrm{eval}}$은 해당 유형의 오류 유무를 독립 정답으로 판정할 수 있는 시간 집합, $T_{\mathrm{eval}}$은 그 총길이다. 전후 비교에는 공통 평가 가능 구간을 사용하고, 전체 원본 대비 평가 가능·미주석·판정 불가 시간 비율을 함께 보고한다. 미확정을 정상으로 채우지 않으며 평가 가능 시간이 0이면 점수를 산출하지 않는다.

- **오류 변화:** 영상별 ΔH=완화 후−완화 전. 감소가 개선이다. Added/Missing/Distorted를 각각 보고하며 합성 가중 총점 하나로 대체하지 않는다.
- **새 오류:** 완화 전 정상이며 평가 가능한 동일 객체·시간에서 새로 생긴 오류. 정상 노출 시간을 분모로 함께 보고한다.
- **잔존·갱신:** 마지막 올바른 갱신 이후 잘못된 상태 지속 시간, 경계→검출→RX 적용→복원 반영 지연.
- **검출:** 유형별 PR-AUC, recall@고정 false alarms/min, temporal IoU, localization, 지연, UNKNOWN/coverage.
- **보조 품질:** PSNR/SSIM/LPIPS/DISTS, tLPIPS 또는 occlusion-aware warp 오차. 움직임을 멈춰 warp 오차를 낮춘 결과를 좋은 복원으로 판단하지 않는다.
- **비용:** 총 channel uses·CBR, 추가 의미 bytes, per-module/전체 지연, lookahead, GPU/호스트 최대 메모리, 재생성 횟수, 실패·보류율.

### 9.3 비교와 통계 해석

프레임이나 동일 원본에서 만든 변형을 독립 표본으로 세지 않는다. 원본별 대응 차이를 만들고 원본 단위 bootstrap 신뢰구간을 보고한다. 3개 생성 시드도 새 원본 3개로 세지 않는다. 유형별 표본이 작으면 신뢰구간이 넓다는 사실을 유지하고, 효과 방향·실패 사례부터 해석한다.

새 metric을 제어에 사용한 경우 그 metric의 개선만으로 성공 판정하지 않는다. 주요 결과는 독립 오류 주석이며, SHAFE/sFRC/기존 의미 후보의 **실제 개선·퇴화 방향 포착**을 별도 평가한다. 시간 정렬은 사건 지연을 지워 버리는 동적 정렬 대신 고정 PTS 대응을 사용한다.

합격 수치·비열등성 허용폭은 ETRI 메일에 없다. 데이터/교정 단계에서 실용적으로 허용할 새 오류·검출 오탐·추가 비용 한도를 정하고 평가 전에 동결한다. 평가 결과를 본 뒤 한도를 바꾸면 새 개발 실험으로 관리한다.

## 10. 최초 실행 묶음과 산출물

다음 순서로 계산량을 제한하면서도 질문을 분리한다.

1. **E0:** 3개 연속 원본에서 실행 가능성·시간축·baseline 오류 확인.
2. **E1+교정:** baseline 결과와 통제 오류로 검출·주석 체계를 교정. 후보 정책·문턱 동결.
3. **첫 미사용 비교:** 12개 원본 × 3개 대응 난수 쌍 × 4개 arm = **144개 60초 이상 복원 실행**. arm은 B1, 경계·갱신 C11, 동적 의미 D11, C11+D11. 비교 기준선은 캐시 재사용하며 같은 실행을 중복 생성하지 않는다.
4. **별도 원인 분리:** 개발/교정 세트에서 C10/C01/D10/D01, 누락·지연, 고정 간격 B2를 실행. 이 결과로 선택한 정책을 test에서 다시 고르지 않는다.
5. **후속 소수 비교:** E4 제어 또는 E5 외부 모델은 다음 미사용 원본 또는 사전 등록된 평가 arm에서 검증. 모든 정책×SNR×시드의 전수 조합부터 시작하지 않는다.

위 144회는 작업량 제안이지 실행 예약·완료가 아니다. 원본 1분당 총 처리 시간을 먼저 실측한 뒤 일정과 평가 규모를 정한다. 각 단계의 시간·전송 예산이 허용하지 않으면 실제 수행 범위를 기록하고 결론도 그 범위로 제한한다.

| 파일·자료 | 필수 내용 |
|---|---|
| 입력 manifest | 출처·원본 해시·연속 시작/끝·실제 길이·FPS·유형·분할 |
| 실행 manifest | 코드/가중치/설정 해시·AWGN·seed·RX 해시·변경 모듈 |
| packet/event 로그 | scene/segment·유효범위·TX/RX/적용 시각·갱신/초기화 이유 |
| 오류 주석·검출 결과 | 시간·객체·영역·유형·상태·독립 근거·자동/정답 구별 |
| 비교영상 | 원본/완화 전/완화 후 동기 3분할, 오류 시각·유형·가능한 영역 |
| 사례표 | 성공·미완화·새 왜곡·보류·실행 실패, 전체 수와 선정 규칙 |
| 결과표 | 유형·키프레임 나이·경계 누락 조건별 오류와 비용·불확실성 |

비교영상의 재인코딩 파일은 정량 평가 입력으로 사용하지 않는다. 원본은 내부 검증 저장소에 유지하고 외부 생성 API·공개 사이트로 전송하지 않는다. 문헌 조사 완료, 구현 완료, 60초 실행 완료, 실제 완화 입증은 서로 별도로 표시한다.
