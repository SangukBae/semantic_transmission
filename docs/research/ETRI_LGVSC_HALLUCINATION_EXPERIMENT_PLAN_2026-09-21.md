# LGVSC 단기 성능 개선 실행안

개정일: 2026-09-21. 사용자 요청에 따라 **효과 근거가 있고 적용 부담이 작은 방법부터** 실행하도록 범위를 줄였다. 이 문서는 우선순위·실행 제안이며 새로운 구현·60초 복원·할루시네이션 감소의 완료 기록은 아니다.

**주력은 기존 LGVSC의 키프레임 최대 간격을 1초로 줄이는 것이다. 다음으로 씬 체인지에서 키프레임·캡션·이전 참조를 함께 갱신한다. 저해상도 보조영상은 짧은 검증을 통과할 때만 추가한다.**

기준: [ETRI 메일](../ETRI_FOLLOWUP_EMAIL_SUMMARY.md) · [공통 평가 원칙](../ETRI_FOLLOWUP_PROTOCOL.md) · [선정 근거](ETRI_HALLUCINATION_LITERATURE_REVIEW_2026-09-21.md) · [구현 위치·상태](ETRI_HALLUCINATION_CODE_AUDIT_2026-09-21.md).

## 1. 적용 우선순위

순위는 로컬 관측·구현 재사용·ETRI 요구와의 연결에 따른 판단이다. 성공 확률을 수치로 추정할 근거는 없으며, 아직 어느 후보도 장시간 의미 오류 감소를 입증하지 않았다.

| 순서 | 방법 | 기대하는 개선과 근거 | 이번 결정 |
|---|---|---|---|
| 1 — 주력 | **SKEM 키프레임 보존 + 최대 1초 간격 + 기존 끝점/연결 정렬** | 긴 무관측 구간 축소. ETRI 10초에서 PSNR 19.71→23.83 dB, LPIPS 0.3553→0.2957. 전송량 4.09배. WebVid에서는 지표별 결과가 엇갈림 | 기존 `dense_1s`를 재사용. 개선 크기의 로컬 근거가 가장 강한 출발점 |
| 2 — 장면전환 대응 | **씬 경계에서 생성 구간 분리·새 키프레임·캡션 갱신·이전 참조 초기화** | 다른 장면의 객체·배경이 다음 장면에 남는 원인을 직접 차단할 가설. 로컬 효과는 미검증 | 1번 위에 한 가지 변경 묶음으로 추가. 고전환 영상에서 먼저 확인 |
| 3 — 조건부 보강 | **실제 전송한 저해상도 영상으로 저주파 보정** | 기존 두 짧은 영상에서 큰 PSNR 개선 가능성 관측. LPIPS·SSIM은 일부 악화 | 기존 코드를 짧게 검증하고 객체·동작 오류가 줄 때만 채택 |

현재는 추가 전송량을 기록하면서 품질 개선 가능성을 확인하는 안이다. 메일이 전송량 증가를 금지하지는 않지만 무제한 예산을 뜻하지도 않는다. **허용 전송량·처리 시간 상한을 실행 전에 기록**하고, 초과 시 개발 단계에서 2초 간격으로 낮춘 뒤 고정한다. 평가 영상마다 유리한 간격을 사후 선택하지 않는다.

정렬만의 전체 화질 개선은 확인되지 않았다. 1번은 이미 실행된 결합 조건을 재사용하며, 전체 개선을 정렬 단독 효과로 설명하지 않는다. 수동 행동 캡션·적응형 삽입·anchor 후처리는 기존 결과에서 이득이 작거나 일관되지 않아 기본 조합에서 제외한다.

## 2. 구현할 핵심 동작

**키프레임 간격:** 기존 선택 프레임을 유지하고 24 FPS에서 최대 24프레임 간격으로 보충한다. 추가 프레임도 NTSCC와 AWGN을 통과시킨다. 기존 수신 시각 정보는 재사용한다. `conditioning_alignment`와 `concatenation_policy`를 각각 고정하며 일반 설정에 키만 추가해 전달됐다고 가정하지 않는다.

**씬 경계:** 송신단에서 자동 경계 검출기 하나를 고정한다. 우선 후보는 [TransNet V2](https://github.com/soCzech/TransNetV2)이며 LGVSC 연결은 추가 구현이다. hard cut의 직전·직후 프레임을 확보해 서로 다른 장면의 두 끝점 사이를 생성하지 않는다. 새 장면의 캡션·광류를 다시 추출·전송하고 수신단의 이전 장면 caption과 생성 overlap 참조를 함께 만료시킨다. 최소 패킷 필드는 `scene_id / valid_from / valid_until`이다. 정상 연속 구간의 참조는 유지한다.

검출 누락 시에도 **최대 1초 키프레임 갱신과 주기적 짧은 구간 caption 재추출**이 남도록 한다. 기존 `dense_1s`는 부모 구간 caption·flow를 복사하므로 이 대체 동작을 이미 구현했다고 볼 수 없다. 개발 영상의 확인된 경계 하나를 고의로 누락시켜 잔존 오류를 확인한다. 주기 갱신도 누락을 완전히 해결한다고 보장하지 않으며, 정상 가려짐·조명 변화·dissolve의 오탐도 기록한다.

**저해상도 보강:** 기존 72×40·24 FPS·H.264 CRF 30·보정 강도 0.5를 출발값으로 삼는다. 실제 LDPC/16QAM/AWGN으로 받은 영상만 사용하며 기존 생성물의 후처리로 비교한다. 같은 생성 결과의 보정 전후를 먼저 확인해 효과를 분리한다. 추가 전송 비용을 포함하며, 키프레임 예산까지 바꾼 비교는 결합 시스템 효과로 표시한다. 고해상도 객체·동작을 복구한다는 보장은 없다.

## 3. 최소 실행 순서와 비교군

### A. 기존 짧은 결과를 재사용해 선택

ETRI 10초와 WebVid 14초 결과에서 객체 수·동작 순서·사라진 객체·이전 배경 잔류를 먼저 확인한다. 원본을 사용하는 이 검수는 외부 평가이며 수신단 제어에 넣지 않는다. 후보 하나의 개발 비교를 마치면 정책을 고정한다. 기존 결과가 있는 조건은 다시 생성하지 않는다.

### B. 실제 연속 60초 지원 확인

장면전환 낮음/일반/높음 각 1편, **총 3편의 실제 연속 60–90초**를 사용한다. 기존 영상 반복·단순 연결·감속으로 채우지 않는다. 먼저 20초→60초로 실행 가능성을 점검한다. 전처리의 16초 절단과 `max_frames=384`를 해소하고, 60초·24 FPS의 원본 1,440개 시점 모두에 복원이 대응하는지 확인한다. B의 공개 연결 정책이 만든 중복 경계는 대응표로 구분하며 원시 출력 길이도 기록한다. 고정 PTS 평가 대응에서 실제 사건 지연을 지우지 않는다.

메모리 때문에 내부 구간을 나눌 때 임의의 메모리 경계마다 상태·참조를 초기화하지 않는다. 길이 보존·입출력 분할 방식은 공통으로 적용하되 **씬 경계에 따른 초기화는 S에만** 적용한다. 전체 실행 시간·GPU/호스트 최대 메모리·실패 위치를 기록한다. 60초 미달이면 최대 검증 길이를 보고한다.

### C. 기준선 → 키프레임 보강 → 장면 대응의 세 조건

| ID | 조건 | 확인할 차이 |
|---|---|---|
| B | 기존 LGVSC 생성 정책을 공통 장시간 실행 경로에 적용 | 완화 전. 원 논문 완전 재현으로 표시하지 않음 |
| K | B + 최대 1초 키프레임 + 고정한 끝점/연결 정렬 | 이미 짧은 결과가 있는 주력 조합의 효과와 비용 |
| S | K + 씬 경계 처리 + 구간 의미정보 갱신 | 추가 장면 대응의 효과와 비용 |

**우선 3편 × 3조건 × 1개 난수 쌍 = 9회 장시간 복원**으로 제한한다. AWGN 10 dB, 576×320, 24 FPS, 30 steps, `(channel_seed, generation_seed)=(1024,42)`를 출발안으로 고정한다. 같은 seed여도 구간 분할이 바뀌면 생성 잡음이 일대일로 같지는 않다. 추가 SNR·다수 시드·144회 평가는 이번 필수 범위에서 뺀다.

장시간 점검·교정에 사용한 원본은 개발 자료다. 시간이 허용되면 정책 동결 후 별도 미사용 원본을 유형별 1편씩 평가한다. 개발 3편만 완료하면 예비 사례 결과로 제출하고 일반화는 주장하지 않는다. 실패 영상이나 불리한 seed를 제외하지 않는다.

저해상도 보강은 개발 비교에서 유효할 때만 최종 후보에 추가하고 평가 전에 고정한다. **동일 생성물의 후처리는 복원 재생성이 필요 없다.** 동일 예산에서 우월하다고 주장하려면 K의 간격을 개발 단계에서 정해 S 또는 보조영상 조합과 비용을 맞추거나 비용–오류 곡선을 제시한다. 단순 K 비교군은 생략하지 않는다.

## 4. 빠르게 확인할 성능과 제출자료

- **주 평가:** 원본 대비 Added/Missing/Distorted의 시간 구간과 가능한 객체 영역, 오류 초/분, 완화 후 새 오류, 씬 경계 뒤 이전 상태의 잔존 시간. 유형별 오류 초/분은 평가 가능한 시간에서 오류 시간의 합집합 비율×60으로 계산한다.
- **정답:** 모든 조건에 같은 원본 시각을 적용한다. 가려짐·정상 퇴장을 오류로 세지 않고, 미확정은 따로 남긴다. 전후 공통 평가 가능 구간과 전체 영상 대비 검수 비율을 함께 보고한다. Missing 영역은 원본 위치에 근거한다.
- **검출 범위:** 독립 원본 대조로 확인한 오류와 자동 후보 표시를 구분한다. 자동 오류 위치·유형 검출은 확인된 구현 범위만 보고한다. 씬 검출 precision/recall·누락 사례도 기록한다. 원본 없는 범용 RX 할루시네이션 검출기는 이번 필수 구현에서 보류한다.
- **보조 평가:** PSNR·SSIM·LPIPS와 전송량·처리 시간. PSNR 상승만으로 할루시네이션 감소를 판정하지 않는다. 개발 단계에서 주요 오류 감소와 정상 객체·동작 보존을 함께 확인한 후보를 채택하고, 동결 후의 악화는 결과에 그대로 포함한다.
- **비교 조건:** 원본 구간·시간축·AWGN·평가기 고정. 공통 시각 심벌의 잡음을 재사용하고 추가 심벌의 seed 규칙을 기록한다. 시각 심벌·caption·scene 정보·보조영상·부호화/패딩을 합산한다. 원본 키프레임을 직접 넣은 oracle은 실제 통신 결과에서 제외한다.
- **제출물:** 원본/완화 전/후 동기 3분할 영상, 오류 시각·유형·가능한 영역 표시, 성공·미완화·새 왜곡 사례표, 비용과 실행 상태. 사례가 관찰되지 않으면 없다고 기록한다. 비교영상 재인코딩본은 정량 평가에 쓰지 않으며 원본은 내부에 보관한다.

학습 관련 답변은 별도 짧은 표로 병행한다. NTSCC 이미지 코덱, PLLaVA 영상 caption, Open-Sora 영상 생성의 **실제 체크포인트와 공개 학습 이력**, 프로젝트 추가 학습 여부를 구분하고 미공개 항목은 그대로 표시한다. 동적 의미정보는 먼저 현재 짧은 구간 caption이 동작·방향·등장/퇴장 시점을 놓치는지 확인한다. 놓치는 사례가 남을 때만 자동 prompt를 보강해 추가 비교한다.

## 5. 이번에 보류할 범위

대체 생성 모델 도입, 영상 재학습, DPS/RPU 이식, 복잡한 객체 이벤트 패킷, 다중 후보 재생성, 새로운 범용 검출기와 대규모 신규 지표 검증은 첫 제출물 이후로 둔다. 기존 지표 연구는 유지하되 최종 채택을 기다리며 영상 개선을 미루지 않는다. anchor 후처리·CFG 탐색·적응형 삽입은 현재 주력보다 근거가 약해 기본 조합에 더하지 않는다.
