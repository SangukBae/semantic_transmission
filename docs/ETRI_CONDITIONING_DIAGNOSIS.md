  프레임을 요구하여 6개 집중 검토 후보를 만들었고, 각 후보에서 최소 한 프레임을 시각 확인했다. 이 임시 규칙은 검증된 할루시네이션 검출기가 아니다.

  AI가 시각 검토했다. 오류/후보 11건에 관찰 프레임, 검토 시간대, 대략적 영향 영역,
  Added/Missing/Distorted, 확신도와 근거 이미지를 기록했다.

검토 창의 시작·끝은 **오류가 연속해서 존재한다고 확정한 시간 경계가 아니다**.
영역 좌표는 대표 프레임의 대략적 위치이며 프레임별 객체 추적 주석은 아니다.
AI 단독·비맹검·탐색 검토이므로 발생률이나 검출 정확도를 계산하지 않았다.

## 생성 조건에서 확인한 내용

**캡션·광류 행의 구간 대응은 정상이다.** 수신 메타데이터 109행을 실제 GPU 생성 로그의
109개 프롬프트와 대조했다. 소문자·공백 정규화와 motion score 소수 첫째 자리 변환을 적용하면
109개 모두 일치했다. 이번 실패를 캡션 한 행의 인덱스 밀림으로 설명할 근거는 없다.
[대조 기록](../outputs/etri_conditioning_review_20260928/caption_alignment_audit.json)

**설명의 내용에는 누락·충돌 후보가 있다.** 개가 보이는 구간의 캡션에는 개가 언급되지 않는다.
54.6~55.5초 캡션은 차량이 오른쪽을 향해 주차되어 있다고 설명하지만, 확인한 원본 표본은
차량 정면을 보여준다. 실제 생성기에 이 설명이 전달된다. 설명 누락·충돌이 오류를 일으킨 정도는
캡션만 바꾸는 별도 실험 전까지 미확정이다.

**마스크 정렬이 요청한 시간 위치를 바꾼다.** 현재 Open-Sora의 `apply_mask_strategy`는
`align=5`일 때 참조 시작과 대상 시작을 잠재 시간축의 5칸 단위로 조정한다.
기존 실행의 실제 VAE 참조 길이와 출력 마스크를 확인하고, 같은 함수를 인덱스 표식 텐서에
적용하여 아래 수를 얻었다.

| 항목 | 위치가 바뀐 경우 |
|---|---:|
| 끝 키프레임의 주입 위치 | 84 / 109 생성 구간 |
| 이전 생성 영상의 참조 시작 위치 | 103 / 108 구간 연결 |

이 수는 **위치 변경 횟수**이며 의미 오류 횟수나 할루시네이션 발생률이 아니다.
5칸 조정을 없애는 것이 VAE와 생성 모델에 항상 더 적합하다는 뜻도 아니다.
현재 VAE는 17개 영상 프레임을 5개 잠재 프레임 블록으로 처리한다. 한 장에서 얻은 잠재 표현을
블록 중간에 주입하는 것과 블록 시작에 주입하는 것은 같지 않으며, **잠재 인덱스의 마지막 위치를
맞췄다고 출력 픽셀의 마지막 프레임까지 정확해진다고 가정할 수 없다**. 반올림 해제는 검증 대상인
단일 변경안이지, 확인된 해결책이 아니다.

54.625~55.458초 구간(키프레임 1311→1331)은 다음과 같다.
끝 키프레임은 요청·실제 모두 잠재 인덱스 10에 들어가므로 이 구간 자체의 끝 위치는 밀리지 않는다.
하지만 이전 구간은 7개 잠재 프레임을 만들고, 마지막 5개인 **2~6**을 요청해도
실제로 **0~4**를 다음 구간 참조로 사용한다. 따라서 짧은 키프레임 간격만으로 이전 상태의
오염 가능성이 사라지는 것은 아니다. 이것만으로 해당 차량 오류의 원인을 확정할 수는 없다.

## 결과

**세 창 × 두 방법의 생성·평가를 모두 완료했다. 반올림 해제는 일부 구간을 개선하지만
인물 구간에 새 왜곡을 만들므로 기본 설정에 일괄 적용하지 않는다.**
기준선의 기존 생성 코드·설정은 유지했다. 실제 모델 생성·평가에 총 29.15분이 걸렸다.

- **성공 표본:** 58.5, 58.875, 59.0, 59.208초의 재생성 기준선은 심한 다색 추상 무늬를

- **새 왜곡:** 9.5초의 화면 깨짐은 개선되지만 10.167·10.417초에서는 변경안이 전경 인물을
  매우 크게 확대하고 배경 구조를 바꾼다. 인물 구간을 개선됐다고 판정할 수 없다.

  재현되지 않았다. 따라서 원래 55초 오류를 이 보정으로 해결했다고 해석하지 않는다.

## 다음 실험의 판단

이 절의 제안을 실행한 후속 기록은 [마지막 17프레임 참조 실험](ETRI_TAIL_REFERENCE_DIAGNOSIS.md)에 분리한다.

현재 결과로 `align=None`을 전 영상의 기본값으로 바꾸는 것은 권하지 않는다.
다음 한 가지 실험은 **`align=5`는 유지하고, 이전 생성 영상 전체 대신 마지막 17프레임을
잘라 인코딩하여 다음 구간 참조로 사용하는 방법**이다. 17프레임→5잠재 프레임 단위를 유지하면서
오래된 참조 위치가 선택되는 문제를 분리할 수 있다. 이는 제안이며 이번에 실행하지 않았다.

이때 참조 인코딩 길이가 바뀌면 VAE의 난수 소비량도 달라질 수 있으므로 생성 초기 잡음을
명시적으로 맞추고 검증해야 한다. 같은 세 창의 성공·잔여 오류·새 왜곡을 다시 비교한 뒤,
회귀가 줄어든 후보만 60초 전체와 다른 개발 영상으로 확장한다.

## 재실행

이 컴퓨터의 기존 60초 수신 결과를 사용하는 진단 명령이다. SKEM·캡션·전송을 다시 하지 않는다.
완료 단계는 산출물 해시를 검증하고 재사용한다. 코드·환경이 변경되면 다른 `--output` 경로를 사용한다.

```bash
env -u LD_LIBRARY_PATH -u PYTHONPATH PYTHONNOUSERSITE=1 PYTHONUNBUFFERED=1 OMP_NUM_THREADS=8 \
  "$HOME/anaconda3/envs/lgvsc/bin/python" scripts/diagnose_etri_conditioning.py
```

완료 후 비교 MP4·표본 이미지·프레임별 대응 표를 만든다. 이 단계에는 모델 추론이 없다.

```bash
"$HOME/anaconda3/envs/lgvsc/bin/python" scripts/etri_conditioning_evidence.py
```
