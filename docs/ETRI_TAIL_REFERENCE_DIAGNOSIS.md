# 이전 생성 구간의 마지막 17프레임 참조 실험

2026-09-28. [반올림 해제 실험](ETRI_CONDITIONING_DIAGNOSIS.md)의 후속이다.
**세 창 × 두 방법의 실제 생성·평가를 완료했다.** 차량 구간과 일부 깨짐은 개선됐지만,
인물 위치·형태 오류와 차량 문의 심한 붕괴가 남았다. 기본 설정에 일괄 적용하지 않는다.

## 질문과 고정 조건

기존 `align=5`를 유지하면서 **이전 생성 구간 전체 대신 마지막 17프레임을 VAE에 입력**하면
참조의 시간 위치가 더 잘 맞고 중간 생성 오류가 줄어드는지 확인한다.
17프레임은 새 원본을 추가 전송하는 것이 아니라 수신기에서 이미 생성한 영상의 끝부분이다.

- 개발용 `tv_low_08`의 기존 10초 인물·55초 차량·59초 차량 문 주변 세 창을 그대로 사용한다.
  원본 프레임 범위는 217~266, 1303~1334, 1400~1439(양끝 포함)이다.
- 동일한 AWGN 10 dB 수신 키프레임, 캡션, 광류, 체크포인트, seed 2025, 30단계,
  576×320·24 fps를 사용한다. 추가 전송량은 0이다.
- 두 방법 모두 `conditioning_alignment='official_release'`, `align=5`이다.
  기존 짧은 첫 구간의 왼쪽 패딩 처리와 최종 구간 연결 정책도 유지한다.
- 변경안에서 다음 구간으로 넘기는 참조는 **17개 영상 프레임 → 5개 잠재 프레임**이다.
  이때 마스크의 참조 시작은 0이므로, 5칸 정렬로 더 앞의 구간이 선택되는 문제가 없다.
  끝 키프레임의 주입 위치 조정과 캡션 내용은 바꾸지 않는다.

이전 생성 결과 자체의 오류는 마지막 17프레임에도 남을 수 있다.
이 실험은 참조 구간 선택만 분리한 것이며 모든 할루시네이션 원인을 해결하는 조치는 아니다.

## 난수와 재현성 통제

단순히 같은 시드를 설정하는 것만으로는 부족하다. 참조 인코딩 길이가 달라지면 VAE가 사용하는
난수 개수도 달라져 이후 생성 잡음까지 바뀔 수 있기 때문이다.

기준선을 새로 생성하면서 구간별 **초기 잡음 텐서**, 그 시점의 CPU·CUDA 난수 상태,
참조 인코딩 직전 난수 상태를 저장한다. 변경안은 참조 인코딩 직전에 대응 난수 상태를 복원하고,
생성 직전에 기준선의 초기 잡음과 난수 상태를 재사용한다. 두 방법의 마스킹 직전 잡음,
수신 키프레임 잠재표현, 난수 상태를 해시로 비교한다. VAE가 만든 이전 생성 참조 값은
실험에서 바꾸는 대상이므로 같다고 가정하지 않는다.

기준선에서는 저장 과정이 난수 상태나 잡음을 바꾸지 않도록 구현했다. 새 기준선 MP4가
이전 실험의 기준선과 같은지도 확인한다. **비교 쌍은 새로 재시작한 짧은 창**이며,
기존 60초 실행 전체의 생성 상태를 재현하지는 않는다.

## 검증과 판단

- 12개 생성 구간 쌍의 초기 잡음·생성 난수 상태·수신 키프레임 잠재표현이 모두 일치했다.
- 9개 이전 참조의 인코딩 직전 난수 상태가 일치했다. 변경안은 전부 17프레임→5잠재 프레임,
  실제 마스크 참조 시작 인덱스 0이었다. 기존 경로가 이미 17프레임을 쓰던 3개는 길이가 같고,
  나머지 6개에서 실제 잘라내기가 발생했다.
- 12개 생성 구간 중 6개는 잡음 재사용이 없었다면 초기 잡음이 달라졌을 것이다.
  같은 시드만 설정한 비교와 구분해야 한다.
- 변경 전 구간의 PNG 18·9·10프레임은 각 창의 기준선과 일치했다.
  기존 60초 산출물 3,275개·단계 기록 15개와 이전 진단의 단계 기록 13개를 보존했다.
- 자동 테스트 21개가 통과했고, 같은 실행 명령으로 13개 단계를 모두 추론 없이 재사용했다.

[검증 기록](../outputs/etri_tail_reference_20260928/verification.json)

참조를 최근 구간으로 제한하는 것은 일부 개선 신호가 있으나, **끝 키프레임 주입과 이전 생성
오류의 영향까지 해결하지 못한다**. 기본값 채택을 보류하고 개발 후보로 유지한다.
다음 분리 실험은 이번 17프레임 참조와 앞선 반올림 해제를 **함께 적용한 네 번째 조건**을 같은
잡음으로 비교하는 것이다. 두 변경의 상호작용을 확인한 뒤 60초 전체 확장 여부를 판단한다.
이 결합 조건은 본 실험에 포함하지 않았다. 이후 실행 상태와 결과는
[별도 결합 실험](ETRI_COMBINED_REFERENCE_DIAGNOSIS.md)에 기록하며, 본 실험 결과와 구분한다.

## 실행과 산출물

```bash
bash scripts/check_etri_tail_reference.sh
```

세 창 × 기준선/변경안의 생성·평가, 조건 해시 확인, 원본/기준선/변경안 비교 영상·표본 이미지,
프레임별 지표 표를 순서대로 만든다. SKEM·캡션·전송을 재실행하지 않는다.
같은 명령은 완료 단계의 산출물 해시를 검사해 재사용한다. 코드·환경이 바뀌면 새 `--output` 경로를
사용한다. `--source`는 이전 반올림 해제 실험 폴더를 지정한다.

출력은 `outputs/etri_tail_reference_20260928`에 저장한다.

| 파일 | 의미 |
|---|---|
| `protocol.json`, `pairs.json` | 원본 실험의 검증된 단계 기록, 실행 코드·환경·설정과 대응 창 |
| `*/baseline/receiver/replay/*.pt` | 이번 기준선에서 저장한 구간별 잡음·난수 상태 |
| `*/*/receiver/conditioning_trace.json` | 실제 참조 입력 길이·잠재 길이·마스크·조건 해시 |
| `RESULT.json` | 대응 조건 검증과 자동 화질 지표. 독립 의미 오류 판정과 구분 |
| `*/comparison.mp4`, `*/comparison_samples_*.jpg` | 같은 시점의 원본/재생성 기준선/17프레임 참조 |
| `*/paired_quality.csv`, `*/evidence.json` | 프레임별 지표와 전체/중간 프레임 집계 |
| `AI_REVIEW.json` | AI의 표본 관찰. 독립 정답이나 전 프레임 주석을 뜻하지 않음 |

실제 모델 실행 전에 난수 재사용·입력 차원 불일치 거부·실제 꼬리 프레임 선택·조건 불일치 거부와
기존 조건 처리 테스트 **21개를 통과**했다. 기존 생성기의 기본 설정은 변경하지 않았다.
