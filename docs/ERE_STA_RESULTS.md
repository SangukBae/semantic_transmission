# ERE·STA 시험 결과와 분석

이 문서는 **v3.0의 1회차 실패 기록**이다. 이후 코드 수정과 새 폴더의 개발 재감사에서는
필수 관문이 통과했다. 현재 상태는 [v3.1 수정·재감사 결과](ERE_STA_REAUDIT_RESULTS.md)를 참고한다.
아래 수치·구현 설명은 1회차 실행 당시를 기준으로 보존한다.

2026-09-14. **두 후보의 계산 코드를 구현하고 사전 검사를 실행했다.
ERE 사건 추출기가 필수 관문에 미달해 본 성능 실험은 실행하지 않았다.**
STA의 근거 판정·산술 검사는 실행했으며, 채널 오류를 생성 오류로 잘못 분류하는 반례도 확인했다.
본 실험을 실행한 뒤 AUC가 낮아서 탈락한 결과와 구분한다.

| 항목 | 실행한 범위 | 결과 |
|---|---|---|
| ERE | RAFT 광류 → 움직임 영역 → 추적 → 사건 추출·대응 구현, 개발 원본 추출기 감사 | **필수 관문 미달** |
| STA | TX/RX 근거 판정, EDR·CLR·GFR·GHR 계산, 분석적 규칙 사례 6개 | 기본 산술 검사 통과, **내용 손상 오귀착 반례 확인** |
| 본 후보·기존 지표 비교 | ERE/SER, OOR/HOR/ODR, MTE·OTF·IDF1 등 비교 | **미실행** |
| STA 모의 복원·실제 복원 연결 | 영상과 송수신 표현을 연결한 귀착 정확도 | **미실행** |

프로토콜 §6은 **“아래를 통과하지 못하면 지표 점수를 계산하지 않는다”**고 정했다.
사건 추출 재현율·정밀도가 각각 80% 이상이어야 하므로 이 조건을 그대로 적용했다.
ERE 본 평가·STA 귀착 정확도의 결과는 `null`이다. 정확도 0% 또는 실패율 100%라는 뜻이 아니다.

## 자료와 정답 검사

- 공개 DAVIS 원본 **22개**: 개발 8개, 평가 14개.
- 새 합성 원본 **48개**: 개발 16개, 평가 32개. 장면마다 정답 사건 6개가 있다.
- 총 **70개 원본, 2,216개 파생 사례**를 준비했다. 이전 1·2차 원본 ID·합성 seed 중복은 0개다.
- 정답 검사에서 **2,211개를 채택하고 5개를 제외**했다. 제외한 사례는 공개 영상의 역순·구간 교환으로,
  변형을 넣어도 정해진 사건 변화가 확인되지 않았다.
- 정상 대조군 **656개 모두** 사건·존재 불변 조건을 통과했다. 합성에는 질감·색상·조명·카메라·
  외곽 스타일·미세 움직임 대조군을 포함했고 외곽 스타일의 IoU/종횡비 범위도 검사했다.

정답 검사 통과는 지표의 정확도 통과가 아니다. 사건 종류·시각·방향과 제한된 객체 모양 조건을
검증한 것이며 모든 의미 속성을 보장하지 않는다. 공개 JPEG에는 8 Hz의 시험 재생 시간을
부여했고 원 촬영 시간이라고 주장하지 않는다. 합성 개발·평가는 같은 장면 형식의 다른 seed다.

추출기 검사는 **개발 원본 24개**에서만 실행했다. 평가용 46개 원본은 정답 적격성만 확인했고
후보 점수는 계산하지 않았다. 새 사람 검수는 없으며 DAVIS의 기존 사람 주석을 정답 검사와
추출기 감사에 사용했다. RGB 추출기에는 정답 마스크·사건·변형 이름을 입력하지 않았다.

## ERE가 막힌 이유: 움직임 영역과 객체의 존재는 다르다

| 개발 자료 검사 | 정답 수 | 맞춘 수 | 재현율 | 정밀도 | 판정 |
|---|---:|---:|---:|---:|---|
| 합성 사건 | 96건 | 15건 | **15.6%** | **15.0%** (예측 100건 중 15건) | 필수 기준 80% 미달 |
| 공개 사건 | 66건 | 9건 | 13.6% | 9.0% | 보조 감사 |
| 합성 객체-프레임 | 1,328개 | 1,310개 | **98.6%** | 해당 관문 없음 | 필수 기준 통과 |
| 공개 객체-프레임 | 408개 | 83개 | 20.3% | 선택 객체만 주석되어 전체 정밀도 미산출 | 사전 선언대로 진단 전용 |

합성 사건의 종류별 결과는 다음과 같다.

| 실제 사건 | 정답 | 대응 성공 |
|---|---:|---:|
| 이동 시작 | 32 | **0** |
| 방향 전환 | 16 | 8 |
| 정지 | 16 | **0** |
| 등장 | 16 | 6 |
| 퇴장 | 16 | 1 |

원본 `renderer/260915100`에서는 0.5초에 **기존 객체가 움직이기 시작했지만** 추출기는
새 움직임 트랙의 `enter`로 기록했다. 2.625초에 **객체가 멈췄지만** `exit`로 기록했다.
정지하면 광류의 움직임 영역이 사라지고, 재출발하면 새 영역이 생기기 때문이다.
현재 정의에는 정지 중인 동일 객체가 계속 존재한다는 상태를 유지하는 경로가 없다.

![정답과 추출 사건의 시간 비교](../outputs/ere_sta_20260914_v1/event_gate_example.png)

사후 원인 분석에서 방향 조건만 제거해도 합성 대응 수는 **15/96으로 같았다**.
종류까지 무시하고 시각·위치만 맞추면 68/96이었으며 `start → enter` 31건,
`stop → exit` 15건 등의 혼동이 나타났다. 이 느슨한 대응은 실패 원인 분석용이고,
원래 관문·수식·사건 종류를 바꿔 통과시킨 결과가 아니다.
정답 객체와 연결된 예측 트랙 64개 중 추가 분절 트랙은 16개(정의한 분절률 25%)였다.

이 결과는 사건 개수로 나누는 ERE 수식의 우열을 평가하기 **이전의 문제**다.
잘못 분류된 사건을 세면 사건 단위 분모도 이를 해결하지 못한다.
이번에는 문턱을 낮추거나 `start/enter`, `stop/exit`를 같은 사건으로 합치지 않았다.
정지 객체의 존재 추적을 추가하는 변경은 별도 설계·개발 관문 검증이 필요하다.

## STA에서 확인한 것과 아직 확인하지 않은 것

STA의 계산 코드는 사건/객체 단위, 대응 관계, 송신 표현(TX), 수신 표현(RX)을 받아
네 비율을 따로 계산한다. 빈 분모는 `null`로 반환하고 중복 대응을 거부한다.
변형 이름이나 정답 오류 종류를 계산 함수에 전달하지 않는다.

다음은 **두 개의 사건을 둔 분석적 규칙 검사**다. 공개/합성 영상의 귀착 정확도 통계가 아니다.

| 설정 | 주요 계산 결과 | 해석 |
|---|---|---|
| 정상 표현·정상 재현 | 네 비율 모두 0 | 정상 산술 확인 |
| TX에서 사건 근거 모두 누락 | EDR=1, CLR/GFR=null | 송신 근거 없음 |
| TX 정상, RX 패킷 모두 제거 | CLR=1, GFR=null | 수신 근거 없음 |
| TX/RX 정상, 재현 사건 모두 누락 | GFR=1, CLR=0 | 수신 근거는 있으나 미재현 |
| 근거 없는 객체 한 개 추가 | GHR=1/3 | 재현 단위 세 개 중 하나가 근거 없음 |
| **RX 키프레임 내용 손상, 시각은 유지, 사건 미재현** | **CLR=0, GFR=1** | **채널 오류를 생성 실패로 오귀착** |

마지막 반례는 현재의 “사건 근처에 키프레임이 있으면 근거 있음” 규칙에서 나온다.
내용이 손상돼도 시각이 남아 있으면 RX 근거가 있다고 판정한다.
따라서 **패킷 제거를 구별하는 것과 내용 손상의 원인을 구별하는 것은 다르다.**
이 검사는 실제 무선 비트를 훼손하거나 실제 디코더를 실행한 실험이 아니다.

후속 설계에서는 단순 키프레임 존재와 실제 사건·객체 정보가 읽히는 상태를 구분해야 한다.
원본 정답을 STA에 직접 넣어 그 구분이 되는 것처럼 평가해서는 안 된다.
STA의 실제 영상/TX/RX 어댑터와 표현에서 다시 렌더링하는 모의 복원 전체 경로는 이번 단계에서
구현·실행하지 않았다. 필수 관문 통과 후 본 평가 실행기도 이어서 구현해야 한다.

## 구현·검증 및 남은 범위

구현한 파일은 `event_metric.py`, `attribution_metric.py`, `metric_v3_cases.py`,
`metric_v3_validation.py`와 실행·보고 스크립트다. **전체 자동 테스트 67개가 통과**했고,
두 값의 범위·빈 분모·일대일 대응·카메라 이동·반대 방향 영역·정상 대조군·STA 반례를 검사했다.
기존 MTE·OTF 코드와 실험 결과는 수정하지 않았다.

자료와 정의는 해시로 고정했다. 구현 전 원문, 고정 당시 문서·코드 사본, 실제 가중치/모델 버전
확인 결과를 실행 폴더에 보존했다. [실행 전 보완 기록](ERE_STA_EXECUTION_NOTES.md)에
공개 자료 수 오기, 미지정 속도 기준, 모양 오류의 정답 관문 등 해석을 남겼다.
관문 결과를 본 뒤 후보 수식·문턱을 수정한 이력은 없다.

관문이 실패한 상태에서 `event`, `object`, `attribution` 실행을 요청하면 모두 차단되는지도
확인했다. 본 후보 점수 파일은 **0개**다. 코드 검사 통과·정답 검사 통과·성능 검증을 구분한다.

**완료:** 자료 준비, 정답 감사, 개발 추출기 검사, ERE/STA 핵심 계산·규칙 검사, 결과·원인 기록.
**미완료:** 추출기 관문 통과, 후보별 AUC/검출률·기존 지표 비교, STA 귀착 정확도,
실제 복원 귀착, 신규성 입증. 따라서 ETRI 1단계 완료를 선언하지 않는다.

재현은 패키지 루트에서 다음 순서로 한다. 새 출력 폴더를 사용하며,
같은 원본·seed 재실행은 독립 검증이 아니다.

```bash
bash scripts/run_metric_v3.sh prepare outputs/ere_sta_repeat
bash scripts/run_metric_v3.sh truth_audit outputs/ere_sta_repeat
bash scripts/run_metric_v3.sh extractor_gate outputs/ere_sta_repeat
bash scripts/run_metric_v3.sh summarize outputs/ere_sta_repeat
```
