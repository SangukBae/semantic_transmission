# FSO·EOI·UEP 관측·정답 정렬 개발 수정 (2026-09-16)

## 연구 상태

이 수정은 `metric_validation_20260916_v1`의 실패를 확인한 **후속 개발 실험**이다.
기존 코드·임계값·결과를 수정하지 않는다. 동일 영상 재평가는 미관측 데이터 검증이
아니며, 개선된 결과가 있어도 ETRI 최종 지표 채택 또는 신규성을 선언하지 않는다.

## 수정 전에 정한 구성

1. 기존 SAM2/DINO/RAFT 관측 캐시를 읽기 전용으로 재사용한다. 검출기를 다시 학습하지 않는다.
2. 같은 영상의 시간적으로 겹치지 않는 추적 조각은 최대 2개 결측 프레임,
   DINO 유사도 0.80, 예측 위치 거리(화면 대각선) 0.08 안에서 연결한다.
   결측 프레임에 객체를 만들어 넣지 않는다. 동시에 보이는 두 객체는 합치지 않는다.
3. 영상 사이에는 프레임별 일대일 대응을 사용한다. 마스크 IoU≥0.50,
   면적비≥0.50인 기하 대응 또는 특징 유사도≥0.65·거리≤0.15·IoU≥0.05인
   대응을 허용한다. 연속 조각이 한 원본 객체를 공유할 수 있지만 같은 프레임의
   두 복원 객체를 하나의 원본 객체로 설명하지 않는다. 대응된 프레임과 점유 창은 별도로 기록한다.
4. 사건 정의를 **화면 좌표의 객체 중심 궤적**으로 명시한다. 8 Hz, 5프레임 평활화,
   속도 0.5 pixel/frame, 전후 2프레임, 정지/출발 2프레임 지속, 방향 전환 90°,
   사건 간격 3프레임을 RGB 관측과 주석 궤적에 동일하게 적용한다.
   주석은 DAVIS 마스크 및 알려진 편집에서만 얻는다. RAFT/SAM2/DINO 출력으로 정답을 만들지 않는다.
   이 좌표계는 카메라 독립적인 세계 좌표의 움직임을 보증하지 않는다. camera 변형은 알려진
   아핀 변환을 주석 중심에도 적용한다. 이를 세계 상태 보존 검증의 통과로 해석하지 않는다.
5. FSO 점유 창 4프레임, 이전 움직임 대비 속도비 0.5, 이전 방향 허용각 45°를 유지한다.
   궤적 결측·사건 부재는 null이다. EOI는 원본 순서 쌍 중 대응 가능한 비율이
   80% 미만이면 null로 보류하고, 기존 방식의 원시 역전율과 대응률을 함께 남긴다.
6. UEP는 신뢰할 수 있게 원본 객체와 대응된 복원 조각을 원본으로 설명한다.
   나머지 조각은 수신 성공 슬롯에서 실제 대응된 RX 객체 프레임만 제외한다.
   조각별 최댓값과 원래 4프레임 포화 척도를 보존한다.
   장기 포화를 없애기 위해 분모를 사후 변경하지 않는다.

## 정답의 대상 범위

합성 영상은 모든 생성 객체를, 자연 영상은 DAVIS에서 선택한 객체만 정답으로 안다.
자연 영상의 FSO/EOI에서는 선택 객체의 주석 사건과 RGB 추출 사건의 **쿼리 대응 진단**을
별도로 제공한다. 전체 자동 점수를 선택 객체 정답과 비교한 값을 채택 판정으로 쓰지 않는다.
객체 추가가 없는 외형 대조군과 알려진 삽입 객체의 UEP는 기존 정답을 그대로 사용한다.
평가 대상·관측 불가·쿼리 누락을 보고하며 누락을 정상 0으로 채우지 않는다.

## 실제 복원 12개 독립 근거

모델을 다시 복원하지 않는다. 32개 평가 프레임과 실제 RX 키프레임 근거를 이미지로
내보내고 점수 추출기 출력을 사용하지 않는 AI 시각 검토를 기록한다.
검토자는 이전 v5 집계 결과를 이미 알고 있으므로 완전 맹검 또는 사람 독립 검수가 아니다.
선명하게 확인 가능한 객체/사건과 불확실한 객체/사건을 구분한다. 확인 불가능한 정답은 null로 둔다.
대략적인 이진 관찰을 정확한 FSO/EOI/UEP 수치 정답으로 둔갑시키지 않는다.
원본·복원·시간축·근거 파일의 SHA256으로 검토를 결합한다.

## 산출물과 재현

새 구현·결과는 v6 개발 수정으로 구분한다. 원래 세 단계의 모든 저장 결과를 보존한다.
수정 관측기와 대응·관측률 회귀 검사를 수행하고, 합성 교차/RX/자연/기존 실제 복원을 재평가한다.
설정·입력·코드를 실행 전에 동결하며 변경 시 기존 산출물 덮어쓰기를 거부한다.
임계값은 새 정상 사례에서 사후 선택하지 않는다. 기본 0 초과 경고를 진단으로 기록하며,
새 임계값의 독립 교정·잠금 평가 전에는 `DEVELOPMENT_ONLY`로 남긴다.
