# MTE·OTF 구현 및 2차 검증 결과

2026-09-14. **MTE → OTF 구현과 새 자료의 자동 검증을 완료했다. 두 후보 모두
사전 채택 기준에는 미달했으며, 새 논문 지표로 확정하지 않는다.**
사람의 추가 검수 없이 오류를 삽입하고 정답을 기록했다. 실제 복원의 의미 정확도와
사람 판정에 대한 일치도를 입증한 실험은 아니다.

| 후보 | 확인된 결과 | 판단 |
|---|---|---|
| MTE: 움직임 차이 | 공개 영상 시간 오류 평균 검출률 85.9%, 정상 오탐률 4.7%. 짧은 역순·순서 교환에는 취약 | 기존 RTE보다 개선됐지만 시간축 비교 지표 전체를 넘지는 못함 |
| OTF: 객체 존재·모양 차이 | 합성 객체 누락 100%, 추가 0%, 모양 변경 33.3% 검출. 정상 오탐률 0% | 누락에는 반응하지만 추가·왜곡을 포괄하는 지표로는 부족 |

검출률은 **삽입한 오류를 잡은 비율**, 오탐률은 **정상 대조군을 오류로 잘못 판정한 비율**이다.
OTF 표의 수치는 사전에 정한 주 점수 `max(1−OTF-F1, ODR)`의 결과다.

## 무엇을 구현하고 어디서 시험했는가

[수식·조건·재현 프로토콜](MTE_OTF_PROTOCOL.md)에 정의를 남겼다. MTE는 RAFT 광류에서
카메라 움직임을 분리하고 공간별 방향 히스토그램과 짧은 구간의 큰 차이를 측정한다.
OTF는 SAM2 자동 분할과 DINOv2 특징으로 두 영상의 객체를 각각 찾고, 트랙을 일대일로
대응해 추가(HOR)·누락(OOR)·왜곡(ODR)을 계산한다. 지표 입력은 RGB다.
객체의 장거리 궤적이나 복잡한 사건의 의미를 직접 이해하는 모델까지 구현한 것은 아니다.

| 자료 | 개발 원본 | 미사용 평가 원본 | 전체 파생 사례 | 정답 범위 |
|---|---:|---:|---:|---|
| DAVIS 2017 공개 영상 | 8 | 16 | 384 | 코드로 삽입한 역순·정지·지연·구간 교환 |
| 새 절차적 합성 장면 | 8 | 16 | 792 | 위 변형과 객체별 움직임·추가·누락·모양 변경 |
| 합계 | 16 | 32 | 1,176 | 48개 원본에서 파생; 1,176개 독립 영상 실험이 아님 |

이전 2,432개 사례와 원본·seed를 분리했다. 개발 정상 자료에서 임계값을 정하고,
평가 점수를 본 뒤 수식·임계값·주 판정 기준을 바꾸지 않았다. 정식 점수 계산 전
카메라 회전 단위 검사에서 발견한 수정을 `protocol.json`의 `pre_score_amendment`에 남겼다.

DAVIS는 공식 train/val에서 각각 선택했다. JPEG 묶음의 매 3번째 프레임에 8 Hz를 부여한
최대 4초의 시험 재생 구간이다. 원 촬영 시간축이나 공개 영상 전체 길이의 평가가 아니다.
합성 개발/평가는 같은 렌더러·궤적 형식의 다른 seed이므로 미지의 장면 유형에 대한
일반화는 검증하지 않았다. 사전학습 모델이 DAVIS를 보지 않았다는 보장도 없다.

채택 기준은 오류 **각 종류**에 AUC ≥0.9, 검출률 ≥80%, 정상 오탐률 ≤10%, 측정률 ≥95%다.
통계는 도메인별 평가 원본 16개를 묶음으로 재추출하는 bootstrap 500회로 계산했다.
현재 평가 자료는 이제 사용한 자료이며, 후속 설계를 위한 새 독립 시험 자료로 재사용할 수 없다.

## MTE: 개선은 있지만 역순·순서 교환에 충분하지 않다

공개 영상에서 평가 오류 192개와 정상 대조군 64개를 모두 측정했다.

| 삽입 오류 | 검출률 | AUC | 12.5% 짧은 오류의 검출률 |
|---|---:|---:|---:|
| 구간 정지 | 91.7% | 0.957 | 81.2% |
| 지연 | 97.9% | 0.996 | 93.8% |
| 구간 역순 | 79.2% | 0.927 | 50.0% |
| 구간 순서 교환 | 75.0% | 0.924 | 43.8% |

| 공개 영상 비교 지표 | 오류 종류 평균 검출률 | 정상 오탐률 |
|---|---:|---:|
| MTE | 85.9% | 4.7% |
| 이전 후보 RTE | 25.5% | 3.1% |
| SSIM | 68.8% | 4.7% |
| LPIPS-Alex | 73.4% | 3.1% |
| tOF-RAFT-small | 48.4% | 0.0% |
| tOF-Farneback | 80.2% | 3.1% |
| tLP-Alex | 93.7% | 7.8% |

각 지표의 문턱은 자체 개발 정상 점수로 정했으므로 위 표가 동일 오탐률 비교는 아니다.
문턱에 의존하지 않는 원본별 AUC 차이도 비교했다. MTE−SSIM은 +0.062
(95% CI +0.015~+0.111), MTE−RTE는 +0.250 (+0.191~+0.294)였다.
반면 MTE−tOF-Farneback은 −0.033 (−0.079~−0.004), MTE−tLP-Alex는 −0.018
(−0.064~+0.013)이다. **시간축 기준선 전체에 대한 우위는 확인되지 않았다.**
tLP-Alex의 통과도 이번 공개 영상 통제 시험에 한정된다.

상위 구간 평균을 전체 평균으로 바꾸면 검출률은 85.9%에서 71.4%로 낮아졌지만
오탐률도 4.7%에서 1.6%로 낮아졌다. 원 제안의 방향 벡터 평균을 쓰면 검출률 85.4%,
오탐률 10.9%였다. 구성 요소의 효과를 기록하되 검출률 상승만으로 개선을 단정하지 않는다.

합성 움직임 시험에서는 평균 검출률 79.5%, 오탐률 6.25%였다. 정지·지연은 100%지만
객체 움직임 역전은 29.2%였다. 다만 이 항목에는 **시험 정답의 한계도 발견됐다.**
왕복 궤적의 대칭 구간을 역순으로 읽으면 실제 방향이 거의 바뀌지 않을 수 있다.
전체 72개 해당 사례 중 12개(개발 3, 평가 9)는 비교 가능한 실제 이동 방향이 반대인 전이가
0개였다. 따라서 29.2%를 순수한 방향 역전 검출 성능으로 해석하지 않는다.
[변형 정답 감사](../outputs/mte_otf_20260914_v1/reversal_truth_audit.json)에 기록했고
사후에 유리한 사례만 남겨 기존 판정을 바꾸지는 않았다.

오류 강도를 늘릴 때 점수가 함께 증가하는 경향은 있었다. 공개 역순·지연·순서 교환의
원본별 Spearman 상관 중앙값은 1.0이었다. 세 강도만 비교한 결과이며,
짧은 오류를 문턱 아래에서 놓치는 문제를 해결했다는 뜻은 아니다.

## OTF: 통합 점수와 자동 추적에서 병목을 확인했다

평가 합성 정상 대조군 96개와 객체 오류 144개를 모두 측정했다.
고정 주 임계값은 0.185185이며, 주 점수의 추가·누락·모양 변경 AUC는 각각
0.738, 1.000, 0.879였다. 누락 검출 100%만으로 채택할 수 없다.

보조 점수를 원래 의도한 오류 종류에 각각 적용한 결과도 확인했다.
아래는 **보조 분석**이며 주 점수의 실패 판정을 대체하지 않는다.

| 원래 의도한 보조 점수 | 대상 | 검출률 | 정상 오탐률 | AUC |
|---|---|---:|---:|---:|
| HOR | 객체 추가 | 33.3% | 0% | 0.996 |
| OOR | 객체 누락 | 97.9% | 0% | 1.000 |
| ODR | 모양 변경 | 100% | 0% | 1.000 |

ODR 자체는 이 합성 모양 변경에 잘 반응했다. 하지만 서로 다른 보조 점수를 하나의
최댓값으로 묶고 공통 문턱을 적용하면 작은 왜곡을 놓쳤다. HOR도 AUC는 높지만
정해진 정상 문턱에서 짧은 객체 추가를 충분히 잡지 못했다.

예를 들어 평가 원본 `renderer/260914900`에서 객체를 절반 구간에 추가했을 때,
추출기는 새 객체를 찾았지만 주 점수는 0.104로 문턱 0.185보다 낮았다.
전체 관측 수로 나누는 방식이 짧은 추가를 희석한 사례다.
반대로 12.5% 누락에서는 객체 트랙이 끊겨 OOR 0.247과 HOR 0.203이 함께 나왔다.
**누락을 검출했다고 오류 종류까지 정확히 구별한 것은 아니다.**

가장 가까운 추적 기준선인 IDF1도 같은 SAM2/DINO 예측 트랙으로 계산했다.
OTF와 IDF1의 원본별 AUC 차이는 **0.000, 95% CI [0.000, 0.000]**으로 이점이 없었다.
두 수식이 모든 상황에서 같다는 증명은 아니지만, 이번 시험에서 새 방식의 이득을 입증하지 못했다.
프레임별 마스크 F1에 대해서는 +0.080의 차이가 있었으며 CI는 [+0.056, +0.100]이었다.
[추적 기준선 비교](../outputs/mte_otf_20260914_v1/tracking_baseline_comparison.json)와
[종류별 보조 점수](../outputs/mte_otf_20260914_v1/typed_object_diagnostics.json)에 원 수치를 보존했다.

## 측정 도구 자체의 정확도와 실제 복원 진단

지표의 RGB 입력과 분리해, 원본에서 추출한 마스크를 기존 DAVIS 주석 및 렌더러 정답과
독립 비교했다. 여기의 비율은 **정답 객체-프레임 중 마스크 IoU ≥0.5로 찾은 비율**이다.
영상마다 점수 하나가 나오는 ‘측정률 100%’와 실제 객체를 정확히 찾는 비율은 다르다.

| 원본 자료 | 개발 | 평가 |
|---|---:|---:|
| DAVIS 주석 객체-프레임 검출 | 233/556 = 41.9% | 246/709 = 34.7% |
| 합성 정답 객체-프레임 검출 | 559/640 = 87.3% | 1,139/1,280 = 89.0% |

공개 영상에서 추출기가 상당수 주석 객체를 놓쳤다. OTF 점수를 실제 할루시네이션의
확정 판정으로 사용할 수 없는 이유다. DAVIS는 선택한 객체만 주석하므로 나머지 예측을
전부 오탐으로 세지는 않았다. 기존 DAVIS 주석은 사람이 만든 자료이며 이번에는 추가 검수하지 않았다.
공개 정상 대조군의 OTF 오탐률은 7.8%지만, 공개 영상 객체 오류의 검출률은 정답이 없어 미검증이다.

합성 원본의 실제 방향 전환 34건 중 현재 사건 추출기가 대응한 것은 1건뿐이었다
(평가 22건 중 1건). **MTE의 보조 사건 점수도 신뢰할 수준이 아니다.**
광류 전경 오차는 평가 원본 평균 약 1.81픽셀이었다. 객체별 방향을 합치는 사건 표현과
검출 규칙을 분리해 개선할 필요가 있다. 질감 정상 대조군 48개는 코드상 마스크·궤적이
정확히 유지됨을 확인했다. 색·질감 자체가 의미인 다른 과제까지 정상이라는 주장은 하지 않는다.

기존 LGVSC·SGD-JSCC 복원 **6쌍**에도 두 지표를 실행했다. ETRI 보행 영상의 두 모델,
Kinetics·WebVid 짧은 구간의 두 모델이다. 새 복원 모델 실행을 추가한 것은 아니다.
원본·복원 FPS에 따라 8 Hz를 요청하고 가장 가까운 실제 프레임을 대응했다.
ETRI는 각 80개, Kinetics는 각 6개, WebVid는 각 3개 시점을 측정했으며
원본·복원 간 최대 시점 차이는 16.7 ms였다. 중복 프레임 제거·내용 기반 시간 재정렬은 하지 않았다.
표본 수집률은 모두 100%였지만 짧은 구간은 특히 사건 판단에 부족하다.
이 복원 쌍에는 의미 정답이 없고 전송 조건도 일치시키지 않았으므로 모델 우열을 판정하지 않는다.

## 검증 기록과 후속 판단

- 전체 자동 테스트 **50개 통과**. 반대 방향 상쇄, 카메라 회전, 빈 객체, 짧은 누락,
  트랙 분절, 실제 시점 대응의 지연·꼬리 누락 보존 등을 검사했다.
- MTE/기존 지표 1,176건, OTF 456건 계산 완료. 실행 실패 및 주 점수 null 사례 0건.
  가중치·코드·사례 출처 해시, 점수 범위, 동일 영상 점수 불변 조건을 확인했다.
- 고정 개발 사례 하나를 매번 빈 캐시에서 두 번 계산했다. MTE 숫자 94개,
  OTF 숫자 33개의 최대 차이는 모두 0이었다. 독립 복원 seed 반복 검증은 아니다.
- GPU 본 계산 시간은 MTE/기존 지표 약 19.2분, OTF 약 31.1분이었다.
  자료 확보·환경 준비·감사·실제 복원 진단 시간을 포함한 전체 작업 시간은 아니다.
- NVIDIA 커널/사용자 라이브러리 불일치는 해당 프로세스에만 호환 라이브러리를 연결해
  우회했다. 전역 드라이버 불일치는 남아 있으며, 재현 시 프로토콜의 실행 환경을 사용한다.

선행 연구와 수식의 겹침은 [프로토콜의 비교표](MTE_OTF_PROTOCOL.md)에 정리했다.
광류 방향 히스토그램, 전역 트랙 대응 F1, SAM/DINO 기반 객체 비교 자체는 기존 요소다.
이번 결과는 이 조합을 논문 기여로 확정할 성능·차별성 근거를 제공하지 못했다.
**ETRI 1단계는 아직 완료가 아니다.** 다음 설계는 실제 방향 변화가 보장되는 오류 생성,
객체별 사건 표현, 추출·추적 실패와 실제 추가·누락을 구분하는 방식부터 다뤄야 한다.
사용한 평가 자료에서 문턱만 조정해 통과시키는 방식으로 진행하지 않는다.

기본 재현은 [프로토콜](MTE_OTF_PROTOCOL.md)의 명령을 따른다. 추가 감사·진단은
저장된 `real_pairs.json`을 사용해 다음과 같이 실행했다. 저장된 결과를 보려면 재실행할 필요는 없다.

```bash
export PYTHONNOUSERSITE=1
export PYTHONPATH="$PWD/src"
export LD_LIBRARY_PATH="$PWD/.local/metric_v2_driver/extracted/usr/lib/x86_64-linux-gnu"
metric_motion_python=/home/sangukbae/anaconda3/envs/lgvsc/bin/python
metric_object_python="$PWD/.local/metric_v2_env/bin/python"
metric_run=outputs/mte_otf_20260914_v1
"$metric_motion_python" scripts/add_metric_v2_tracking_baselines.py --output "$metric_run"
"$metric_motion_python" scripts/analyze_metric_v2_diagnostics.py --output "$metric_run"
"$metric_motion_python" scripts/audit_metric_v2_extractors.py --output "$metric_run" --stage motion
"$metric_object_python" scripts/audit_metric_v2_extractors.py --output "$metric_run" --stage object --cached-only
"$metric_motion_python" scripts/evaluate_metric_v2_pairs.py motion --pairs "$metric_run/real_pairs.json" --output "$metric_run/real_motion_scores.json"
"$metric_object_python" scripts/evaluate_metric_v2_pairs.py object --pairs "$metric_run/real_pairs.json" --output "$metric_run/real_object_scores.json"
"$metric_motion_python" scripts/repeat_metric_v2.py --output "$metric_run" --stage motion
"$metric_object_python" scripts/repeat_metric_v2.py --output "$metric_run" --stage object
"$metric_motion_python" scripts/verify_metric_v2_run.py --output "$metric_run" --complete
```
