# ERE·STA: 사람의 추가 검수 없는 3차 지표 실험

2026-09-14. [1차 RTE·LSSD](AUTOMATIC_METRIC_PROTOCOL.md)와
[2차 MTE·OTF](MTE_OTF_PROTOCOL.md)의 **실패 원인을 분석해 만든 3차 후보의 설계 고정 문서**다.
이 문서는 점수를 계산하기 전에 데이터·수식·관문·채택 기준을 고정한다.
**2026-09-14 1회차는 사건 추출 관문 미달이었다. v3.1 수정 후 새 폴더의 합성 개발 재감사에서는
필수 관문이 통과했다. 이후 개발 문턱을 고정해 별도 폴더에서 본 성능·영상 귀착 평가를 완료했으며,
ERE와 STA의 주 채택 기준은 모두 미달했다.** STA 특징의 보조 분류 결과와 정상 외형 변화 오탐은
주 판정과 구분해 보고한다.
[본 평가 결과와 분석](ERE_STA_FORMAL_RESULTS.md), [추가 실행 정의](ERE_STA_FORMAL_EXECUTION.md),
[재감사 결과·분석](ERE_STA_REAUDIT_RESULTS.md), [1회차 기록](ERE_STA_RESULTS.md),
[실행 전 해석·보완 기록](ERE_STA_EXECUTION_NOTES.md)을 참고한다.
고정 당시 원문과 코드 사본은 실행 폴더에 보존했다. 구현 자체를 연구 성공으로 간주하지 않으며,
성능과 신규성은 실험과 선행 연구 비교로만 판단한다.

**2026-09-14 개정(v3.1): 1회차의 개발 자료 관문 결과를 근거로 §3의 사건 정의와 §4.1의 근거 판정
규칙을 고쳤다. 이 개정 당시 평가 원본의 후보 점수는 0건이었으며, 채택 문턱(§7.2)과 필수 관문 기준(≥0.8)은
바꾸지 않았다. 개정 내역은 §0.1과 [수정 기록](ERE_STA_EXECUTION_AMENDMENTS.json)에 있다.**

2차의 MTE·OTF 결과와 자료는 기준선으로 보존한다. 이 실험은 그것을 대체하지 않고,
**MTE·OTF를 사전 등록 비교 대상에 포함**한다.

## 0. 2차 실패 원인과 이번 대응

| 2차에서 확인된 원인 | 근거 | 이번 프로토콜의 대응 |

| 이질적 보조 점수를 `max()`로 통합 | 종류별 점수는 AUC 0.996~1.000인데 통합 주 점수는 추가 0% | **통합 점수를 만들지 않고** 오류 종류별 점수를 사전 등록 (§5) |

| 기존 지표와 같은 것을 잼 | OTF−IDF1 AUC 차이 0.000, CI [0,0] | STA는 기존 지표가 **입력조차 갖지 않는** 대상을 측정 (§4) |

### 왜 정상군 변경이 핵심인가

1·2차의 삽입 오류는 모두 같은 픽셀의 시간 재배열이거나 합성 장면의 객체 편집이고,
정상군은 밝기·gamma·JPEG처럼 픽셀이 거의 같은 변형이었다. 이 구성에서는 광류·픽셀
차이가 사실상 충분통계량이므로 의미 지표가 이길 구조가 아니다.

반면 실제 LGVSC 복원은 픽셀이 크게 다르면서 의미는 대체로 보존된다(01번 영상 PSNR 19.7 dB).
따라서 **"픽셀은 크게 다르지만 사건은 같은" 사례를 정상군에 넣어야** 의미 지표의 존재 이유를
시험할 수 있다. 이것이 3차의 가장 중요한 변경이다.

### 0.1 1회차 관문 결과와 이번 개정 (2026-09-14)

1회차 실행([결과](ERE_STA_RESULTS.md))은 **사건 추출 관문 미달**로 본 실험을 실행하지 않았다.
평가 원본의 후보 점수는 0건이며, 아래 개정은 **개발 자료의 관문 결과만 보고** 이뤄졌다.
§6이 관문 통과 전 수식 수정을 허용하는 구간에 해당한다.

| 1회차에서 확인된 문제 | 근거 | 이번 개정 |
|---|---|---|
| 정지한 객체의 존재를 유지할 경로가 없음 | `start→enter` 31건, `stop→exit` 15건 | §3을 존재·움직임 **2채널**로 분리 |
| 방향 전환 자체의 검출 실패 | 방향 전환 8/16, 퇴장 1/16. 종류를 무시하면 68/96 | §3에 방향 전환 매개변수 재선정을 명시 |
| 공개 영상의 존재 추출 불가 | 공개 객체-프레임 재현율 20.3% | 공개 영상 ERE를 **진단 전용**으로 사전 선언 |
| 키프레임 시각만으로 근거를 인정 | `corrupt_keyframe_retained`에서 CLR=0, GFR=1 | §4.1을 **내용 의존** 규칙으로 변경 |

**ERE·SER와 EDR·CLR·GFR·GHR의 수식은 바꾸지 않았다.** 바뀐 것은 사건을 관측하는 방식과
근거를 판정하는 규칙이다. 문턱을 낮추거나 `start`/`enter`, `stop`/`exit`를 같은 사건으로
병합해 통과시키는 방식은 쓰지 않는다.

개발 자료를 반복 사용하면 추출기가 개발 자료에 과적합될 수 있다. 재감사 횟수와 각 회차의
수치를 수정 기록에 남기고, **평가 원본은 필수 관문을 통과할 때까지 후보·학습 모델 입력이나
매개변수 선택에 사용하지 않는다.** 자료 무결성·정답 적격성 검사에는 읽는다.

## 1. 이번에 제안하는 두 지표

| 지표 | 대상 | 성격 |
|---|---|---|
| **ERE** (Event Reproduction Error) | E1: 동작·방향·사건 순서 | 외형 불변 사건 열 비교. 분모는 사건 개수 |
| **STA** (Semantic Transmission Attribution) | E2·E4 | 의미 오류를 송신 누락·채널 손실·생성 오류로 귀착 |

객체 존재·모양은 **새 수식을 만들지 않는다.** 2차의 종류별 점수 OOR·HOR·ODR을
사전 등록해 그대로 쓴다(§5). 2차 결과가 이 점수들의 유효성을 이미 보여줬고,
실패는 통합 방식에 있었기 때문이다.

## 2. 데이터와 정답

### 2.1 원본

- 1차 2,432건, 2차 1,176건의 원본·seed는 재사용하지 않는다. `prepare`가 이전
  `protocol.json` 두 개를 읽어 source ID와 seed 중복을 거부한다.
- **공개 영상:** DAVIS 2017 TrainVal 480p. 이름 해시 salt는 `metric-v3-20260914/`이며
  2차에서 쓴 24개 시퀀스를 제외한다. train 잔여에서 개발 8개, val 잔여 **14개**를 평가로 쓴다.
  val 30개 중 16개를 2차가 썼으므로 평가 원본이 14개로 줄어든다. 이 감소를 그대로 보고한다.
  매 3번째 프레임 최대 32장, 8 Hz 시험 재생 시간축이다. 원 촬영 시간이 아니다.
- **합성 장면:** 새 렌더러 `metric_v3_cases.py`. 개발 seed 260915100–115(16개),
  평가 seed 260915900–931(32개). 각 32프레임, 320×192, 8 fps.
  **장면마다 사건이 4개 이상 발생하도록 궤적을 구성한다**(이동 시작, 방향 전환,
  정지, 객체 등장·소멸). 사건이 2개 미만인 장면은 생성 단계에서 거부한다.
- 합성 개발/평가는 같은 렌더러의 다른 seed다. 미지의 장면 유형에 대한 일반화는 검증하지 않는다.
  사전학습 모델이 DAVIS를 보지 않았다는 보장도 없다.

### 2.2 정상 대조군: 의미 보존 재렌더링 (핵심 변경)

**합성 장면 (엄밀한 정상군).** 렌더러가 같은 궤적·같은 사건을 유지한 채 외형만 바꾼다.

| 정상군 | 바뀌는 것 | 유지되는 것 |
|---|---|---|
| `restyle_texture` | 배경·객체 질감 주파수와 진폭 | 마스크, 궤적, 사건 |
| `restyle_palette` | 객체·배경 색상(hue) 회전 | 마스크, 궤적, 사건 |
| `restyle_lighting` | 조명 기울기와 전역 밝기 | 마스크, 궤적, 사건 |
| `restyle_camera` | 작은 전역 이동·회전(카메라 흔들림 위상) | 객체의 장면 내 상대 궤적, 사건 |
| `restyle_instance` | 객체 외곽 스타일(모서리 둥글기 등), 마스크 IoU ≥0.7·종횡비 변화 ≤10% | 사건, 존재 구간, 대략적 크기 |
| `restyle_gait` | 사건에 영향을 주지 않는 미세 위치 흔들림 | 사건 시각·방향 |

- 기존 `identity`, `brightness20`, `gamma075`, `jpeg75`도 유지한다.
- `restyle_instance`의 허용 범위(IoU ≥0.7, 종횡비 ≤10%)는 오류 변형 `object_shape`
  (종횡비 2배 이상 변형)와 **수치로 분리**해 사전 고정한다.

**공개 영상 (근사 정상군).** 실제 영상은 같은 사건으로 다시 렌더링할 수 없다.
따라서 기하와 사건을 유지하면서 픽셀을 크게 바꾸는 변형만 쓴다:
`hue_rotate`, `grayscale`, `jpeg20`, `downscale_half_upsample`.
**이것은 재합성의 근사이며 생성 모델의 재생성과 같다고 주장하지 않는다.**
SDEdit 등 생성 모델은 의미 보존이 보장되지 않으므로 정답 생성에 쓰지 않는다.
따라서 §7의 주 주장은 합성 자료에서 하고, 공개 영상은 보조 근거로 보고한다.

### 2.3 오류 변형과 정답 검증 관문

**시간 오류(공개·합성 공통):** `reverse`, `freeze`, `lag`, `swap`.
**합성 전용:** `motion_reverse`, `motion_freeze`, `object_addition`, `object_omission`, `object_shape`.
오류 구간 비율은 12.5%, 25%, 50%이다.

**정답 검증 관문(신규).** 모든 오류 사례는 채점 대상이 되기 전에 다음을 통과해야 한다.

- 합성: 렌더러 정답 궤적·마스크에서 **원본과 변형의 사건 열을 각각 계산**한다.
  사건 종류·시각(>0.25초)·방향(>45°) 중 하나 이상이 달라야 오류 사례로 채택한다.
- 공개: DAVIS 기존 마스크의 무게중심 궤적에서 같은 규칙으로 사건 열을 계산해 비교한다.
  기존 주석은 사람이 만든 자료이며 이번에 추가 검수하지 않는다. 이 사건 열은
  **정답 검증과 추출기 감사에만 쓰고 지표 입력으로는 쓰지 않는다.**
- 정상군은 반대로 **사건 열과 객체 존재 구간이 완전히 같아야** 채택한다.
- 탈락한 사례 수와 사유를 `truth_audit.json`에 남긴다. 2차에서 사후에 발견한
  왕복 궤적 문제(72건 중 12건 방향 변화 0)를 사전에 제거하기 위한 장치다.

### 2.4 지표 입력

지표에는 RGB 프레임만 넣는다. 변형 종류, 위치, 렌더러 마스크, 주석은 넣지 않는다.
STA만 예외적으로 **송수신된 의미 표현**을 추가 입력으로 받는다(§4). 원본 정답은 받지 않는다.

## 3. ERE 정의 (2026-09-14 개정)

`event_metric.py`. **존재 채널과 움직임 채널을 분리한다.** 1회차의 광류 단일 채널은
정지한 객체의 존재를 유지할 수 없어 `start`를 `enter`로, `stop`을 `exit`로 기록했다(§0.1).
움직임 영역의 생성·소멸은 객체의 등장·소멸이 아니다.

1. **존재 채널:** 프레임별 자동 분할과 외형 특징으로 객체를 찾아 트랙으로 연결한다.
   `object_metric.py`의 SAM2.1 Hiera-tiny + DINOv2 ViT-S/14 추출·연결 규칙을 그대로 쓴다.
   1회차 합성 개발 객체-프레임 재현율은 98.6%로 필수 관문을 통과했다.
2. **움직임 채널:** RAFT-small 광류에서 RANSAC similarity affine 카메라 성분을 뺀다.
   inlier <50%이면 카메라 0으로 두고 추정 실패율을 기록한다.
3. **트랙별 운동 상태:** 존재 트랙의 마스크 안에서 잔여 광류의 평균을 그 트랙의 속도로 쓴다.
   **정지한 객체도 존재 트랙이 유지되므로 속도 0인 상태가 정의된다.** 1회차와의 핵심 차이다.
4. **궤적 평활화:** 카메라 이동을 보정한 트랙 무게중심을 이동평균으로 평활화한 뒤 속도를 구한다.
   초기 진단 기준은 5프레임이며 §3.8의 개발 진단으로 **7프레임**을 선정했다.
   가장자리에서는 이용 가능한 표본만 평균한다.
5. **사건 정의:** 트랙마다 다음을 뽑고 객체별 최소 간격 0.375초를 적용한다.
   - `enter`/`exit`: **존재 트랙의 생성·소멸**(클립 경계 제외)
   - `start`/`stop`: **존재가 유지되는 트랙의 운동 상태 전이**(최소 속도 경계를 넘는 변화)
   - `turn`: 존재가 유지되고 움직이는 트랙의 방향 전환
6. **사건 기술자:** `s_e = (종류, 진행 방향 8분면, 속도 3등급, 무게중심 3×3 격자 칸)`.
   색·질감·텍스처는 포함하지 않는다. 이것이 재렌더링 정상군에 대한 불변성의 근거다.
7. **사건 대응:** 종류가 같고 `|Δt| ≤ 0.25초`, 방향 차 ≤45°, 격자 칸 Chebyshev 거리 ≤1인
   쌍만 허용해 Hungarian으로 일대일 대응한다. 시간 정렬·워핑은 하지 않는다.
8. **방향 전환 매개변수 재선정:** 1회차 방향 전환 재현율 8/16은 존재·움직임 혼동으로
   설명되지 않는 **별도의 실패**다. 평활 구간, 최소 속도, 전후 각도 조건 중 무엇이 원인인지
   **개발 자료에서만** 확인하고, 선정값과 근거를 재감사 전에 기록한다. 평가 원본은 쓰지 않는다.

v3.1 실행값은 **평활 7프레임·최소 속도 0.25 px/frame·전환 각도 >150°·전후 각 2프레임**이다.
54개 개발 설정의 비교와 재감사 전 등록 수치는 [수정 기록](ERE_STA_EXECUTION_AMENDMENTS.json)의
3회차, 재감사 결과는 4회차에 있다. 두 채널 기본 설정도 전환 16/16이었으므로 이 개선 전체를
매개변수 조정 효과로 해석하지 않는다. 실행 당시 문서·수치는 새 출력 폴더에 고정 보존했다.

```
ERE = 1 − |대응된 A의 사건| / |A의 사건|     원본 사건 중 재현되지 않은 비율
SER = |대응 안 된 B의 사건| / |B의 사건|      복원에만 있는 사건의 비율
```

- 두 값을 **합치지 않는다.** 각각 자기 대상 오류에 대해 따로 문턱을 받는다(§5).
- `|A의 사건| < 2`이면 `ERE = null`이며 측정률에 기록한다. 정지 장면은 측정 대상이 아니다.
- **공개 영상의 ERE는 진단 전용으로 사전 선언한다.** 개정된 §3은 존재 채널에 의존하는데
  1회차 공개 객체-프레임 재현율이 20.3%였기 때문이다. 주 결과는 합성 자료로 한정하고,
  공개 영상에서는 사건 추출 정확도와 함께 참고 수치로만 보고한다. 이 축소를 그대로 기록한다.
- 부산물로 미대응 사건의 시각과 격자 위치를 `error_intervals`로 출력한다.
  3단계의 구간 재생성 제어에 쓸 수 있으나, 이번 실험에서 그 효과를 주장하지 않는다.
- 분모가 사건 개수이므로 12.5% 길이의 오류라도 사건 하나가 깨지면 `1/|E_A|` 이상이 된다.
  희석 문제를 수식 수준에서 제거한 것이며, 실제 민감도는 실험 대상이다.

## 4. STA 정의

`attribution_metric.py`. 기존 지표가 갖지 않는 제3의 입력인 **실제로 송수신된 의미 표현**을 쓴다.

이 패키지는 이미 송수신 경계에서 그 자료를 저장한다:
`receiver/metadata.csv`(수신 캡션·flow), `receiver/decoder_inputs.json`(수신 키프레임 인덱스),
`receiver/frames/sample/key_frames_received/*.png`(수신 키프레임).
`codec_transport.py::receive`는 원본 픽셀을 읽지 않는다.

### 4.1 근거 판정

의미 단위 `u`는 §3의 사건 또는 객체 트랙이다. 각 `u`에 대해 세 값을 구한다.

```
supp_TX(u)  송신된 표현에 u의 근거가 있는가
supp_RX(u)  수신된 표현에 u의 근거가 있는가
repro(u)    복원 영상이 u를 재현했는가        (ERE 또는 OOR/HOR의 대응 판정)
```

근거 판정 규칙을 사전 고정한다. **키프레임의 존재만으로 근거를 인정하지 않는다(2026-09-14 개정).**
1회차 반례에서 키프레임 내용이 손상돼도 시각이 남으면 근거가 있다고 판정해,
채널 오류를 생성 실패로 귀착했다(§0.1).

- 사건 `u`(시각 `t`): 다음 중 하나를 만족해야 `supp = 1`이다.
  - `|t_keyframe − t| ≤ 0.25초`인 키프레임이 있고, **그 키프레임에서 읽어낸 상태가 `u`의 상태와
    일치**한다. 일치 조건은 사건 대응과 같은 허용치(종류 동일, 방향 차 ≤45°, 격자 거리 ≤1)를 쓴다.
  - `t`를 포함하는 구간의 캡션이 해당 사건 종류와 방향 어휘를 포함한다.
- 객체 `u`: 수신 키프레임에서 해당 객체 토큰이 **실제로 복구**되거나, 캡션이 그 토큰을 포함한다.
- **복호 불가 처리:** 패킷 손실, 검사합 실패, 추출 실패로 내용을 읽을 수 없는 키프레임은
  근거로 세지 않는다. 이로써 패킷 손실과 내용 손상이 **모두 CLR에 나타난다.**
- 표현에서 상태를 읽을 때 원본 정답을 쓰지 않는다. 합성 실험에서는 수신된(훼손된) 키프레임
  픽셀에 §3의 추출기를 적용하고, 실제 복원에서도 같은 추출기와 문자열 대조를 쓴다.
- 합성 자료의 캡션 어휘는 고정 어휘로 판정한다. 실제 복원의 판정은 근사이므로 진단으로만 보고한다.

### 4.2 점수

```
EDR = |{u : supp_TX(u)=0}| / |U|                        송신단 누락률
CLR = |{u : supp_TX=1, supp_RX=0}| / |{u : supp_TX=1}|   채널 손실률
GFR = |{u : supp_RX=1, repro(u)=0}| / |{u : supp_RX=1}|  생성 실패율
GHR = |{v ∈ B : supp_RX(v)=0 이고 v ∉ A}| / |B|          근거 없는 생성률
```

- 네 값을 **가중합하지 않고 벡터로** 보고한다.
- 각 값이 서로 다른 단계를 가리킨다. GFR만 수신단이 고칠 수 있고, EDR은 2·4단계 대상이다.
- GHR은 "수신 정보에 근거가 없는데 생성된 것"이므로 E2의 할루시네이션 정의와 일치한다.
- `|U| = 0` 또는 분모가 0이면 해당 값은 `null`이며 측정률에 기록한다.

### 4.3 귀착 검증 방법

전송 표현을 코드로 훼손하고, 지표가 원인을 맞히는지 본다. 귀착 정답은 조작으로 정의된다.

| 조작 | 정답 귀착 | 오귀착 판정 |
|---|---|---|
| 사건 구간의 키프레임 제거 + 캡션 구절 삭제 | EDR | GFR·CLR이 대신 오르면 오귀착 |
| 채널 비트 손상·패킷 손실 | CLR | |
| 표현은 온전한데 복원에서 사건 누락 | GFR | |
| 표현에 없는 객체를 복원에 추가 | GHR | |

- 복원 영상은 **표현으로부터 다시 렌더링한 모의 복원**이다. 이 실험은 **지표의 귀착 논리를
  검증**하는 것이지 어떤 디코더의 성능을 평가하는 것이 아니다. 이 구분을 결과 문서에도 남긴다.
- 실제 LGVSC·SGD 복원 쌍에는 의미 정답이 없으므로 진단으로만 계산한다.
- **규칙 단위 검사(필수).** 1회차의 여섯 가지 규칙 사례를 개정 규칙으로 다시 계산한다.
  특히 `corrupt_keyframe_retained`는 **CLR=1이고 GFR은 0 또는 null**이어야 한다.
  여섯 사례가 모두 기대값과 일치하지 않으면 STA 실험을 진행하지 않는다.

## 5. 오류 종류별 점수 사전 등록

2차의 `max(1−OTF-F1, ODR)` 같은 통합 점수를 만들지 않는다. 대신 아래 대응을
**점수 계산 전에** 고정하고, 각 점수는 자기 대상에서만 채택 판정을 받는다.

| 오류 종류 | 주 점수 | 근거 |
|---|---|---|
| reverse, freeze, swap, lag | ERE | §3 |
| motion_reverse, motion_freeze | ERE | §3 |
| 가짜 사건 생성 | SER | §3 |
| object_omission | OOR | 2차 실측 검출률 97.9%, AUC 1.000 |
| object_addition | HOR | 2차 실측 AUC 0.996 |
| object_shape | ODR | 2차 실측 검출률 100%, AUC 1.000 |
| 귀착 4종 | EDR·CLR·GFR·GHR | §4.3 |

각 점수의 문턱은 자기 도메인 개발 정상군의 95백분위(`higher`)로 따로 정한다.
오탐률은 재렌더링 정상군을 포함한 **모든 정상군**에서 측정한다.

## 6. 사전 관문 (점수 계산 전)

아래를 통과하지 못하면 지표 점수를 계산하지 않는다. 통과 전에는 수식 수정이 허용되며,
수정 내역과 그 시점의 `scores_observed = 0`을 `pre_score_amendment`에 기록한다.

| 관문 | 기준 | 2차 실측 | 3차 1회차 실측 | v3.1 재감사 |
|---|---|---|---|---|
| 존재 트랙 객체-프레임 재현율 (합성 개발) | ≥0.8 | 87.3% | 98.6% 통과 | **98.6% 통과** |
| 사건 추출 재현율 (합성 개발) | ≥0.8 | 2.9% | 15.6% 미달 | **95.8% 통과** |
| 사건 추출 정밀도 (합성 개발) | ≥0.8 | 미측정 | 15.0% 미달 | **92.0% 통과** |
| 방향 전환 종류별 재현율 (합성 개발) | ≥0.8 | 미측정 | 8/16 = 50% 미달 | **16/16 통과** |
| STA 규칙 단위 검사 6건 | 전부 기대값 일치 | 해당 없음 | 1건 불일치 | **6/6 일치** |
| 객체-프레임 재현율 (공개 개발) | 진단 전용, 참고 기준 0.8 | 41.9% | 20.3% | 20.3% |
| 정답 검증 통과율 | 기록 후 진행 | 2차 사후 발견 | 2,216건 중 2,211건 채택 | 동일 |

- **공개 영상 객체 검출률은 1·2차 실측 모두 기준 미달이다.** 따라서 공개 영상의 객체 점수
  (OOR·HOR·ODR)와 개정된 ERE는 **사전에 진단 전용으로 선언**한다. 주 결과는 합성 자료다.
- 방향 전환 재현율을 별도 관문으로 추가했다. 전체 사건 재현율이 통과해도 E1의 핵심인
  방향 전환이 낮으면 ERE의 목적을 달성하지 못하기 때문이다.
- 사건 추출 관문을 통과하지 못하면 ERE 실험을 중단하고 추출기부터 고친다.
  2차처럼 추출기가 깨진 상태로 수식을 채점하지 않는다.
- 관문 재감사는 개발 자료에서만 하고, **회차마다 수치를 수정 기록에 남긴다.**
  평가 원본은 필수 관문 통과 전까지 후보·학습 모델 입력이나 매개변수 선택에 사용하지 않는다.

## 7. 비교와 채택

### 7.1 비교 대상 (사전 등록)

같은 픽셀·같은 시점에서 계산한다: PSNR, SSIM, LPIPS-Alex, CLIP cosine, RTE, LSSD,
tLP-Alex, tOF-Farneback, tOF-RAFT, **MTE(`mte_tail`), OTF(`otf_error`, OOR/HOR/ODR), IDF1**.
ERE 비교에는 프레임별 tOF·tLP 곡선을 문턱으로 잘라 구간 검출로 바꾼 기준선도 포함한다.
영상 단위 평균과만 비교하면 불공정하기 때문이다.

STA에는 귀착을 계산하는 기존 지표가 없다. 대신 위 지표들에게 같은 귀착 라벨 예측 과제를
부여한다. 4분류이므로 **우연 수준은 0.25**이며, 이것이 비교 기준선이다.

### 7.2 채택 기준

- 오류 종류마다 AUC ≥0.9, 검출률 ≥0.8, 정상 오탐률 ≤0.1, 측정률 ≥0.95.
- STA: 귀착 정확도 ≥0.8, 각 성분의 대상 조작 AUC ≥0.9, 무훼손 사례 오탐률 ≤0.1.
- 우위 주장은 동일 원본 쌍 bootstrap(500회, 원본 단위 재추출) AUC 차이의 95% CI가
  **모든 사전 등록 비교 지표**에 대해 0보다 클 때만 허용한다.
- **도메인을 나눠 보고한다.** 합성 재렌더링 영역과 기존 픽셀 재배열 영역을 분리하며,
  새 지표는 새 영역에서 이기면서 기존 영역에서 지지 않아야 한다.
- 관문 통과와 신규성은 별개다. 기존 기술 조합이 주 구성이면 실용 진단 도구로만 보고한다.
- 평가 결과를 본 뒤 수식·문턱·주 점수 대응을 바꾸지 않는다. 바꾸면 새 원본·새 seed가 필요하다.

## 8. 선행 연구와 겹치는 부분

| 연구 | 이미 있는 요소 | 이번 후보가 입증해야 할 부분 |
|---|---|---|
| [TecoGAN tOF·tLP](https://github.com/thunil/TecoGAN/blob/master/metrics.py) | 광류·지각 시간 차이 | 재렌더링 정상군에서의 오탐 차이 |
| [HOF / Laptev et al., CVPR 2008](https://www.di.ens.fr/~laptev/actions/) | 광류 방향 히스토그램 | ERE는 히스토그램이 아닌 트랙 사건 열을 쓴다는 점의 실익 |
| Temporal action detection (tIoU 기반 mAP) | 사건 단위 시간 대응 채점 | 자동 추출한 원본 사건을 기준으로 삼는 구성의 타당성 |
| [HOTA](https://arxiv.org/abs/2009.07736), [IDF1](https://arxiv.org/abs/1609.01775) | 검출·연결 분리, 전역 대응 F1 | 2차에서 OTF−IDF1 = 0.000이었다. 객체 쪽은 신규성을 주장하지 않고 종류별 점수로만 사용 |
| [InterDyn](https://interdyn.is.tue.mpg.de/media/upload/interdyn_video.pdf) | 원본-생성 객체 움직임 비교 | 짧은 오류·외형 변화에 대한 추가 이점 |
| [VBench](https://arxiv.org/abs/2311.17982) | 생성 영상 품질 분해 | 원본 대비 비교와 추출 오류 분석 |
| RAG 평가 (context recall 대 faithfulness) | **검색 실패와 생성 실패의 분리** | STA의 착상과 가장 가까운 선행. 영상·물리 채널·전송 표현으로의 전이와 훼손 실험 검증이 새로운 부분 |
| 고전 JSCC의 source/channel 왜곡 분해 | 단계별 왜곡 분해 | 의미 단위 수준의 귀착과 자동 검증 절차 |

STA의 착상이 RAG 평가와 겹친다는 점을 먼저 밝힌다. 신규성 주장은
**생성형 영상 의미 통신에서 실제 송수신 표현을 제3 입력으로 삼아 의미 오류를 세 단계로
귀착시키고, 표현 훼손 실험으로 그 귀착을 검증하는 평가 체계**에 한정한다.

- 공개 영상 22개(개발 8·평가 14), 합성 48개의 시험 규모다. 2차와 같은 pilot 규모다.
- 공개 영상에는 엄밀한 의미 보존 재렌더링을 만들 수 없다. 근사 정상군의 한계를 명시한다.
- 합성 개발/평가는 같은 렌더러의 다른 seed다. 장면 유형 일반화는 검증하지 않는다.
- STA의 귀착 검증은 모의 복원을 쓴다. 실제 디코더의 성능 평가가 아니다.
- 근거 판정 규칙은 명시적 언급만 본다. 키프레임이 사건을 암묵적으로 시사하는 경우를
  다루지 못하므로, EDR이 과대평가될 수 있다.
- RAFT·SAM2·DINOv2는 정답이 아니라 측정 도구다. 도구 오차를 §6에서 따로 측정해 보고한다.
- 실제 LGVSC·SGD 복원에는 의미 정답이 없으므로 모델 우열을 판정하지 않는다.
- 개정된 ERE는 SAM2/DINOv2 존재 채널에 의존한다. 1회차에 "지표 1은 분할 모델을 쓰지 않는다"고
  둔 설계상의 장점은 사라졌고, 공개 영상에서는 ERE를 주 결과로 쓸 수 없다.
- 이번 개정은 **개발 자료의 관문 결과를 본 뒤** 이뤄졌다. 평가 원본 점수는 0건이므로 평가
  자료는 그대로 유지하지만, 개발 자료 반복 사용에 따른 과적합 위험은 남는다.
- STA의 개정된 근거 규칙도 표현에서 상태를 읽을 수 있는 범위까지만 판정한다.
  귀착 결과를 실제 인과적 고장 위치의 증명으로 해석하지 않는다.

## 10. 재현

`metric_v3_validation.py`의 자료 준비·정답 감사·개발 추출기 감사를 구현했다.
전체 계획의 단계 순서는 다음과 같으며, **본 평가 `event`·`object`·`attribution` 실행기는 아직
추가 구현이 필요하다.** 현재 이 세 명령은 관문을 검사한 뒤 미구현 상태로 종료한다.
`prepare`가 코드·가중치·원본·픽셀 해시와 이 프로토콜을 고정하고, 이전 두 실험의
`protocol.json`을 읽어 원본·seed 중복을 거부한다. 고정 대상 파일은
`event_metric.py`, `attribution_metric.py`, `metric_v3_cases.py`, `metric_v3_validation.py`,
`object_metric.py`, `motion_metric.py`, `automatic_metrics.py`, `temporal_baselines.py`,
`tracking_baselines.py`, `automatic_validation.py`이다.

```text
prepare → truth_audit → extractor_gate → event → object → attribution → summarize
```

환경은 2차와 같이 나눈다. 광류·귀착 단계는 `lgvsc` 환경, SAM2/DINOv2를 쓰는 객체 단계와
**개정으로 존재 채널을 쓰게 된 `event` 단계**는
`.local/metric_v2_env`를 쓴다. 시스템 드라이버는 교체하지 않고 프로세스 `LD_LIBRARY_PATH`로만
호환 라이브러리를 연결한다.

```bash
# 먼저 개발 진단을 완료한다. 전체 반복 명령은 ERE_STA_REAUDIT_RESULTS.md에 있다.
bash scripts/run_metric_v3.sh prepare outputs/ere_sta_new \
  --reuse-inputs outputs/ere_sta_20260914_v1 \
  --diagnostics outputs/ere_sta_v31_development/diagnostics.json
bash scripts/run_metric_v3.sh truth_audit outputs/ere_sta_new
bash scripts/run_metric_v3.sh extractor_gate outputs/ere_sta_new
bash scripts/run_metric_v3.sh summarize outputs/ere_sta_new
```

같은 원본·seed로 다시 실행한 결과는 반복 검증이지 새 독립 시험이 아니다.
`outputs/`, `data/`, `.local/`은 로컬 산출물이며 Git 추적 대상이 아니다.

**개정 후 실행(2026-09-14).** §3과 §4.1이 바뀌어 `event_metric.py`와 `attribution_metric.py`의
해시가 달라지므로 **새 출력 폴더에서 `prepare`부터 다시 실행한다.** 1회차 실행 폴더
`outputs/ere_sta_20260914_v1`은 관문 실패 기록으로 보존하고 덮어쓰지 않는다.
개정된 ERE는 존재 채널을 쓰므로 `event` 단계도 `.local/metric_v2_env`에서 실행한다.
재감사는 `outputs/ere_sta_20260914_v2`에서 완료했다. 합성 원본·seed와 정답 자료는 동일하다.
평가 원본은 자료 무결성·정답 적격성에만 읽었고 후보·학습 모델 입력으로는 사용하지 않았다.
