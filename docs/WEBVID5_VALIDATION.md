# WebVid5 개발 검증

수정: 2026-09-17. 첫 실행은 첫 영상의 선택 단계에서 GPU 메모리 부족으로 중단됐다.
**메모리 보완 v2 설정의 실패 구간 재검증은 통과했으며, 5편 전체 재실행은 아직 시작하지 않았다.**

## 한 명령으로 실행

이 컴퓨터의 어느 디렉터리에서든 다음 명령을 입력한다.

```bash
bash /home/sangukbae/ETRI/Semantic/semantic_transmission/scripts/run_webvid5.sh
```

스크립트가 저장소 디렉터리로 이동하고 `.local/settings.json`의 Conda 환경을 사용한다.
ROS의 `PYTHONPATH`와 시스템 `LD_LIBRARY_PATH`를 해제하며, 각 모델을 별도 프로세스로 순차 실행한다.
터미널을 유지해야 하는 전경 실행이다. 결과 폴더와 현재 영상·단계를 터미널에 표시한다.
InternVL 선택 단계는 영상당 수 시간이 걸릴 수 있으며 세부 진행은 해당 영상의 `logs/select.log`에 기록된다.

동일 명령에 `--dry-run`을 붙이면 원본·전처리 파일 해시, 프레임 수, 환경 경로와
재사용 가능한 결과를 검사한다. 모델 추론, 출력 디렉터리 생성, 실행 이력 갱신은 하지 않는다.

## 고정한 다섯 유형

[선정 manifest](../configs/webvid5_manifest.json)는 공식 WebVid55 목록에서 확보한 원본 중
다음 5편을 고정한다. 원본의 처음·25%·50%·75%·끝 프레임을 확인한 목적 표집이다.
복원 결과를 보기 전에 정했으며 무작위·대표 표본은 아니다. 유형은 주된 특성이며 서로 배타적이지 않다.

| 유형 | 영상 내용 | 입력 프레임 | 입력 길이 |
|---|---|---:|---:|
| 저동작 장면 | 등불, 비교적 안정된 구도와 초점 변화 | 181 | 7.54초 |
| 한 사람의 이동 | 들판에서 스카프를 든 사람의 이동·회전 | 337 | 14.04초 |
| 빠른 이동 | 눈길을 달려와 지나가는 썰매견 | 384 | 16초 |
| 카메라 이동 | 항구를 내려다보며 이동하는 드론 | 384 | 16초 |
| 여러 객체와 가림 | 낮은 시점에서 본 여러 보행자의 등장·퇴장·가림 | 384 | 16초 |

총 1,670프레임, 69.58초다. 실제 실행 순서는 기존 배치 실행기의 파일명 정렬 순서다.
입력은 `.local/datasets.json`의 `webvid55/processed`이며 **전처리된 영상 전체 길이**를 사용한다.
공식 전처리에서 최대 16초로 제한된 파일이므로 긴 원본 파일 전체를 의미하지는 않는다.
원본과 전처리 결과의 SHA-256 및 프레임 수가 manifest와 다르면 추론 전에 중단한다.
없는 파일을 다른 영상으로 대체하거나 9프레임 smoke 입력으로 축소하지 않는다.

## 실행·평가 조건

[전용 프로필](../configs/webvid5.json)의 v2는 `lgvsc_variable.json`의 모델·선택·평가 조건에
메모리 보완을 적용한 별도 프로필이다. 프로필 파일의 해시도 선정 manifest에 고정했다.

- 576×320, 24fps, 각 입력의 전체 프레임. InternVL BF16 SKEM, threshold=0.35, stride=1.
- InternVL 마지막 3개 계층의 BF16 가중치를 CPU에 보관하고 연산 시 GPU로 전송한다.
  초기 배치에서도 이 계층들을 GPU에 한꺼번에 올리지 않는다.
  K/V 캐시는 값이 같은 별도 텐서로 복사해 불필요하게 큰 QKV 원본 메모리를 붙잡지 않게 한다.
- 공식 PLLaVA 캡션·UniMatch 광류, Open-Sora 30단계·시드 42.
- 공개 NTSCC quality-4 체크포인트, AWGN 10dB, channel seed=1024.
- `decoder_policy=official_release`, `concatenation_policy=official_release`.
  구간 경계 중복을 포함하며 참조 프레임에도 동일한 대응을 적용한다.
- PSNR, 흑백 SSIM, LPIPS-VGG, CLIP ViT-B/32, DISTS를 PNG 프레임과 최종 MP4에 각각 평가한다.
- 전송 성공·파일 무결성·영상 길이를 확인하고, 패킷 구성·LDPC 패딩/패리티·복소 채널 사용량·CBR를 기록한다.

v2의 잠정 예상 시간은 약 **35시간**이다. 최초 17.5시간 또는 초기 진행 관측의 20시간은
CPU 보관 계층 1개였던 v1의 예상이며 v2에 그대로 적용하지 않는다.
v1에서 완료한 98회 비교 평균 45.57초에, 같은 98번 비교를 v2로 실행한 시간 비율
`70.76 / 44.02 ≈ 1.607`을 곱해 비교당 약 73.25초로 보정했다.
`(1,665 × 73.25 + 1,670 × 1.97) / 3,600 ≈ 34.8시간`이다.
속도 비율의 짝 비교는 1건이므로 정밀한 예측이 아니며 장면과 키프레임 수에 따라 달라진다.
수정 후에도 완료 영상은 0편이므로 다음 실행은 5편 모두 새로 생성한다.

## 결과와 해석

실행마다 `outputs/webvid5_날짜_시간_식별자/`에 새 배치를 만든다.

| 파일 | 내용 |
|---|---|
| `summary.json` | 성공 편수, 영상별 결과, 5편 평균, 항목별 전송량·총 CBR |
| `per_video_metrics.csv` | 영상별 5개 화질 지표×2종 출력, 전송량, CBR, 단계 시간 합계 |
| `report.html` | 원본과 복원 MP4를 나란히 재생하는 로컬 비교 페이지 |
| `manual_review.csv` | 유형별 관찰 항목과 사람이 기록할 의미 오류 메모 |
| `webvid5_protocol.json` | 선정 목록·실행 설정·실행 코드 해시·환경·가중치 파일 정보 |
| `batch_manifest.json` | 진행·실패 상태와 영상별 단계 기록 |
| `<영상 ID>/logs/` | 영상별 단계 로그 |
| `<영상 ID>/quality*.csv`, `quality.json` | 프레임별·영상별 화질 지표 |
| `<영상 ID>/*_accounting.json` | 송신·채널·수신 검증 및 전송량 상세 |

모든 영상이 완료된 경우에만 **영상별 평균에 같은 가중치를 준 5편 평균**을 제공한다.
일부 실패 시 성공 영상만으로 5편 평균을 만들지 않으며 `INCOMPLETE`로 기록한다.
`pipeline_seconds`는 재사용 영상도 원래 실행의 9단계 시간 합계다. 이번 명령의 경과 시간은 아니다.
직렬화된 JSCC 파일의 바이트 수와 실제 RF bit 수는 다르며, 연속 심벌은 복소 채널 사용량으로 집계한다.

`PASSED`는 9단계 실행과 산출물 검증 완료를 뜻한다. 화질 합격 임계값이나 의미 보존 성공 판정은 없다.
객체 추가·소실, 이동 방향, 동작 순서, 가림 오류는 비교 페이지에서 확인하고 `manual_review.csv`에 기록한다.
이 사람 검수는 자동 수행하지 않으므로 요약에는 `manual_review_status=PENDING`으로 남긴다.
5편 결과를 보고 모델을 수정하면 최종 확인에 별도 미사용 영상이 필요하다.

## 중단과 재실행

같은 명령을 다시 입력하면 같은 조건으로 끝난 영상만 해시·설정·전송·평가 결과를 검증해
새 배치로 복사한다. 미완료 영상은 처음부터 실행하며 단계 중간 재개는 지원하지 않는다.
기존 출력은 덮어쓰지 않는다. `.local/webvid5_history.json`에 배치 경로와 실행 조건별 이력을 저장한다.
동일 WebVid5 명령의 중복 실행은 파일 잠금으로 방지한다.

선정 목록, 프로필, 실행 코드, 환경 및 가중치 파일 정보가 바뀌면 이전 조건의 결과를 섞지 않는다.
가중치는 설치 경로·파일 크기·수정 시간을 확인한다. 매 실행마다 대형 가중치 전체를 SHA-256으로
재검증하는 기능은 아니다. 이미 완료된 산출물의 무결성 오류는 자동 무시하지 않고 오류로 알린다.

## 구현 확인

CPU 회귀 검사는 합성 파일로 정확한 5편 선택, 전체 길이 설정, 사전 점검의 무추론·무기록,
입력 변경 차단, 일부 실패 후 재사용, 이전 결과 보존, 조건 변경 시 분리,
누락 지표의 성공 집계 방지와 중복 명령 차단을 확인한다.
실제 로컬 데이터 5편·설치 환경을 사용하는 `--dry-run`도 별도로 확인한다.
이 검사는 장시간 모델 추론 완료나 복원 품질을 입증하지 않는다.

## 2026-09-17 선택 단계 메모리 부족 보완

첫 배치 `outputs/webvid5_20260917_153638_6b1098`은 15:36에 시작했고,
16:52에 첫 영상의 99번 비교 도중 중단됐다. 98번까지의 비교는 완료됐다.
로그에는 `torch.OutOfMemoryError`, 추가 할당 시도 112MiB, GPU 여유 3.69MiB,
다른 프로세스 PID 531354의 약 914MiB 점유가 기록돼 있다. 점검 시 이 프로세스는 이미 종료돼
어떤 프로그램이었는지는 확인하지 못했다. 기존 1계층 설정의 메모리 여유가 부족했다.

v2는 CPU 보관 계층을 3개로 늘리고, 캐시 값은 그대로 유지하며 과도한 원본 버퍼 참조를 해제한다.
키프레임 선택 기준·프레임 수·타일 수·생성 토큰 상한·정밀도는 기존 값을 사용한다.
실패한 영상의 원본 프레임 0을 기준으로 98·99·100번을 비교했다.
별도 프로세스에 1GiB 텐서를 할당해, CUDA 문맥을 포함해 약 1.27GiB를 추가로 사용하는 조건에서도
세 비교 모두 통과했다. 샘플링한 GPU 최소 여유는 473MiB였다.

세 비교의 Yes/No 확률과 차이는 먼저 통과한 4계층·기존 캐시 방식과 정확히 일치했고,
98번은 중단된 원래 1계층 실행 기록과도 일치했다. 이는 해당 세 비교에서의 일치이며
모든 입력에서의 동일성이나 5편 전체 성공을 입증하지는 않는다.

전체 회귀 검사 175개 통과·1개 생략. CUDA 메모리 오류는 다음 실패 시 터미널 메시지에도 표시한다.
기존 실패 배치의 408개 파일은 보존했다. 선택 단계 중간 재개를 지원하지 않으므로,
동일 실행 명령을 다시 입력하면 첫 영상부터 다시 처리한다.
검증 범위와 측정값은 [메모리 보완 검증 기록](validation/2026-09-17-webvid5-oom-fix.json)에 보관한다.
