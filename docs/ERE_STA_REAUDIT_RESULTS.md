## 무엇을 고쳤고 왜 좋아졌는가

- `scripts/run_metric_v3.sh`: 사건·객체 추출기 감사를 모두 `metric_object_python`으로 실행한다.
  SAM2/DINOv2와 RAFT를 함께 쓰는 사건 감사가 실제로 `.local/metric_v2_env`에서 완료됐다.
- `event_metric.py`: 기존 `ObjectExtractor`와 트랙 연결 규칙을 재사용해 **객체 존재**를 유지하고,
  각 마스크 안의 카메라 보정 잔여 광류로 **운동 상태**를 계산한다. 등장·퇴장과 이동 시작·정지를
  구분하고, 방향 전환은 카메라 이동을 보정한 중심 궤적에서 계산한다.
- `attribution_metric.py`: 키프레임 근처 시각만으로 근거를 인정하지 않는다. 읽힌 내용의 사건
  종류·방향·위치가 맞아야 하며, 손실·검사합 실패·영상 복호 실패·내용 추출 실패를 표시한다.

예를 들어 `renderer/260915100`의 0.5초에는 **이미 있던 객체가 이동을 시작**한다.
이전에는 새 움직임 영역을 `enter`로 잘못 기록했지만 이번에는 `start`로 맞혔다.
2.625초의 정지도 이전 `exit`에서 올바른 `stop`으로 바뀌었다.

## 방향 전환 진단은 재감사 전에 끝냈다

합성 개발 원본 16개에서 다음 **54개 조합**을 비교했다. 추출 전에 탐색 범위와 선택 규칙을
기록하고, 선정 수치·수정 기록을 작성한 뒤 새 실행 정의를 고정했다.

| 매개변수 | 개발 진단 범위 | 선택값 |
|---|---|---:|
| 중심 궤적 평활 길이 | 3, 5, 7프레임 | **7프레임** |
| 최소 속도 | 0.25, 0.5, 1.0 px/frame | **0.25 px/frame** |
| 방향 전환 각도 | 90°, 120°, 150° 초과 | **150° 초과** |
| 전후 속도 계산 구간 | 각 1, 2프레임 | **각 2프레임** |

선택 순서는 `min(재현율, 정밀도, 방향 전환 재현율)` 최대화 → 사건 F1 최대화 → 기본값과의
가까움이다. 두 채널을 적용한 기본 설정(5프레임/0.5/90°/2)도 방향 전환은 이미 **16/16**이었다.
선정값은 기본 설정 대비 정밀도를 **87.7%→92.0%**로 높이고 재현율은 **96.9%→95.8%**로
바꿨다. 따라서 방향 전환 개선 전체를 매개변수 조정의 효과로 설명하지 않는다.
존재·움직임 분리와 중심 궤적 판정의 각각의 효과는 별도 절제 실험으로 분리하지 않았다.

새 재감사에서는 새 객체 추출 캐시로 다시 실행했고 선택 당시 수치를 재현했다.
평가용 원본으로 모델을 실행하거나 매개변수를 선택하지 않았다.
필수 관문 80%, 사건 대응 조건, ERE/SER와 STA의 비율 수식은 그대로다.

## STA의 손상 반례는 어떻게 바뀌었는가

수신 키프레임 시각이 남아 있어도 내용이 손상돼 사건을 읽을 수 없고 다른 근거가 없다면,
이전의 **CLR=0, GFR=1**에서 **CLR=1, GFR=null**로 바뀐다.
즉, 수신 근거가 사라진 것으로 기록하고 생성 실패율의 분모는 비어 있다고 처리한다.
정상 캡션이 같은 사건을 설명한다면 그것은 별도의 수신 근거로 인정한다.

정상, 송신 누락, 패킷 제거, 생성 누락, 근거 없는 추가, 내용 손상의 **분석적 사례 6개**가
모두 기대값과 일치했다. 별도 자동 테스트에서는 실제 PNG 바이트의 정상 복호, 검사합 오류,
복호 불가, 패킷 손실, 내용 읽기 실패도 검사했다. `decode_keyframe`은 복호된 RGB만 내용
읽기 함수에 넘기며 원본 정답은 넘기지 않는다.

이 6개 사례는 명시적으로 만든 사건 상태를 쓰는 규칙 검사다. **실제 영상의 귀착 정확도 100%를
뜻하지 않는다.** 단일 정지 이미지에서 시작·방향 전환을 알 수 없으면 판정을 보류해야 한다.
수신 영상의 시간 문맥에서 상태를 읽는 전체 TX/RX 어댑터와 모의 영상 복원 실험은 아직 미구현이다.

## 공개 영상의 한계와 검증 범위

공개 DAVIS 개발 원본 8개에서는 주석 사건 **6/66 = 9.1%**, 방향 전환 **4/59 = 6.8%**,
객체-프레임 **83/408 = 20.3%**를 찾았다. 공개 사건 재현율은 이전 13.6%보다 낮다.
이번 존재 추적을 실제 영상에 바로 적용할 수 있다고 판단할 근거는 없다.
공개 영상은 개정 프로토콜에서 재감사 전에 정한 대로 진단 전용이다.

공개 감사 파일의 `precision=6/710`은 **선택된 DAVIS 객체 주석과의 대응 비율**이다.
전체 객체·사건이 빠짐없이 주석된 자료가 아니므로 이를 실제 전체 사건 정밀도로 해석하거나,
대응되지 않은 704건을 모두 오검출로 확정하지 않는다.

총 70개 원본·2,216개 사례를 이전 실행과 같은 내용으로 별도 파일에 복사했고 RGB·정답 해시를
검증했다. 새 정답 감사 결과 **2,211개 채택·5개 제외**, 정상 대조군 **656개 모두 불변**으로
이전과 같았다. 평가용 원본 46개는 자료 무결성·정답 적격성 검사에만 읽었으며 후보·학습 모델
입력으로 사용하지 않았다. 사람의 추가 검수는 없고 공개 자료의 기존 사람 주석을 감사에 사용했다.

**전체 자동 테스트 79개 통과.** 새 정의·코드·스크립트·모델 해시와 이전 실행의 보존 상태를
확인했다. 아직 미실행인 항목은 평가용 자료의 오류 검출 AUC·검출률, 기존 지표와의 비교,
STA 영상 귀착 정확도 및 실제 LGVSC/SGD-JSCC 복원 귀착이다. 본 평가 실행기도 추가 구현이
필요하며, ETRI 1단계의 유효성·신규성 입증이 완료된 것은 아니다.

## 재현과 산출물

실제 결과는 `outputs/ere_sta_20260914_v2`에 있다. 아래는 패키지 루트에서 새 폴더로 같은
절차를 반복하는 명령이다. 개발 진단도 다시 실행하며 기존 실패·재감사 폴더를 덮어쓰지 않는다.

```bash
env -u LD_LIBRARY_PATH PYTHONNOUSERSITE=1 PYTHONPATH=src \
  LD_LIBRARY_PATH="$PWD/.local/metric_v2_driver/extracted/usr/lib/x86_64-linux-gnu" \
  .local/metric_v2_env/bin/python scripts/diagnose_event_v31.py \
  --source-run outputs/ere_sta_20260914_v1 --output outputs/ere_sta_v31_development_repeat

  --reuse-inputs outputs/ere_sta_20260914_v1 \
  --diagnostics outputs/ere_sta_v31_development_repeat/diagnostics.json
bash scripts/run_metric_v3.sh truth_audit outputs/ere_sta_reaudit_repeat
bash scripts/run_metric_v3.sh extractor_gate outputs/ere_sta_reaudit_repeat
bash scripts/run_metric_v3.sh summarize outputs/ere_sta_reaudit_repeat
```

위 GPU 환경 설정은 이번 컴퓨터의 드라이버 호환 경로다. 시스템 드라이버는 변경하지 않았다.
같은 seed·자료의 반복은 독립 평가가 아니다. 실행 당시 정의는 출력 폴더의
`ERE_STA_PROTOCOL.frozen.md`와 `ERE_STA_EXECUTION_NOTES.frozen.md`에 보존되어 있다.
