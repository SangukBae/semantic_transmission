## 독립 문맥의 정답 재검수·미사용 ClipShots 캡션 비교

**미사용 12원본·24구간에서 보강 캡션 모델은 사실 완전 재현이 51→54/83으로 조금 늘었지만, 동작 재현과 오류 구간은 같았다.** 이전 개발 영상의 큰 오류 감소는 이번 자료에서 재현되지 않았다. 사전에 정한 ‘사실·동작 비하락, 오류·생성 실패 비증가, 한 항목 이상 엄격한 이득’이라는 점수 기준은 통과했다. 통계적 비열등성이나 넓은 일반화가 입증됐다는 뜻은 아니다. 평가 직후에는 개선 후보로 보존했다. 이후 사용자 요청으로 캡션 초안에 기본 채택했으며, 아래 결과는 당시 동결 비교 그대로다. 추가 학습은 0회다.

비교 모델은 **이전 Astra 정답으로 학습한 Qwen + LoRA rank 32**와 그 모델에서 보강 캡션만 추가 학습한 `caption`의 사전 지정 마지막 epoch 2다. 무학습 Qwen과 Astra 직접 캡션의 비교가 아니다. 같은 구간의 4키·원본 픽셀·시간 라벨·프롬프트·NF4 정밀도·160토큰 한도를 고정하고, 두 어댑터를 하나의 Qwen 본체에 동결해 호출 순서를 교대했다. 모든 48캡션을 정상 생성했고 입력 토큰·시각 격자가 쌍별로 일치했다. 선택기는 평가하지 않았다.

**변화는 원본마다 달랐다.** 오토바이 장면에서 기존 모델의 ‘왼쪽으로 쓰러져 있다’는 설명이 주차된 오토바이·차량·주변 건물 설명으로 바뀌며 사실 2개가 늘고 오류가 사라졌다. 반면 새 장면에서는 카메라가 위쪽을 보도록 바뀐 것을 ‘새가 새장 위로 이동했다’고 설명하거나, 컷으로 가까운 화면이 나온 것을 연속 줌으로 단정했다. 기존 오류가 없어진 2구간과 새로 오류가 생긴 2구간이 상쇄됐다. 학습 후 캡션이 더 많은 정보를 언급하는 경우에도 새로운 잘못된 주장이 함께 생길 수 있다.

**정답 재검수도 모델 출력 전에 완료했다.** 기존 대화를 전달하지 않은 세 GPT6-Astra 문맥이 보강 학습 17구간·개발 16구간·새 원본 24구간을 각각 확인했다. 새 원본 정답은 다른 문맥에서 다시 원본과 대조했다. 원래 87사실 중 편집 사이 연속 동작 추론 2개, 인물 정체 1개, 도망 동기 1개가 부분 지지여서 출력 생성 전에 제외했고, 두 평가자가 지지한 83사실(상태 58·동작 13·변화 12)을 동결했다. 이후 별도의 네 번째 GPT6-Astra 문맥이 조건명·이전 점수 없이 48캡션을 판정했다. 원본 작성자와 캡션 판정자는 다르지만 동일 모델 계열의 AI이며 사람 정답·파일 접근의 OS 격리를 뜻하지 않는다.

시간은 캡션별 전처리·생성·디코딩 합계이며 공통 시각 계산·로딩·검수·전송·복원을 제외한다. 같은 실행에서 측정한 참고값으로 반복 성능 벤치마크가 아니다. 생성 최대 GPU 할당량은 9.28GiB였다. 완전+부분 언급은 차례로 56/56/56/55/56개다. 평균 단어 수는 36.6/41.3/40.4/39.2/41.6으로, 이번 정보 손실을 문장 단축으로 설명할 수 없다.

**원본 재검수에서 제 주석 오류도 확인해 정정했다.** 출력 생성 전에 만든 62개 평가 사실 중 도시 장면의 ‘거의 고정된 구도’ 4항목이 잘못됐다. 정지 워터마크를 제외한 전경 특징 추적과 별도 템플릿 대조에서 각 구간의 전경은 오른쪽으로 23.5~24.0픽셀 이동한다(원본 폭 576). 왼쪽으로 이동하는 구도와 일치하며, 오른쪽 pan이라는 출력도 방향이 맞지 않는다. 기존 참조·일차 부분 검수는 보존하고 네 항목을 모든 조건의 분자·분모에서 제외해 위 표를 58개 기준으로 집계했다. 이 정정은 학생 출력 열람 후 이뤄졌으므로 독립·사전 확정 평가로 부르지 않는다. 명시적 고정 카메라·동일 화면 위치 주장과 반대 방향을 오류로 세되, 단순한 ‘비슷한 배치’나 ‘안정적인 촬영’ 표현만으로는 오류를 부과하지 않았다. 정정 이력（로컬 산출물 `outputs/qwen35_evidence_repair_v3/evaluation/reference_errata.json`） · 워터마크 제외 원본 이동 검사（로컬 산출물 `outputs/qwen35_evidence_repair_v3/evaluation/city_motion_reinspection.json`）

이 원본은 학습 120구간에 포함되지 않는다. 다만 현재 동결 **개발 캡션 2개**에도 같은 정지 구도 오류가 있어 검증 CE 해석에 제약이 있다. 동결 자료를 수정하거나 그 결과로 재학습하지 않았다. 60개 3분류 문장에는 이 잘못된 정지 주장이 들어 있지 않음을 따로 확인했다.

|---|---|---:|---:|---:|

학습 루프 시간은 로딩·검증·저장을 제외하며 네 조건 합계 35.76분이다. 각 조건의 최대 PyTorch 할당량은 9.51GiB였다. 마지막 epoch의 학습 캡션 CE는 약 0.96까지 감소했지만 개발 CE는 모두 1 epoch보다 증가했다. 이는 단순히 더 오래 학습하는 결정을 지지하지 않으나, 개발 정답 오류와 원본 4편이라는 한계 때문에 최적 epoch·일반화 실패를 CE만으로 확정하지 않는다. epoch 1 자유 캡션은 이번에 비교하지 않았다.

**무엇이 개선됐고 어디서 막혔는가:**

- **보강 캡션의 국소 이득:** 사람→인쇄 사진→파란 옷 사람의 순서, 무리→팔을 뻗은 사람→인쇄 얼굴의 순서를 더 잘 보존했다. 인물 원본의 완전 사실은 출발 7/16에서 caption 10/16·evidence 11/16으로 증가했다. 반면 바닷가 원본은 12/16에서 각각 9/16·8/16으로 감소했다. 새 사건의 이득과 다른 장면의 세부 속성 손실이 함께 있다.
- **근거 손실의 추가 이득은 미입증:** evidence의 학습 근거 손실은 0.265→0.094로 줄었으나 개발 정답은 출발 25/26보다 낮은 23/26이다. 캡션만 학습한 조건과 비교해 사실 36→35, 동작 11 유지, 오류 2→3이다. 쉬운 근거 문제를 푸는 능력과 필요한 사실을 자유롭게 찾아 설명하는 능력이 분리돼 있다.
- **3분류의 개선이 자유 캡션에 충분히 이어지지 않았다:** judgment는 확인됨 17→20/20, 모순 12→18/20, 근거 부족 19→20/20으로 좋아졌다. 그러나 자유 캡션에서는 정지한 강 장면의 오른쪽 이동, 바위와 거품이 함께 이동한다는 주장이 남았다. caption 대비 동작은 1개 늘었지만 오류는 2구간 늘었다. 질문을 받은 주장 판정의 개선을 캡션 전체 오류 감소로 해석할 수 없다.
- **문장 비교 손실은 더 나은 종합 결과를 주지 않았다:** preference의 비교 손실은 두 번째 epoch에서 0이 됐다. 그 epoch에 제시된 비교쌍의 margin 조건이 충족됐다는 뜻이며 자유 캡션에 사실이 모두 보존된다는 증거는 아니다. 판단 문제는 judgment와 같은 58/60, 자유 캡션의 사실·동작은 각각 1개 낮고 오류는 같은 4구간이다.

네 조건 모두 ‘사실·동작 비하락 + 오류 비증가 + 엄격한 이득’ 기준을 통과하지 못했다. **보강 캡션만 사용한 조건을 간단한 후속 비교 기준으로 보존하되 기본 모델로 채택하지 않는다.** 현재 보조 손실을 더 오래 반복하기 전에 원본 기반 정답을 독립 재검수하고 새 평가 원본을 확보해야 한다. 이 비교는 캡션 LoRA만의 결과이며 사건 후보·키 선택·전송량·Added/Missing/Distorted·복원 영상 성능은 평가하지 않았다.

## 중간 근거·순서·운동/정지 보강 — 학습 없이 준비 완료

아래는 준비 당시 기록이다. 이후 사용자가 네 조건을 완료했고 [후속 분석](RESULTS.md#qwen35-evidence-repair-result)에서 개발 캡션과 원본 정정 내역을 확인했다.

**사용자 요청에 따라 데이터와 학습 코드만 적용했다. Qwen 가중치를 로드하지 않았고 실제 모델 forward/backward·optimizer 갱신·새 체크포인트 생성은 모두 0회다.** 아래는 정확도 실험 결과가 아니라 준비 검증이다. 기본 추론 경로와 기존 완료 모델은 보존했다.

- 기존 학습·개발 원본에서 같은 4장을 직접 대조해 **27구간(학습 17·개발 10)**의 캡션·근거·반례를 보강했다. 중간 동작 단계, 순서가 뒤집힌 설명, 물과 고정된 바위, 객체 운동과 카메라 운동의 구별을 포함한다. 새 주석은 Codex의 원본 대조이며 독립 Astra·사람 정답이 아니다. 기존 교사 캡션을 본 상태에서 재검수했다.
- 같은 자료의 `caption → evidence → judgment → preference` 네 대조 조건을 구현했다. 각 조건은 **동일한 이전 Astra rank 32 체크포인트에서 별도로 시작**한다. 전체 시간 경로의 모든 단계에 손실을 주고, 사실 판단은 지지/모순/근거 부족을 구분하며, 누락·잘못된 동작 문장에는 평균 토큰 손실의 순위 차이를 적용한다. Qwen 본체·시각부·선택기는 고정하고 LoRA만 갱신하는 예정 구성이다.
- 개발 자료의 무조건 `A→D` 답은 **시간 문제 18개 중 6개**만 맞는다. 예전 12/12와 문제·분모가 달라 모델 성능 비교가 아니다. 중간 단계를 보존한 문제와 검수된 인접 단계 문제를 함께 만들었으며, 문제 길이별 상수 답 편향과 자료 부족은 여전히 남는다.
- 한 원본 전체를 최근 학습 자료에서 개발로 옮겼다. 선택한 더 이전 출발 체크포인트의 학습에는 없음을 원본 ID·해시로 확인했다. 새 분할은 **학습 31원본·120구간 / 개발 4원본·16구간**이며, 이미 결과 분석한 최종 평가 원본을 재사용하지 않는다. 새 독립 최종 평가는 아직 준비되지 않았다.
- 관련 **71개 테스트**와 CPU 전처리 **492개 입력** 검사를 통과했다. 최대 입력은 968/4,096토큰이다. 손실의 기울기·중간 단계 반영·재계산 일치 검사는 작은 CPU 텐서로 수행했고 가중치를 갱신하지 않았다. 새 Qwen GPU 역전파·최대 메모리·학습 시간·자유 캡션 정확도는 미검증이다.

활성 준비본은 `outputs/qwen35_evidence_repair_v3`이다. v1/v2는 표적 분포 검토 중의 미학습 초안이며 비교 모델이 아니다. 다음 실행은 사용자 학습 지시 이후에 진행한다. 시간 어댑터·선택기 공동학습과 모델 층수 변경은 이번 범위에 포함하지 않는다.

## 문장 학습 / 근거 연결 학습 — 완료 모델의 자유 캡션 비교

**두 학습은 정상 완료했지만 전반적인 정확도 향상은 확인하지 못했다.** 근거 연결 조건은 최종 평가에서 출발 모델보다 사실 완전 재현이 1개 늘었지만 동작 재현은 1개 줄고, 오류·근거 부족 구간은 1개 늘었다. 문장 학습만 한 조건보다도 오류가 1구간 많다. 두 조건 모두 사전 비하락 기준을 통과하지 못해 기본 경로를 바꾸지 않았다.

`initial`은 **이번 124구간 추가 학습 전의 Astra 정답 rank 32 Qwen**이다. 무학습 Qwen이나 Astra 직접 출력이 아니다. `caption`은 같은 출발점에 캡션 CE만 추가 학습했고, `grounded`는 여기에 0.3 × 근거 위치/전후 순서 손실을 더했다. 둘 다 사용자 실행의 2 epoch·62 update, 사전 지정 마지막 epoch 모델이다. 같은 학습 32원본·124구간·순서·LR 2e-5·rank 32를 사용했다. 각 496개 LoRA 텐서가 모두 유한하게 바뀌었고 초기 가중치는 동일했다. 시각부·선택기는 고정했다. 이번 비교에서는 optimizer 갱신을 하지 않았다.

같은 4키 `[0,2,5,7]`·262,144 최대 픽셀·캡션 프롬프트·160토큰 한도로 새 검증 3원본/12구간과 최종 평가 4원본/16구간을 처리했다. Qwen 본체 하나에 세 동결 LoRA를 올리고 호출 순서를 구간마다 바꿨다. 자유 추론에는 교사 사실·캡션·근거 정답을 넣지 않았다. 84출력 모두 정상 완료했으며 완전히 같은 문장 1쌍은 한 번만 판정해 83개 익명 캡션을 원본과 대조했다.

| 분할 | 조건 | 사실 완전 재현 ↑ | 동작 재현 ↑ | 완전+부분 언급 ↑ | 오류·근거 부족 구간 ↓ | 생성 시간 |
|---|---|---:|---:|---:|---:|---:|
| 검증 12구간 | 추가 학습 전 | 10/31 | 8/15 | 29/31 | 1/12 | 49.7초 |
| 검증 12구간 | 문장 학습 | 14/31 | 7/15 | 29/31 | 1/12 | 49.1초 |
| 검증 12구간 | 근거 연결 학습 | 14/31 | 8/15 | 29/31 | 1/12 | 47.6초 |
| 최종 평가 16구간 | 추가 학습 전 | 17/47 | 12/25 | 44/47 | 2/16 | 64.6초 |
| 최종 평가 16구간 | 문장 학습 | 17/47 | 11/25 | 42/47 | 2/16 | 65.3초 |
| 최종 평가 16구간 | 근거 연결 학습 | 18/47 | 11/25 | 43/47 | 3/16 | 65.6초 |

오류에는 원본과 모순되는 주장과 확인되지 않는 단정을 포함한다. 마지막 일관성 감사에서 같은 전경 구조물을 `bicycle rack`으로 단정한 문장 2개의 누락 오류를 반대 작성자가 원본 85/109/144/168프레임으로 재확인했다. 최종 평가의 최초 오류 집계는 2/1/2였고 위 표는 **2/2/3으로 정정한 값**이다. 원래 검수 파일을 덮어쓰지 않고 별도 정정（로컬 산출물 `outputs/qwen35_grounded_v1/evaluation/review_A_adjudication.json`）과 `original_review_error_windows`를 보존했다. 정정 요청자는 조건 매핑을 본 상태였지만 재검수자에게는 조건을 전달하지 않았다. 사실·동작 점수와 채택 결론은 정정 전후 같다.

**확인한 변화와 한계:**

- 근거 연결 조건의 최종 평가 +1사실은 새 완전 재현 5개와 손실 4개의 합이다. 건물 조명의 변화·폭포 주변 나무·물의 도착 지점은 더 담았지만, 비 속 잎의 작은 움직임과 일부 조명 속성은 빠졌다. 상태 재현은 5→7/22, 연속 운동은 11→9/18, 이산 사건은 1→2/7이다. 한 평균으로 동작 보존 개선을 주장할 수 없다.
- 건물의 상단 창문이 밝아진다는 기존 오류는 전면 띠의 조명 변화로 바로잡았다. 반면 폭포에서는 실제로 변하는 물과 거의 고정된 얼음을 함께 변한다고 설명했다. 검증 도시에서는 새로운 전경이 드러나는 카메라 이동을 추가했다. 교정과 다른 오류가 공존했다.
- 최종 평가 4원본 중 사실 변화는 건물 0·폭포 +3·도시 +1·비 −3이다. 검증의 +4사실은 눈 덮인 강 영상 한 원본에서 나왔다. 서로 인접한 구간을 독립 영상처럼 세거나 이 작은 차이를 일반화하지 않는다.
- 평균 문장 길이는 최종 평가 35.8/36.3/36.3단어로 비슷하다. 이번 손실을 단순한 문장 단축으로 설명하기 어렵다. 생성 시간은 호출별 전처리·생성을 포함하고 공통 시각 계산 7.62초, 모델·어댑터 로딩, 검수, 전송·복원을 제외한다. 근거 학습의 생성 효율 이득은 확인되지 않았다.
- 사용자 학습 루프 시간은 문장 306.4초·근거 774.0초로 보조 문제가 약 2.53배 걸렸다. 모델 로딩·검증은 제외한다. 최대 PyTorch 할당량은 각각 9.51/9.83GiB, 세 LoRA를 함께 올린 이번 추론은 8.63GiB였다.

**근거 문제의 측정 한계도 드러났다.** 학습 검증의 12개 문제는 모두 `A→D`만 정답이다. 영상을 보지 않고 첫/마지막 위치를 답하는 규칙도 12/12를 받는다. 실제 두 epoch 시간 문제 210개 중 174개가 이 상수 규칙을 허용한다. 근거 손실 0.285→0.023이나 12/12만으로 시간 관계 이해가 향상됐다고 말할 수 없다. 이것은 표적 분포와 지표의 한계이며 모델이 실제로 영상을 무시했다고 입증한 실험은 아니다. 또한 이 보조 목표는 **주어진 사실의 근거 위치를 맞히는 문제**여서, 자유 캡션에서 필요한 사실을 찾아 반드시 포함시키는 목표와 다르다.

원본 정답도 별도 확인했다. 학생 캡션을 열기 전에 반대 Astra 작성자가 78사실을 재검수해 75개를 지지했고, 바위 하향 이동 2개와 하늘 어두워짐 1개는 확인되지 않았다. 기존 정답을 고치지 않고 이 3개를 제외한 민감도 점수도 저장했다. 검증 분모는 사실 29·동작 13, 최종 평가는 사실 46·동작 24가 되며 완전 재현 분자는 모두 같아 결론은 바뀌지 않는다.

두 기존 Astra 문맥이 원본 사실 작성자를 서로 바꿔 검수했고 조건 매핑은 감췄다. 같은 모델 계열·공유 파일시스템의 AI 평가이며 사람 정답이나 완전한 독립 검증은 아니다. 원본은 7편의 WebVid, 최종 평가 전부 고정 카메라, 단일 seed다. 이 4원본은 이제 결과 분석에 사용됐으므로 다음 튜닝 뒤 미사용 최종 평가로 재사용하지 않는다. 키 선택·사건 후보·전송량·Added/Missing/Distorted·복원 품질은 이번 범위가 아니다.

다음 우선순위는 현재 손실로 학습을 더 늘리는 것이 아니라 중간 프레임의 근거, 순서 반례, 실제로 고정된 객체와 움직이는 객체의 구별, 누락된 연속 동작 정답을 보강하는 것이다. 상수 위치 규칙이 통하지 않는 검증과 새 독립 원본을 먼저 준비해야 한다. 추가 학습·시간 어댑터·선택기 연결은 실행하지 않았다.

## 관찰문 → 캡션 진단과 학습 준비 — 2026-10-06

**관찰문을 먼저 작성하는 추가 추론은 이번 개발 자료에서 전반 개선을 보이지 않았다. 최초 준비 단계에서는 실제 학습을 시작하지 않았다. 이후 사용자가 두 조건의 학습을 완료했으며 후속 자유 캡션 비교는 [별도 결과](RESULTS.md#qwen35-grounded-result)에 기록한다.**

기존 Astra 정답·rank 32 모델을 고정하고, 이미 평가한 8원본·24개 개발 구간의 같은 4장을 사용했다. 직접 캡션과 `객체·위치·변화·근거 JSON → 이를 체크리스트로 재확인한 캡션`을 비교했다. 최종 캡션은 모두 최대 160토큰·같은 80단어 지시다. 후자는 관찰문 최대 512토큰을 추가로 생성하므로 같은 계산량의 실험이 아니다. 두 경로의 실행 순서는 구간별로 번갈아 배치했다.

| 조건 | 사실 완전 재현 ↑ | 동작 재현 ↑ | 사실 완전+부분 ↑ | 오류·근거 부족 구간 ↓ | 생성 시간 |
|---|---:|---:|---:|---:|---:|
| 직접 캡션 — 이번 재검수 | 33/83 | 22/47 | 69/83 | 4/24 | 91.3초 |
| 관찰문 → 캡션 | 29/83 | 16/47 | 62/83 | 3/24 | 660.3초 |

시간은 각 경로의 텍스트 생성 호출 합계다. 공통 시각 특징 계산 5.6초, 모델 로딩, 검수, 전송·복원은 제외한다. 두 단계는 7.24배 걸렸고 최종 문장 길이는 평균 36.7→38.0단어였다. 단순히 짧아져서 정보가 빠진 경우와 다르게, 세부 정적 묘사와 동작의 배분이 달라졌다. Qwen 출력 72개는 모두 생성 한도 내에서 완료했다.

- **관찰문에 필요한 동작이 충분히 남지 않았다.** 관찰문 자체의 완전 재현은 25/83·동작 12/47이다. 추가 33사실은 부분 언급, 25사실은 언급되지 않았다. 완전히 언급한 25사실 중 24개는 최종 캡션에서도 유지됐다. 따라서 이 프롬프트에서는 마지막 문장화 단계만의 누락보다 관찰문 내용의 부족이 크게 나타났다. 이는 출력 텍스트 분석이지 모델 내부 지각·추론 능력을 직접 측정한 것은 아니다.
- **국소 교정과 다른 정보 손실이 공존했다.** 보행자 방향을 좌→우로 바로잡은 구간에서는 여성의 머리·표정 변화와 카메라 이동이 빠졌다. 직접 캡션 대비 사실 6개를 새로 완전 재현했지만 10개를 잃었다. 선박 오른쪽의 작은 돛도 추가했으나 전체 동작 재현 개선으로 이어지지 않았다.
- **프레임 인용도 완전하지 않았다.** 원래 JSON 형식 검사는 3/24만 통과했다. `i2` 문자열을 정수 2로만 정규화하는 별도 감사에서는 21/24가 통과했고 나머지 3개는 실제로 제공하지 않은 번호를 인용했다. 생성 결과를 재시도·수정하지 않고 원문 그대로 캡션 입력과 의미 검수에 사용했다. 형식 오류와 실제 근거 번호 오류를 분리한다.
- **기준선 점수 차이는 재학습 결과가 아니다.** 직접 캡션 24개는 이전 teacher_r32와 바이트 단위로 같다. 이번에 새 출력과 함께 다시 검수하면서 5사실이 완전→부분으로 바뀌고 손의 이동 주장이 근거 부족으로 한 구간 추가됐다. 이전 기록 38/83·24/47·3/24는 보존한다. 표는 이번 같은 기준의 쌍별 판정이며 AI 판정 변동이 있으므로 작은 차이를 확정적 개선/악화로 일반화하지 않는다.
- **평가 범위:** 기존의 독립 작성된 원본 사실 88개 중 동일 4장에서 관측 가능한 83개만 주 집계했다. 기존 두 Astra 검수 문맥이 조건 이름을 가린 72개 출력을 원본과 대조했다. JSON/문장 형식은 보이므로 절차 자체를 완전히 숨긴 실험은 아니다. 같은 모델 계열의 AI 평가이며 사람 정답·새 최종 평가·복원 성능 검증이 아니다. 기본 추론 경로에 관찰문 단계를 채택하지 않는다.

**학습 준비:** 예비 19원본을 먼저 12/3/4로 나누고 76개 새 구간의 동일 입력 Astra 정답을 작성했다. 기존 자료와 합친 학습은 32원본·124구간·363사실, 새 검증은 3원본·12구간, 최종 평가는 4원본·16구간이다. 준비 당시에는 학습·검증 특징 136구간만 만들고 최종 평가 특징·학생 출력은 생성하지 않았다. 이후 학습 완료 모델의 추론은 위 후속 결과에 분리해 기록한다. [자료의 범위·중복 검사·남은 부족](DATA.md#qwen35-grounded-data)

문장 CE와 CE+근거 위치/전후 순서 손실을 같은 기존 rank 32 가중치에서 시작하는 명령을 준비했다. RTX 4080에서 실제 긴 학습 문장 두 구간의 caption backward와 시간 근거 backward를 검사했다. Adam 모멘트 크기의 메모리를 함께 확보한 상태에서 최대 PyTorch 할당량은 **9.48GiB**, 보조 LoRA 기울기는 유한·비영이었다. **optimizer.step=0, 검사 전후 가중치 해시 동일, 새 학습 체크포인트 없음**이다. 전 학습의 성공이나 정확도 향상을 미리 보장하는 검사는 아니다. 관련 테스트 48개와 셸 문법 검사를 통과했다.

### 사용자 학습의 CUDA 오류 복구 — 2026-10-06

**아래는 복구 당시 기록이며, 이후 사용자가 두 조건 모두 2 epoch·62회 갱신을 완료했다.** 당시 `caption`은 완료됐고 `grounded`는 첫 갱신 후 두 번째 누적 배치에서 `CUDA driver error: unknown error`로 중단됐다. 마지막 저장점은 0회 갱신의 초기 체크포인트였다. 두 조건의 체크포인트 파일 해시와 동결 학습 구현·의존 코드는 모두 일치했다. 이 복구 검사 자체는 자유 캡션 정확도 평가가 아니다.

커널의 `dxgkrnl get_unused_fd_flags failed: ffffffe8`은 -24/`EMFILE`이며, 뒤이어 자원 공유 오류 -131이 기록됐다. 사용자 대화형 Bash의 soft limit은 1,024, Codex 검사 환경은 1,048,576이었다. [WSL 커널의 해당 처리](https://github.com/microsoft/WSL2-Linux-Kernel/blob/linux-msft-wsl-6.6.y/drivers/hv/dxgkrnl/ioctl.c)와 [Linux 오류 번호 정의](https://github.com/torvalds/linux/blob/master/include/uapi/asm-generic/errno-base.h)를 대조했다. 앞선 두 구간 준비 검사는 이 셸 환경 차이와 누적 배치를 확인하지 못했다.

별도 무갱신 재현에서 같은 학습 자료·순서와 첫 배치 뒤 Adam 모멘트 크기의 메모리를 사용했다. 한도 1,024에서는 첫 배치 이후 `webvid_016_9cda7e71_w0`에서 같은 CUDA 오류와 커널 `EMFILE`이 재현됐다. 실행기가 한도를 8,192로 높인 비교에서는 이 구간을 통과했고, 실제 사용 핸들은 1,051개로 이전 한도를 넘었다. 실행기의 프로세스 한도만 수정했으며 손실·학습률·배치·학습 구현 및 체크포인트를 바꾸지 않았다. 검사에서는 optimizer를 갱신하지 않는다. 기록은 런타임 복구 감사（로컬 산출물 `outputs/qwen35_grounded_v1/runtime_fix.json`）에 남긴다.

수정 후 **3개 누적 배치·12구간**을 완료했다. 기록한 최대 핸들 수는 **1,055**, 최대 PyTorch 할당량은 **9.83GiB**였다. 검사 전후 LoRA 가중치 해시가 같고 optimizer 갱신은 0회다. 관련 테스트 51개, 셸 문법, 체크포인트 무결성, 완료 `caption`을 모델 로딩 없이 건너뛰는 검사를 통과했다. 이 검사는 전체 학습·의미 평가 완료를 뜻하지 않는다. 사용자는 같은 `bash scripts/train_qwen35_grounded.sh both` 명령으로 근거 조건을 저장된 초기점부터 다시 실행했고 이후 완료했다.

## 동일 입력 Astra 정답 × LoRA rank — 후속 학습·교차 검수 완료

**새 교사 정답과 rank 32 조합은 학습 전 Qwen보다 사실·동작 재현을 높이고 오류를 줄였다. 다만 기존 정답으로 학습한 짧은 캡션보다 오류가 늘어, 사전 지정한 공동학습 확장·기본 채택 기준은 통과하지 못했다.** 개선 후보 가중치를 보존하며 시간 어댑터·선택기 추가 학습과 기본 경로 교체는 진행하지 않았다. 선택기를 고정한 캡션 대조이므로 키 선택이나 전체 FC-LGVSC 복원의 개선 결과는 아니다.

## 고정 키 캡션 보완 학습·전이 진단 — 2026-10-05

**새 사건 자료와 동작 QA 보조학습을 실제 적용했지만 전반적 정확도 개선을 확인하지 못했다. 새 가중치는 채택하지 않았으며 선택기·공동학습의 추가 갱신은 진행하지 않았다.** RTX 4080에서 두 조건을 각각 2 epoch·44 update 학습하고, 같은 4키로 네 캡션 모델의 24구간·96개 출력을 비교했다. 이전 선택기·공동학습 가중치와 기본 FC-LGVSC 경로는 보존했다.

- **공정 대조:** 새 기본 Qwen에서 동일한 초기 LoRA 496개 텐서, 데이터·순서·LR 2e-5·업데이트 수를 사용했다. `caption_ce`는 캡션 CE, `caption_qa`는 같은 CE + 동작·순서 질문 CE(0.3)다. 시각 인코더와 선택 헤드는 고정하며, 저장된 헤드 12개 텐서가 원본과 동일함을 확인했다. 새 두 조건끼리 보조학습을 비교할 수 있지만, 이전 공동학습 대비 차이는 초기화·자료·목표 변경을 함께 포함한다.
- **자료:** 새 TVSum 8원본을 학습 4편/12구간, 검증 2편/4구간, 평가 2편/6구간으로 분리했다. 기존 자료와 합쳐 학습은 20원본·76개 고유 구간, epoch당 88입력이다. 검증 20구간의 공통 캡션 CE로 epoch 0/1/2 중 선택했고 두 조건 모두 epoch 2가 최적이었다. 새 평가나 아래 기존 진단 영상은 모델 선택에 사용하지 않았다. [출처·제외 항목 감사](DATA.md#qwen35-caption-repair-data)

### 실제로 남은 오류와 후속 동작 질문 진단

- **정답 키가 있어도 동작 생략:** `d11`에서 새 두 모델은 문 열기→탑승→닫기를 설명하지 않고 차량 옆에 서 있다고 썼다. `d13`의 잠깐 등장하는 가로등도 일반 캡션에서는 계속 누락됐다.
- **시간 순서·운동 원인 왜곡:** `d06`의 바닥판 낮추기→다시 들어 올리기를 반대로 서술했고, QA 모델의 `d10`은 차량 접근을 카메라 확대라고 썼다. 새 평가 `a20/a21`에서는 움직이는 흰 차/버스를 기다림/정지로 설명했다.
- **출력 과제의 영향도 존재:** 모델을 바꾸지 않고 학습 때 쓴 동작 질문을 직접 주자 `d11`의 문 열기가 새 두 모델에서 회복됐고, QA 모델은 `d09`의 금속 훈연기를 알아봤다. `d13`에서는 CE가 가로등 등장, QA가 기둥 퇴장의 일부를 언급했다. 따라서 모든 누락을 시각 인코더의 인식 실패로 단정할 수 없다.

- **실행 비용:** 캡션 CE 학습 계산 212.45초, QA 조건 362.06초(약 1.70배), 각각 별도 검증 계산 21.87/21.13초. QA 추가 질문은 총 144회 학습했다. 두 조건의 최대 PyTorch 할당량은 각각 8.54 GiB였다. 원본 준비·모델 로딩·체크포인트 저장·전송·복원을 포함한 총시간이 아니다.
- **검증:** 관련 테스트 29개, 초기 가중치 동일성, 원본·정규화·프레임·특징 캐시, 분할 간 정확한 프레임 해시 중복 없음, 선택 헤드 불변, 입력·출력·판정 연결을 검사했다. 주 비교 96출력과 후속 질문 42출력을 기록했다.

## 새 사건 영상의 정답 키 대조 — 선택 손실과 캡션 손실이 함께 존재

**정답 프레임을 주어도 현재 일반 공동학습 캡션은 필요한 사실을 충분히 설명하지 못했다. 선택기 개선만으로 해결되지 않는다.** 기존 Qwen 파일럿 24원본 및 보호된 평가 원본과 겹치지 않는 예비 원본 **8편(WebVid 2·TVSum 6), 14구간**에서 네 조건 추론·원본 대조를 완료했다. 추가 학습이나 기본 경로 교체는 하지 않았다.

- **대조:** 현재 일반 공동학습 헤드의 선택 / 원본 주석을 이용한 정답 선택 × 학습 전 캡션부 / 일반 공동학습 캡션부. 정답 선택은 진단용이다. 네 조건 모두 균등 8후보에서 양끝 포함 4키, 같은 Qwen NF4·프롬프트·출력 한도·시각 토큰을 사용했다. 학습 전 캡션부도 현재 헤드와 같은 키를 받으므로 원래 전체 파이프라인의 성능을 뜻하지 않는다.
- **사전 고정:** 출력 확인 전에 원본의 8후보·추가 24표본을 보고 59개 사실 항목(동작·변화 30개 포함), 근거 프레임 및 정답 키를 동결했다. 같은 키의 캡션 대조는 이미지·텍스트 입력이 같고 어댑터만 켜고 끈다. 서로 다른 키는 프레임 번호/시간 라벨 때문에 텍스트 토큰 수가 조금 다를 수 있다. 이미지 격자·개수·생성 한도는 같다.

| 선택 / 캡션부 | 완전 재현 사실 ↑ | 완전 재현 동작·변화 ↑ | 명확한 오류 구간 ↓ | 평균 단어 |
|---|---:|---:|---:|---:|
| 학습 선택 / 학습 전 | 33/59 | 11/30 | 3/14 | 66.0 |
| 학습 선택 / 일반 공동학습 | 23/59 | 7/30 | 5/14 | 30.8 |
| 정답 선택 / 학습 전 | 34/59 | 13/30 | 5/14 | 67.2 |
| 정답 선택 / 일반 공동학습 | 24/59 | 7/30 | 5/14 | 28.9 |

사건 **근거가 키에 남는 것**과 사건을 **캡션에 정확히 적는 것**은 다르다. 동결 근거 규칙에서는 학습/정답 선택의 사건 근거가 20/30 → 29/30이다. 유효한 전후 상태 대안을 추가하고 방향에는 실제 이동 표본을 요구한 별도 사후 감사에서는 **같은 키가 22/30 → 30/30**이다. 바퀴를 들고 걷는 최종 상태, 차량이 가까워진 상태, 사람이 차량 안에 있는 상태도 유효한 근거다. 원래 주석·선택·출력은 변경하지 않았다. 최초 29/30을 네 장 예산의 본질적 한계로 해석하면 안 된다. 항목별 근거 감사（로컬 산출물 `outputs/qwen35_oracle_diagnostic_v1/evidence_sensitivity.json`）

1. **선택기 손실:** 잠깐 나타나는 가로등은 학습 키 `[0,1,5,7]`에 없고 정답 키 `[0,3,5,7]`에는 있다. 자전거를 두고 떠나는 장면에서 학습 전 캡션부는 학습 키를 받으면 계속 작업 중이라고 설명했지만, 정답 키를 받으면 오른쪽으로 떠나는 동작을 설명했다. 모든 근거 차이를 실제 사건 누락 수와 동일시하지는 않는다.
2. **캡션 학습의 생략·왜곡:** 정답 키 고정 시 학습 전/공동학습 사실은 34→24/59, 동작·변화는 13→7/30이다. 차량 문을 열고 탑승하는 동작을 학습 전 캡션부는 설명하지만 공동학습은 옆에 서 있다는 정도로 줄였다. 초점 이동을 물체 퇴장으로 설명하거나 바닥판의 내림→다시 올림 순서를 뒤집는 출력도 있다. 짧아진 출력과 정보 손실은 관측했지만 정답 문체·데이터 부족·손실 함수 중 단독 원인은 미분리다.
3. **학습 전 모델의 잔여 한계:** 정답 키에 가로등이 있어도 두 캡션부 모두 그 통과를 설명하지 않았다. 벌통의 연기/훈연기와 차량 바퀴 수 등도 누락·잘못된 속성이 남았다. 캡션 경로의 인식·시간 이해·정보 선택 문제이며, 이번 출력만으로 시각 인코더와 언어 생성부의 내부 원인을 더 세분할 수 없다.

**채점 민감도:** 59개는 속성·방향 조건을 포함한 엄격한 정답 항목이며 완전히 분해된 원자적 사실 전체가 아니다. 정답 키에서 일부만 언급한 항목까지 합치면 학습 전 45/59, 공동학습 45/59이며, 동작·변화는 20/30과 18/30이다. 이는 완전한 정확도 점수가 아니다. 따라서 모든 의미 내용의 인식이 악화됐다고 단정하지 않고, **필요한 세부 사실과 동작을 완전하게 표현하는 성능이 부족하다**고 해석한다. 부분 일치·모호한 주장·명확한 오류를 원문과 함께 별도 기록했다.

- **검증:** RTX 4080 16GB에서 한 Qwen을 순차 사용해 56개 출력을 완료했다. 최대 PyTorch 할당 7.75 GiB. 관련 테스트 24개와 원본/정규화 영상·112개 입력 PNG·체크포인트·동결 코드·캡션/판정 인용 검사를 통과했다. 코드 테스트가 의미 주석의 타당성을 증명하지는 않는다.
- **한계:** 8원본은 기존 학습 파일럿과 분리됐지만 과거 프로젝트 전체 추출 자료에는 존재한다. 사건 중심 목적 표집이며 14개의 독립 원본이 아니다. 정답 작성과 출력 검수는 같은 Codex의 비독립 AI 검토이고 사람/GPT6-Astra 독립 평가가 아니다. 이전 32구간 점수와 직접 비교하지 않는다. 실제 전송·복원 Added/Missing/Distorted는 이번에 평가하지 않았다.
- **다음 판단:** 세 작업 연결 구조를 폐기할 근거는 없지만, 현 캡션 LoRA를 그대로 더 학습하거나 선택기만 바꾸는 것으로 충분하지 않다. 동작 전후·행위자·방향을 분리한 학습 정답과 캡션 보존 평가를 먼저 보완한다. 학습 전 캡션부를 대조로 남기고 고정 키의 캡션 학습 비교를 통과시킨 뒤 선택기 개선 및 공동학습으로 연결한다. 이 진단 원본으로 튜닝하면 최종 평가는 별도 원본이 필요하다.

원본·네 조건·판정 보고서（로컬 산출물 `outputs/qwen35_oracle_diagnostic_v1/report.html`） · 전체 수치（로컬 산출물 `outputs/qwen35_oracle_diagnostic_v1/RESULT.json`） · 동결 조건（로컬 산출물 `outputs/qwen35_oracle_diagnostic_v1/protocol.json`） · [실행](RUN_GUIDE.md#qwen35-oracle-diagnostic)

## 원인 분리·정답 재검수·공동학습 대조 — 일부 사실 회복, 전반 개선 미확인

**주석 보강 후 일반 공동학습은 staged 모델이 놓친 일부 사실을 되찾았다. 추가한 사실 보존 손실은 같은 조건의 일반 공동학습보다 좋지 않았다.** 원래 학습 전 Qwen 대비 모든 지표가 개선된 결과도 아니므로 기본 추출 경로는 교체하지 않았다.

### 선택기와 캡션의 원인 분리

기존/학습 키 × 기본/LoRA 캡션의 네 조건을 32구간에서 새로 생성했다. 같은 키를 비교할 때 실제 입력 PNG·시각 토큰·프롬프트·정밀도·입력 토큰 수를 맞췄다. 모두 NF4/BF16·비시각 norm FP32이며, 과거 최초 기준선과는 정밀도 실행 경로가 달라 과거 숫자를 새 기준선으로 재사용하지 않았다.

| 분할 / 키·캡션 | 사건 포착 ↑ | 핵심 사실 ↑ | 오류 구간 ↓ |
|---|---:|---:|---:|
| 검증 / 기존 키·기본 캡션 | 10/11 | 18/32 | 10/16 |
| 검증 / 기존 키·LoRA | 10/11 | 16/32 | 2/16 |
| 검증 / 학습 키·기본 캡션 | 9/11 | 19/32 | 8/16 |
| 검증 / 학습 키·LoRA | 9/11 | 14/32 | 2/16 |
| 평가 / 기존 키·기본 캡션 | 7/19 | 21/32 | 10/16 |
| 평가 / 기존 키·LoRA | 7/19 | 15/32 | 4/16 |
| 평가 / 학습 키·기본 캡션 | 8/19 | 22/32 | 9/16 |
| 평가 / 학습 키·LoRA | 8/19 | 15/32 | 1/16 |

키를 고정해도 LoRA 적용 후 사실 재현이 줄었다. 정보 손실은 캡션 학습 쪽에서도 발생하며, 선택기만 바꿔 해결할 수 없다. 한편 선택 변경은 컵을 잡은 손 등 일부 사건 근거도 놓쳤다. 학습 키·LoRA 32문장은 앞선 staged 출력과 모두 같아 해당 원본 검토를 출처와 함께 재사용했다. 네 조건 원본 대조（로컬 산출물 `outputs/qwen35_factorial_20261005/report.html`） · 집계·조건 검증（로컬 산출물 `outputs/qwen35_factorial_20261005/RESULT.json`）

### 수정한 정답과 실제 공동학습

- 학습 64구간·검증 16구간의 원본 표본을 다시 검토했다. 학습 사실은 128→172개로 보강했고, 학습 51개·검증 15개 사실에 시간상 나뉜 필수 근거 집합을 연결했다. 팬케이크 들기·헬리콥터 퇴장 경계를 수정했다. 확대 검토에서 불명확한 꽃/꼬리 주장을 보수적으로 정정해 최종 주석 v3를 만들었다. 기존 v1과 중간 v2 자료는 보존했다. 원본 수는 학습 16편으로 그대로다. [데이터·한계](DATA.md#training-readiness) · 원본·근거 검토（로컬 산출물 `outputs/qwen35_fact_joint_v3/data_review.html`）
- 일반 대조군은 전체 캡션 CE + 기존 근거 손실, 제안 조건은 근거 없는 목표 제외 + 사실별 CE 균형 + 사건/시간 사실 누락 손실을 사용했다. 후보·선택 헤드와 언어부 LoRA를 함께 갱신했다. 정답·초기 모델·학습 순서·학습률은 같고, 각 조건 **2 epoch·46 update**를 완료했다. [구조](MODEL_ARCHITECTURE.md#qwen35-fact-training)
- 검증 사건 포착·사실 근거 보존이 초기 모델보다 감소하지 않는 후보 중 공통 고정 근거 CE로 체크포인트를 골랐다. 초기 CE 1.52039에서 첫 epoch 일반 1.51951 / 사실 1.51186, 두 번째 epoch 일반 1.67580 / 사실 1.69357이므로 **두 조건 모두 첫 epoch**가 선택됐다. 평가 정답은 학습과 선택에 사용하지 않았다.
- 각 선택 모델에서 어댑터 tensor **496개**, 헤드 파라미터 tensor **10개**의 실제 변경을 확인했다. 캡션 손실만으로 후보·선택 헤드에 전달되는 GPU 기울기도 0보다 컸다. 이는 연결/갱신의 증거이며 정확도 개선의 증거와 구분한다.
- RTX 4080 16GB에서 두 조건 모두 최대 PyTorch 할당 **8.56 GiB**였다. 학습 루프는 일반 **249.8초**, 사실 **243.4초**이며 모델 로딩·최초 검증은 제외한다. 중간 v2에서 1회 갱신 후 저장·재개를 실제 확인했고, 같은 학습 코드로 최종 v3를 실행했다.

### 선택된 모델의 실제 생성 결과

각 조건에서 검증/평가 32구간을 새로 추론해 총 64개 캡션을 원본과 대조했다. 모든 행은 해당 분할에서 **64키**이며, 정답으로 키를 골라 생성한 결과가 아니다.

| 분할 / 조건 | 사건 포착 ↑ | 핵심 사실 ↑ | 오류 구간 ↓ | 평균 단어 |
|---|---:|---:|---:|---:|
| 검증 / 기존 staged | 9/11 | 14/32 | 2/16 | 22.7 |
| 검증 / 재검수 + 일반 공동학습 | 9/11 | 22/32 | 1/16 | 29.5 |
| 검증 / 재검수 + 사실 보존 공동학습 | 9/11 | 20/32 | 1/16 | 26.9 |
| 평가 / 기존 staged | 8/19 | 15/32 | 1/16 | 16.5 |
| 평가 / 재검수 + 일반 공동학습 | 8/19 | 18/32 | 1/16 | 28.6 |
| 평가 / 재검수 + 사실 보존 공동학습 | 8/19 | 18/32 | 4/16 | 28.8 |

- **되찾은 정보:** 일반 공동학습은 바닥·배경 기구와 트랙터/부착 장치의 퇴장 등을 더 설명했다. 사실 보존 조건은 같은 트랙터 키에서도 퇴장을 생략했다. 제안 손실의 추가 이득은 확인되지 않았다.
- **새 오류:** 사실 보존 조건은 운동 기구의 상승/굽힘 방향을 혼동했고, 문 열림을 오른쪽 이동으로 설명하거나 문 닫힘을 카메라 패닝으로 설명했다. 검증의 `balancer` 장비명 오류도 기록했다. 정확한 인용과 원본 표본을 보고서에 남겼다.
- **사건 합계와 주석 정의:** 동결 주석에서는 두 새 모델 모두 운동 구간 +2, 문 구간 -2로 총 8/19가 유지됐다. 그런데 문 닫힘과 손 철수 두 항목이 모두 손이 있는 i3/f213을 요구한다. 확대 확인한 i4/f226에도 문이 닫혀 있고 새 선택은 이 프레임을 포함하므로, 실제 2사건을 모두 잃었다고 단정할 수 없다. 닫힌 최종 상태도 인정하는 별도 사후 진단에서는 staged 8/19·새 두 모델 9/19다. 기존 기본 Qwen도 같은 변경을 적용하면 7→8/19다. 주 점수와 정답 파일은 유지했고 이 수정으로 모델을 고르거나 재학습하지 않았다. 손 동작 프레임의 누락은 여전히 남는다. 일반/사실 조건의 평가 키는 16구간 모두 같으므로 두 조건의 캡션 차이는 키 차이로 설명되지 않는다. 정의별 민감도·원본 해시（로컬 산출물 `outputs/qwen35_fact_joint_v3/event_rubric_sensitivity.json`）
- **선택 여지:** 정답을 이용한 사후 진단에서는 같은 8후보·양끝 포함 4키 예산으로 검증 11/11·평가 18/19사건을 담을 수 있었다. 이는 정답을 알려준 상한 진단이며 실제 선택기 성능이 아니다. 예산 부족만으로 현재 누락을 설명할 수 없다. 상한·구간별 기록（로컬 산출물 `outputs/qwen35_fact_joint_v3/key_budget_diagnostic.json`）
- **효율:** 평가 캡션이 길어지면서 생성 시간도 기존 staged 32.2초→일반 51.8초 / 사실 52.0초로 늘었다. 같은 생성 함수의 이번 단회 측정이며 모델 로딩·시각 인코딩·전송·복원은 제외한다. 전체 처리 가속으로 주장하지 않는다.
- **검증 범위:** 관련 테스트 17개, 원본 816개 파일 검사, 기존 v1 코드/설정/주석 7개 해시 보존, 두 학습 조건 일치, 체크포인트 및 생성 파일 해시를 통과했다. 입력 이미지 격자/예산은 동일하다. 키가 달라진 운동/문 구간은 프레임 번호·시각 라벨 때문에 입력 텍스트 길이가 ±1토큰 차이나며 별도 기록했다. 고정 키의 2×2 캡션 대조에는 이 차이가 없다.
- **해석 한계:** 이전에 검토한 원본을 다시 사용한 진단 실험이며 분할당 4원본·16구간이다. 캡션 평가는 비독립 Codex AI의 복합 핵심 사실 판정으로, 사람/GPT6-Astra 독립 평가가 아니다. 모호한 방향·자세·지형 표현은 별도 메모를 남기고 명확한 오류 집계에서 제외했다. 수정 데이터와 일반 공동학습의 개별 기여는 분리되지 않았다. 미사용 원본, 실제 전송량 및 복원 Added/Missing/Distorted 개선은 미검증이다.

다음 학습의 비교 출발점은 일반 공동학습 체크포인트로 보존하되 기본 경로는 유지한다. 추가 사실 손실은 보류하고, 새로운 사건 중심 원본·독립 주석과 사건별 누락 분석으로 선택기 및 동작 설명을 보완하는 것이 우선이다. 기존 평가 점수에 맞춰 추가 학습을 반복하지 않았다.

## Qwen 단계별 본학습 결과 — 실행 완료, 전반적인 정확도 개선 없음

사용자가 실행한 `bash scripts/train_qwen35_multitask.sh staged`는 **헤드 12 epoch·192 update → 캡션 QLoRA 3 epoch·48 update를 정상 완료**했다. 가중치 변경, 완료 체크포인트, 데이터·기준선·코드 해시를 확인했다. 이 staged 결과를 확인한 시점에는 공동학습 본 실행 전이었다.

- **과적합 징후:** 헤드 검증 손실은 2 epoch의 1.518이 최저이며 마지막에는 2.489다. 캡션 학습 손실은 1.568→0.679→0.298로 줄지만 검증 CE는 1.507→1.741→1.787로 증가했다. 마지막 모델 대신 **기존 검증 최적 헤드 2 epoch + 캡션 1 epoch**를 선택한 뒤 평가했다. 평가 결과로 체크포인트를 고르지 않았다.
- **자원:** 캡션 단계 최대 PyTorch 할당 8.53 GiB. 로그상 두 학습 루프 합계는 253.4초이며 모델·특징 캐시 로딩 시간을 제외한다. 작은 헤드는 저장한 특징으로 CPU에서 학습한다. 9B 전체 가중치 학습 시간/메모리를 뜻하지 않는다.

같은 원본 표본 8장·선택 4장·캡션 지시문으로 검증/평가 각 16구간을 새로 추론했다. 아래 기준선의 캡션 점수는 원본 재검토 정정을 반영했다.

| 분할 / 조건 | 키 | 사건 포착 ↑ | 핵심 사실 항목 ↑ | 명시적 오류 구간 ↓ | 처리 시간 | 캡션 평균 단어 |
|---|---:|---:|---:|---:|---:|---:|
| 검증 / 학습 전 | 64 | 10/11 | 18/32 | 9/16 | 142.0초 | 62.9 |
| 검증 / 단계별 학습 후 | 64 | 9/11 | 14/32 | 2/16 | 49.2초 | 22.7 |
| 평가 / 학습 전, 재검토 | 64 | 7/19 | 20/32 | 11/16 | 138.0초 | 59.1 |
| 평가 / 단계별 학습 후 | 64 | 8/19 | 15/32 | 1/16 | 37.7초 | 16.5 |

**해석:** 사건 합계는 17/30으로 같다. 문 닫힘·손 철수 두 사건은 되찾았지만 강아지 고개 전환과 컵을 잡은 상태를 놓쳤다. 짧은 캡션은 잘못된 정지·카메라 설명을 줄이는 동시에 컵을 가져가는 손, 트랙터 퇴장, 배경 정보를 생략했다. 학습 후에도 운동 동작 순서 반전과 화면 안의 케이블카가 사라졌다는 오류가 남았다. 오류 구간 감소를 정보 보존까지 포함한 정확도 향상으로 해석하지 않는다.
