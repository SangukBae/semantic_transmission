# ETRI 후속 연구 개발·평가 프로토콜

- 작성일: 2026-09-21
- 요구사항 기준: [ETRI 후속 연구 요청 메일 요약](ETRI_FOLLOWUP_EMAIL_SUMMARY.md)
- 개발 순서: [ETRI 연구 개발 계획](ETRI_DEVELOPMENT_PLAN.md)
- 상태: 후속 개발·평가의 기준을 정리했다. 장시간 영상 확보, 실행기 확장, 오류 표시 및 완화 효과 검증의 완료 기록은 아니다.

2026-09-24 실행 근거: [평가 입력 v1](ETRI_BENCHMARK_V1.md)에 60초 원본 60개와 120초 확장 6개를
준비·검증했다. 아래 일반 원칙을 구체화한 입력 분할·예정 AWGN 작업·주석 양식이며,
독립 정답과 장시간 복원·완화 성능의 완료 기록은 아니다.

메일의 요청과 이를 수행하기 위한 프로젝트 설계를 구분한다. 60초 이상은 **확장 가능성을 검토하고
달성을 추진할 목표**이며, 5분·영상 수·SNR 목록·성능 합격 수치는 메일에서 확정하지 않았다.
아래 기록 형식, 대체안 후보, 평가 항목은 프로젝트의 실행 설계다. 실험별 수치와 구성은 결과 확인 전에 고정한다.

## 1. 요구사항과 완료 근거

| ID | 메일의 요청 | 이번 개발·평가에 필요한 근거 |
| --- | --- | --- |
| R1 | 채널별 비교 제외, AWGN 중심의 검출·완화 | 공통 AWGN 설정, 완화 전후 조건 및 비용 기록 |
| R2 | 동일 입력·채널의 원본/완화 전/완화 후, 성공·실패·새 왜곡 제시 | 동기 비교영상, 사례 목록, 가능 범위의 프레임·시간·영역·오류 유형 표시 |
| R3 | 실제 연속 영상의 60초 이상 확장 검토, 장면전환 3개 조건 | 원본 출처·연속 구간·실제 길이, 유형별 목록, 실행 가능성 측정과 미충족 사유 |
| R4 | drift·깜빡임, 씬 체인지 검출·패킷 갱신·검출 실패 대안 확인 | 시간별 오류, 장면 경계와 갱신 로그, 누락 시 대체안 비교 |
| R5 | 이미지/동영상 학습 여부와 동적 의미정보의 충분성 검토 | 모듈별 체크포인트·학습 이력 설명, 속도·동작·중간 구간 정보 보강의 비교와 재학습 필요성 판단 |
| R6 | 기존 연구방향 유지, 원본은 내부 검증에 활용 | 기존 모델·지표 연구와의 연결, 원본·산출물 관리 |

기존 짧은 영상 실험·통제 지표 실험은 개발 근거로 사용한다. 그 실행 성공이나 통과 판정을
R2~R5 전체의 충족으로 바꾸지 않는다. 새 지표의 신규성은 기존 연구 목표로 별도 검증한다.

## 2. AWGN 비교 조건

- 채널 종류별 비교를 현재 과업에서 제외한다. Rayleigh·이동 채널·SDR 확장은 이번 완료 조건이 아니다.
- 기존 기준선의 10 dB AWGN 설정을 출발점으로 삼되, 사용할 SNR과 잡음·생성 시드 목록은 실험 전에 고정한다.
  메일이 10 dB만 요구한 것은 아니다. AWGN 내 SNR 변경은 필요성이 있을 때 별도 조건으로 기록한다.
- 완화 전후에는 원본 구간, 전처리, 시간축, 해상도, 평가 코드와 공통 생성 설정을 맞춘다.
  변경한 모듈·가중치·프롬프트·전송 정책은 별도 조건으로 명시한다.
- 수신단 보정만 비교하면 같은 수신 데이터를 재사용한다. 키프레임·Semantic Packet을 추가하면
  공통 데이터의 잡음 대응을 유지하고 추가 데이터의 잡음 생성 규칙·전송 비용을 기록한다.
  같은 AWGN 조건과 같은 전송량은 별개이므로 동일 예산 비교 또는 비용–품질 비교로 보고한다.
- 수신단 완화에는 실제 수신 정보와 설치된 모델만 사용한다. 원본 영상은 송신단 처리와 독립 평가에 사용한다.
  원본 키프레임·수동 정답을 수신단에 직접 넣는 조건은 원인 분석용 진단으로 분리한다.
- 키프레임, 동적 설명, 갱신 신호, 부호화·패딩과 사용한 재전송 비용을 합산한다.
  미포함 물리 계층 비용, 처리 시간·메모리·재생성 횟수도 명시한다.

## 3. 장시간 시험영상 구성과 실행 가능성

원본 한 영상에서 **실제 시간 순서를 유지한 60초 이상 연속 구간**을 우선 확보한다. 자연스럽게
장면이 전환되는 영상도 포함한다. 짧은 클립 반복, 무관한 클립의 인위적 연결, 프레임 반복·감속으로
길이를 늘리는 방식은 이 목표를 충족하지 않는다. 여러 짧은 영상의 총 길이가 60초를 넘는 것도 별개다.

| 유형 | 선정 조건 | 주 확인 항목 |
| --- | --- | --- |
| 낮은 장면전환 빈도 | 장면전환이 거의 없는 장시간 연속 구간 | 마지막 수신 키프레임 이후 경과 시간에 따른 의미 drift, 깜빡임, 객체의 장기 유지 |
| 일반적인 장면전환 빈도 | 자연스러운 여러 장면과 객체·동작 변화 | 경계 검출, 동작·속도·관계 설명, 갱신 지연 |
| 높은 장면전환 빈도·고난도 | 빈번한 씬 체인지와 객체 출현·퇴장·배경 변화 | 누락·오탐, 오래된 조건의 잔류, 대체안의 효과와 부작용 |

유형은 복원 결과를 보기 전에 선정한다. 원본의 장면 경계 시각·전환 횟수/분·객체 변화 근거를
기록하고, 일반/고빈도의 구분 기준과 유형별 편수를 사전 등록한다. 초기 실행 가능성 확인은
유형별 최소 한 편을 목표로 하되, 이는 프로젝트의 예비 규모이며 최종 일반화 검증의 충분한 표본 수를 뜻하지 않는다.

데이터 목록에는 원출처·영상 ID, 원본 해시, 추출 시작/끝 시각, 원본/처리본 길이·FPS·프레임 수,
시간 대응, 유형·선정 근거, 개발/교정/평가 분할을 기록한다. 같은 원본의 구간은 서로 다른 분할에 넣지 않는다.
이미 오류 분석·설정 선택에 사용한 영상은 개발 자료로 관리한다.

기존 Stage 01은 16초에서 자르고, `etri_official.json`은 기존 10초 입력을 전제로 한다.
`lgvsc_variable.json`도 현재 `max_frames=384`이다. 이 설정을 그대로 실행해 장시간 평가라고
보고하지 않는다. 길이를 유지하는 전처리와 별도 실행 프로필을 만들고 입력부터 최종 출력까지 확인한다.

긴 영상을 메모리 때문에 내부 구간으로 나눠 처리할 수는 있다. 이때 원본의 연속 시간축, 구간 간 상태·
참조 전달, 경계 중복·누락과 장면전환 시 초기화 정책을 기록한다. 짧은 구간마다 모든 상태를 초기화해
장기 drift를 제거한 결과를 연속 복원으로 해석하지 않는다. 정책 비교 자체는 별도 실험으로 남길 수 있다.

짧은 기능 점검 뒤 실제 길이를 늘려 단계별 시간·최대 메모리·실패 위치·재개 가능성을 측정한다.
60초를 처리하지 못하면 확보 길이와 최대 검증 길이, 병목과 후속 조치를 보고하고 **길이 목표 미충족**으로 남긴다.
문서 개정만으로 장시간 지원을 완료 처리하지 않는다.

## 4. 오류 검출·완화와 씬 체인지 누락 대응

- 원본 대비 오류는 Added(없는 객체·내용 추가), Missing(있어야 할 객체·내용 누락),
  Distorted(객체·속성·동작·관계의 왜곡)로 기록한다. drift·깜빡임·속도·사건 순서·장면 조건 잔류는
  추가 태그로 관리한다. 여러 유형이 함께 발생하면 각각 기록한다.
- 정상 가려짐·프레임 밖 퇴장·실제 씬 체인지를 할루시네이션과 구분한다. 검출기의 관측 실패와
  정답 부족은 `UNRESOLVED` 등 별도 상태로 남긴다. 수신 근거가 부족하다는 사실만으로 원본 대비 Added라고 판정하지 않는다.
- 검출 성능과 완화 성능을 분리한다. 오류 검출의 오탐·미탐·관측률, 오류 지속 시간·영역,
  완화 후 잔존·새 오류를 기록한다. 영상 평균 화질만으로 할루시네이션 감소를 결론 내리지 않는다.
- 저전환 영상에서는 마지막 수신 키프레임 이후 경과 시간별 오류를 집계한다. 고전환 영상에서는
  독립적으로 확인한 장면 경계와 검출 시각, 키프레임·Semantic Packet 생성/수신/적용 시각을 대응시킨다.
  패킷에는 장면·구간 식별자, 유효 시간 범위, 갱신 이유를 남기는 방안을 설계한다.
- 키프레임 선택과 씬 체인지 검출을 같은 성능으로 간주하지 않는다. 새 장면에 이전 캡션·움직임
  정보가 재사용되는지, 생성기의 이전 구간 참조를 언제 초기화하는지 별도로 확인한다.

검출 누락의 대체안 후보는 **최대 키프레임 간격 제한과 주기적 의미정보 갱신**, 별도 변화 신호를
통한 재검사, 근거 부족 시 재생성 보류·수신 프레임 기반 출력 등이다. 모두 설계 후보이며 효과가
검증된 기능으로 간주하지 않는다. 선택한 정책의 주기·발동 조건·출력 방식·비용을 사전 등록한다.

개발 실험에서 실제 누락 사례와 검출 누락·지연을 통제한 사례를 구분하여, 대체안의 유무에 따른
오류 지속·새 왜곡·갱신 비용을 비교한다. 프레임 유지로 움직임이 사라지거나 갱신량이 급증하는
부작용도 기록한다. 대체안이 항상 씬 체인지를 해결한다고 가정하지 않는다.

## 5. 학습 이력과 동적 의미정보 검토

구현된 추론 경로와 학습 이력은 [모델 구조](MODEL_ARCHITECTURE.md),
[데이터 안내](DATA.md), [논문·구현 감사](LGVSC_PAPER_IMPLEMENTATION_AUDIT.md)를 함께 확인한다.

NTSCC의 이미지 코덱 학습, InternVL·PLLaVA·UniMatch의 사전학습, Open-Sora의 영상 생성 사전학습,
이 프로젝트의 추가 학습을 구분하여 설명한다. 모델 이름이나 폴더에 이미지가 있다는 사실만으로
전체 시스템의 학습 구성을 확정하지 않는다. 모듈별 체크포인트 ID·해시·모델 문서·학습 자료·
시간축 학습 목적·추가 학습 여부와 확인되지 않은 항목을 표로 정리하는 것이 후속 산출물이다.

현재 구간 캡션과 광류 요약이 존재하더라도 걷기·달리기·정지 준비, 속도·방향·등장·퇴장 시점을
충분히 전달하는지는 별도 검증한다. 중간 구간 caption/video summary, 사건 시각과 속도·방향 정보를
Semantic Packet에 추가·갱신하는 후보를 비교하고, 수신단 반영 방식과 추가 비용을 기록한다.

무학습 조건 보강과 동영상 데이터 미세조정은 서로 다른 후보로 검토한다. 먼저 정보 누락·조건 반영·
생성기의 시간축 표현 중 실패 원인을 분리하고, 재학습의 필요성·데이터·계산량을 판단한다.
동영상 재학습이 이미 결정됐거나 이미지 학습만으로 충분하다는 결론을 앞서 적지 않는다.

## 6. 비교자료와 결과 보고

각 영상·AWGN 조건·시드에 대해 원본 / 완화 전 / 완화 후를 원본 시간축으로 동기화한다.
원본·복원 원파일과 별도로 비교용 영상을 만들고, 비교 렌더링의 재인코딩 결과를 정량 평가 원본으로 사용하지 않는다.
기존 공개 연결 정책의 중복 경계를 제거하거나 대응할 때 실제 사건 지연·누락까지 없애지 않는다.

다음은 **신규 평가에서 준비할 산출물 규격**이며, 현재 실행기가 모두 생성한다는 뜻은 아니다.

| 산출물 | 내용 |
| --- | --- |
| 입력·실행 manifest | 원본/처리본 해시·연속 구간·유형·분할, 모델·설정·코드, AWGN·시드·시간축 대응 |
| 비교영상과 비교 페이지 | 원본/완화 전/완화 후 동기 재생, 세 영상의 실제 경로와 완료 상태 |

오류 영역 표시는 가능한 범위에서 제공한다. Missing은 완화 전 영상에 검출 박스가 없을 수 있으므로
원본 객체 영역과 시간 대응을 근거로 표시하고 좌표 기준을 남긴다. 장면 전체 오류는 전역 구간으로,
객체 영역을 특정할 수 없으면 미확정으로 기록한다. 정답과 자동 검출 표시도 구분한다.

성공·미완화·새 왜곡 사례를 같은 기준으로 분류하고, 전체 사례 수와 선정 방법을 함께 보고한다.
해당 사례가 없으면 관찰되지 않았다고 쓰며 예시를 만들지 않는다. 실패·보류를 집계에서 몰래 제외하지 않는다.
단일 시드의 성공 영상만 선택하지 않고 영상별 대응 비교를 기본으로 하며, 충분한 표본에서는 원본 단위 불확실성도 보고한다.

실행 완료, 오류 주석 완료, 완화 효과 입증, 길이·유형 목표 충족을 각각 판정한다.
독립 정답이 없으면 진단 단계로 남긴다. 원본은 메일의 취지에 따라 내부 성능검증용으로 관리한다.
