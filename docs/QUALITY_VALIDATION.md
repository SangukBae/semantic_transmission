## 터미널 표시

실행 중에는 현재 검증의 한 줄을 덮어쓰고 **진행률 숫자만** 바꾼다. 완료된 검증은 완료 문장 한 줄을 남긴다.
예를 들어 첫 검증 완료 후 두 번째 검증을 실행 중인 화면은 다음과 같다.

```text
[1/3] 키프레임 기준 오차 보정 검증이 끝났습니다 (100.0%).
[2/3] 저해상도 제약·적응형 키프레임 비교 진행률  42.7%
```

전체 완료 시 다음과 같이 표시한다. 아래는 출력 예시이며 실험 완료 기록이 아니다.

```text
[1/3] 키프레임 기준 오차 보정 검증이 끝났습니다 (100.0%).
[2/3] 저해상도 제약·적응형 키프레임 비교 검증이 끝났습니다 (100.0%).
[3/3] 별도 영상 5편·3개 시드 검증이 끝났습니다 (100.0%).
결과: /home/sangukbae/semantic_transmission/outputs/quality_validation_<실행해시>/REPORT.md
```

진행률은 완료 작업 수와 현재 작업에서 처리한 프레임·구간 수를 사용한다. **남은 시간의 비율은 아니다.**
모델 로딩이나 세부 진행률을 제공하지 않는 작업에서는 숫자가 잠시 유지될 수 있다.
실패나 Ctrl+C에는 100% 완료 문장을 출력하지 않고 중단 문장과 로그 위치를 남긴다.
출력을 파일/파이프로 보내면 진행률 갱신을 생략하고 완료·실패 문장만 기록한다. 상세 진행 상태는 `status.json`에 저장한다.

모델을 실행하지 않고 표시만 확인하려면:

```bash
bash scripts/run_quality_validation.sh --demo
```

입력 영상·기존 복원 결과·환경·모델 경로와 실행 계획을 읽기 전용으로 확인하려면:

```bash
bash scripts/run_quality_validation.sh --dry-run
```

## 각 검증의 실행 범위

| 검증 | 실행 내용 | 비교와 재사용 |
|---|---|---|
| 1 | 기존 ETRI·WebVid 각 1편의 수신 키프레임을 기준으로 생성 영상 보정 | ETRI에서 강도 0/0.25/0.5/0.75 비교 후 고정하고 WebVid에 적용. 원래 복원 결과와 전송 데이터를 재사용 |
| 2 | 위 두 영상에서 균일 키프레임 추가 / 적응형 추가 / 적응형 추가+저해상도 제약 비교 | 같은 전송 예산 상한, 같은 생성 시드. 후보 키프레임은 한 번 인코딩하여 조건별로 재사용 |
| 3 | 별도 WebVid 5편에서 시드 42/43/44로 비교 | 영상마다 원래 기준선·균일 추가·적응형 추가·저해상도 결합을 생성하고 기준선 보정은 후처리. 선택·자막·전송 결과는 시드 간 재사용 |

기본 계획은 세부 작업 327개이다. 3번의 생성은 5영상×3시드×4조건=60회이며, 보정 때문에 영상을 다시 생성하지 않는다.
기존 ETRI·WebVid 결과는 읽기 전용으로 사용한다. 새로운 출력은 별도 실행 폴더에 저장한다.
소스 해시·모델 파일 정보·코드·설정을 기록하며, 생성 프레임의 중복 경계는 원본 시간축에 맞춰 제거한 후 평가한다.

기본 설정과 영상 목록은 [configs/quality_validation.json](../configs/quality_validation.json)에 고정되어 있다.
개발용 ETRI에서만 보정 강도를 선택한다. 중간 프레임 LPIPS가 0.002 이상 개선되고 PSNR 감소가 0.1dB 이내,
시간차 오차 증가가 0.002 이내인 후보 중 LPIPS가 가장 작은 값을 선택한다. 후보가 없으면 강도 0을 선택한다.
저해상도 보정 강도 0.5 등 나머지 값은 별도 영상 결과를 보기 전에 고정한다.
별도 5편은 이번 보정 강도 선택에서 제외한 영상이며, 프로젝트의 과거 모든 실험에서 미사용한 영상이라는 뜻은 아니다.

## 방법과 전송량 경계

- **키프레임 기준 보정:** 수신 키프레임과 해당 시점의 생성 프레임 차이를 저주파 잔차로 만들고 ±32 범위로 제한한다.
  생성 프레임 사이의 Farneback 광류로 전파하며, 왕복 대응·밝기 차이·유효 좌표로 신뢰도가 낮은 위치의 보정을 줄인다.
  수신 보정 함수에는 원본 영상을 제공하지 않는다.
- **저해상도 제약:** 송신 측에서 모든 프레임을 72×40 H.264(CRF 30) 영상으로 인코딩한다.
  헤더·영상·CRC를 포함한 패킷 전체를 실제 Sionna LDPC(6144/9216)·16QAM·AWGN 채널에 통과시킨다.
  수신 성공과 시간축을 확인한 후, 받은 저해상도 영상과 생성 영상의 저주파 차이를 후처리로 반영한다.
- **적응형 추가:** 원본 영상의 작은 해상도에서 양 끝 프레임의 선형 보간 오차가 큰 시점을 송신 측에서 선택한다.
  기존 의미 구간의 경계를 보존하고 자동 자막·광류 메타데이터를 세분 구간에 재사용한다.
  비교군은 긴 구간의 중점을 차례로 추가한다. 원본을 이용한 수신 결과 선택이나 시드 탐색은 하지 않는다.
- **전송 예산:** 각 영상의 원래 키프레임 전송량을 다시 계측한 값의 2배를 세 조건의 공통 상한으로 둔다.
  NTSCC 복소 심벌, 메타데이터·rate index·LDPC 패딩, 저해상도 패킷의 복소 채널 사용량을 포함한다.
  물리 링크 헤더는 포함하지 않는다. 조건별 실제 사용량과 남은 예산은 `variants/budget.json`에 기록한다.
  동일 상한 비교이며 실제 사용량이 정확히 같다고 주장하지 않는다. 원래 키프레임+저해상도 정보가 예산을 초과하면 실패한다.
  예산을 자동으로 늘리거나 일부 비용을 빼지 않는다.
- **시드:** 생성 시드는 세 조건에 공통으로 적용하고 전송 잡음은 재사용한다.
  NTSCC AWGN은 키프레임 인덱스별 NumPy 난수로 생성하여 공통 키프레임의 잡음을 맞춘다.
  공식 GPU 채널의 특정 난수 출력과 동일한 재생이라는 뜻은 아니며, 해당 조건을 채널 기록에 남긴다.

## 결과와 재개

`outputs/quality_validation_<실행해시>/`에 다음 파일이 저장된다.

| 파일 | 내용 |
|---|---|
| `REPORT.md`, `summary.json` | 조건별 지표·전송량·영상별 시드 짝 비교·제한 사항 |
| `comparison.html` | 원본과 복원 영상의 동기 재생 |
| `manual_review.csv` | 물체·행동 추가/누락 및 시간 오류의 사람 검수 기록. 기존 입력은 보존 |
| 각 조건의 `metrics.json`, `per_frame.csv`, `frames/`, `video.mp4` | 전체/키프레임/중간 프레임 지표와 보정·복원 영상 |
| `protocol.json`, `plan.json`, `status.json` | 고정 설정·입력 해시·작업 계획·현재 상태 |
| `tasks/<작업명>/worker.log`, `receipt.json` | 모델 상세 출력과 작업 완료·파일 해시 |
| `validation_N_complete.json`, `COMPLETE.json` | 검증별/전체 **실행 완료** 기록 |

PSNR·SSIM·LPIPS·CLIP·DISTS 및 원본 대비 프레임 차분 오차를 계산한다.
별도 영상에서는 같은 영상·시드를 짝지어 비교하고 시드를 영상별로 평균한 다음 5편을 평균한다.
15개 실행을 독립된 영상 15편으로 취급하지 않는다.
개선 판정은 사전에 정한 LPIPS·PSNR·시간차 오차 기준의 제한된 확인이며, 통계적 유의성이나 할루시네이션 제거를 입증하지 않는다.
의미 오류의 독립 검수는 `PENDING`으로 남긴다. **“검증이 끝났습니다”는 실행 완료이며, 개선 성공을 뜻하지 않는다.**

중단 후 **같은 명령을 다시 실행**하면 완료 파일의 해시를 확인하고 남은 작업부터 진행한다.
실패 작업의 부분 출력은 `failed_attempts/`로 보존하고 해당 작업을 다시 실행한다.
완료 파일이 변경되었거나 코드·입력·설정이 달라진 출력 폴더는 섞어 사용하지 않는다.

첫 검증까지만 먼저 실행한 다음 기본 명령으로 이어갈 수도 있다.

```bash
bash scripts/run_quality_validation.sh --through 1
```

출력 위치를 지정하려면 `--output outputs/my_quality_validation`을 사용한다. 재개할 때도 같은 옵션을 사용한다.
설정을 바꿔 별도 실험을 할 때는 `--config <설정.json>`을 사용한다.

## 2026-09-21 짧은 첫 구간의 연결 오류 수정

실제 2번 검증의 `webvid_person.42.adaptive.reconstruct`에서 첫 구간이 8프레임이 되어 중단됐다.
VAE로 인코딩한 참조 길이는 2였지만 다음 구간의 연결 마스크는 5를 요구하여 빈 슬라이스 대입 오류가 발생했다.
메모리 부족 오류가 아니다. 다른 저해상도 결합 조건의 첫 구간도 16프레임이라 같은 경계 처리가 필요했다.

수정 후에는 이전 생성 구간이 17프레임보다 짧을 때 첫 프레임을 앞에 반복하여 17프레임으로 만든 뒤 조건으로 인코딩한다.
17프레임 이상인 공식 경로와 원본 시간축·전송량·생성 단계 수는 유지한다. 패딩은 연결 조건에만 적용하며 출력 프레임을 늘리지 않는다.
이는 공식 코드가 처리하지 못한 짧은 구간의 동작을 정의한 수정이며, 품질 개선 자체의 입증은 아니다.

실제 GPU VAE 검사에서 기존 8프레임→2잠재 프레임 오류를 재현했고, 수정 후 17프레임→5잠재 프레임의 실제 마스크 대입을 확인했다.
관련 테스트 47개도 통과했다. 검사 기록은 `outputs/diagnostics/quality_short_overlap_20260921/`에 있다.

기존 실행 `quality_validation_e8babaef576c`는 완료된 37개 작업의 출력 해시를 확인해 재사용하도록 복구했다.
그중 완료된 복원 4건의 이전 구간 길이는 모두 17프레임 이상으로 새 분기에 해당하지 않는다.
원래 프로토콜·완료 기록·수정 전후 소스는 실행 폴더의 `repairs/short_overlap_v1/`에 보존한다.
완료 기록에는 실제 생성 당시 코드의 실행 서명을 남기고, 재개용 의존성 서명을 별도로 연결한다.
수정된 코드의 기본 출력 이름은 기존 실행 폴더를 가리키므로 **원래 명령을 그대로 다시 실행**하면 된다.

복구 도구 `scripts/repair_quality_validation_short_overlap.py`는 해당 한 가지 소스 수정만 허용한다.
다른 코드·입력·모델·설정 변경이나 완료 파일 변조가 있으면 재사용을 거부한다.

현재 적응형 추가는 기존 의미 구간을 유지한다. 키프레임 추가만으로 새 장면의 캡션이나
Semantic Packet 갱신이 검증됐다고 보지 않는다. 기존 LPIPS·PSNR·시간차 문턱은 이 실행기의
개발 선택 기준이며 ETRI의 할루시네이션 합격 기준이 아니다.

위 항목은 계획이다. 이 문서 수정은 설정·실행기·평가기의 동작을 바꾸지 않으며,
기본 명령의 완료만으로 새 요구를 모두 충족했다고 보고하지 않는다.
